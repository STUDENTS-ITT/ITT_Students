# Краткий отчёт: Error-State Kalman Filter в коде — соответствие теории

**Дата:** 13.09.2026
**Тема:** проверка фильтра Калмана БИНС на соответствие принципу error-state Kalman Filter (ESKF).

---

## 1. Что проверяли

Реализация фильтра Калмана в программе `imitator` (`src/ins/ins_filter.h`, `src/navigation/trajectory.h`) сравнивалась с канонической схемой error-state:
номинал интегрируется отдельно, фильтр оценивает только **ошибки**, после коррекции ошибки возвращаются в решение и обнуляются.

## 2. Главный вывод

**Фильтр в целом соответствует принципу ESKF.** Архитектура правильная: номинал живёт вне фильтра, в фильтре — 15 ошибок (координаты, скорости, углы, смещения акселерометра и гироскопа), коррекция по СНС и по акселерометру работает штатно.

**Но есть 3 существенных расхождения** («ошибка ковариации», «частичное обнуление», «ненадёжное обновление ковариации»), которые снижают точность самооценки фильтра и могут влиять на результат подбора коэффициентов.

## 3. Расхождения с теоретической моделью

| № | Что не так | Риск | Срочность |
|---|-----------|------|-----------|
| **П1** | После коррекции ошибки обнуляются, но **ковариация P не пересчитывается** (в теории: `P ← G·P·Gᵀ`). P «помнит» уже снятые ошибки и остаётся завышенной | Фильтр излишне доверяет измерениям; расхождение видно в NIS/NEES; может смещать подбор коэффициентов | Высокая |
| **П2** | Коррекция по наклону (акселерометр) обнуляет **только** ошибки углов и смещений датчиков, а ошибки координат/скорости/курса остаются «жить» между кадрами СНС и предсказываться дальше | Смешение двух режимов (feedforward + ESKF); рассогласование среднего ошибки и ковариации | Высокая |
| **П3** | Ковариация обновляется упрощённой формулой `P=(I−K·H)·P` вместо устойчивой Joseph-формы | Потенциальная потеря симметрии и «положительности» P → нестабильность K и осцилляции | Средняя |
| П4 | Углы считаются глобальными Эйлеровыми (с wrap ±π) вместо локальных малых углов/quaternion | Сингулярность при тангаже ±90°; некорректная инжекция больших ошибок курса | Средняя |
| П5 | Предсказание (predict) идёт **до** интегрирования за такт (по состоянию прошлого такта) | Систематический сдвиг на 5 мс между predict и коррекцией | Низкая |
| П6 | По наклону в СНС-контуре измерение «виртуальное» (инновация ноль); без `angle.dat` курс вообще не корректируется | Потеря наблюдаемости курса; трата ресурсов на пустые измерения | Средняя |
| П7 | Один общий шум σ на все три оси скорости и углов (горизонталь/вертикаль не разделены) | Неточная физическая модель шума Q | Низкая |
| П8 | Q — простая диагональ `σ²·T` без корреляций ошибок скорость↔угол (через ускорение) и без дискретного преобразования `Q_d = F·Q·Fᵀ` | Модель шума процесса неточна и рассогласована с F | Низкая |
| П9 | F дискретизируется первым порядком (`I + T·A`) вместо матричной экспоненты | Погрешность предсказания на крупных шагах и быстрых манёврах | Низкая |
| П10 | Reset ошибок выполняется только на кадре СНС (1 Гц): между кадрами вывод компенсируется feedforward-вычитанием `x` в `makeResult`, инжекция в номинал отложена (продолжение П2) | Смешение feedforward и ESKF-контуров; две разные «точки зрения» на решение | Средняя |
| П11 | Комментарии заявляют частоту «400 Гц» (шаг 2.5 мс), фактически `IMU_RATE_HZ = 200.0` (шаг 5 мс) | Рассинхрон документации и реализации | Низкая |
| П12 | Ссылка на полную версию `docs/eskf_report.md` — файл отсутствует (есть `docs/kalman_filter_report.md`) | Документация | Низкая |

## 4. Что это значит на практике

- **Для текущего режима** (горизонтальный полёт, малые наклоны) влияние расхождений П4–П9, П11–П12 незначительно — углы малы, курс медленный.
- **П1–П3, П10 важны:** они касаются самой ковариации, а от неё напрямую зависят коэффициент усиления K, достоверность NIS/NEES и ландшафт метрики J при подборе сигм. Частично объясняют наблюдаемый при подборе режим «копия СНС» (фильтр предпочитает следования спутнику собственной инерциальной оценке).

## 5. Рекомендации

1. **Первоочередное (П1, П3):** после обнуления ошибок пересчитывать ковариацию `P ← G·P·Gᵀ`; перейти на Joseph-форму обновления P.
2. **Средний приоритет (П2, П10):** определиться с семантикой — либо полное обнуление ошибок на каждом кадре, либо явный режим прогноза с feedforward-выводом; сейчас гибрид.
3. **Опционально (П4):** перейти на малые углы/quaternion — снять ограничение ±90° и ±π.
4. **Низкий приоритет (П6, П7):** разделить шумы горизонталь/вертикаль; обработать случай отсутствия `angle.dat` (курс без коррекции).
5. **Низкий приоритет (П8, П9):** разделить оси и дискретизировать Q через F (`Q_d ≈ F·Q·Fᵀ`); при крупных шагах использовать матричную экспоненту для F.
6. **Документация (П11, П12):** привести комментарий о частоте ИМУ к фактическому `IMU_RATE_HZ = 200`; разместить или убрать ссылку на `docs/eskf_report.md`.

## 6. Оценка готовности

| Критерий | Оценка |
|----------|--------|
| Соответствие архитектуре ESKF | ✅ Соответствует |
| Ковариационная согласованность (P) | ⚠️ Есть расхождения (П1–П3) |
| Ограничения по углам | ⚠️ Сингулярность 90°, wrap ±π (П4) |
| Наблюдаемость курса/наклона | ⚠️ Зависит от наличия `angle.dat` (П6) |
| **Итог** | **Работоспособен, но рекомендуется доработка П1–П3** |
