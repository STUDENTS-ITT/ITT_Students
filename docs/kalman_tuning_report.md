# Отчёт: подбор коэффициентов фильтра Калмана (9 наборов)

Сводный отчёт по полному прогону подбора коэффициентов ESKF (этап 7 плана).
Отчёт собран из артефактов `tools/kalman_tuner/full_runs/`.

> Для знакомства с методиками 13A/13B/13C/13G (что и как подбирается, размер
> сетки, почему в 13C больше точек с отклонениями) см.
> `docs/kalman_tuning_methods.md`.

- **Дата прогона:** 2026-10-10 (все 9 наборов завершились успешно, exit=0).
- **Инструмент:** `tools/kalman_tuner/` (перенос оптимизатора `tune_kalman_v3.py`).
- **Данные:** `ITT_Students-Katya/dataset_shum/<набор>` (синтетика с эталоном `truth.txt`).
- **Исполняемый файл:** `build/src/console/imitator.exe`.

## Метод

- **Метрика:** `J = P95(pos)/5.0 + P95(vel)/0.5 + P95(hdg)/1.0 + 0.05·Mean + 0.005·u² + 0.5·P99.9(pos@200Hz)/5.0` (v3).
- **Горизонт:** `skip=130 c`, split `train=60%`, `workers=8`.
- **Оптимизация:** Sobol-разведка (65 точек, ранний стоп после 16 нейтральных
  подряд) → полировка Nelder-Mead; старт у `u=0`; фиксированный SEED
  (воспроизводимость).
- **Коэффициенты (8):** `sigma_g`, `sigma_a`, `sigma_bg`, `sigma_ba`, `sigma_pos`,
  `sigma_h`, `sigma_v`, `sigma_ang` (последний — `sig_hdg`).

## Этап 13C — робастность хвоста (окна ~5 с, выбросы, куртозис)

Реализовано **только в метрике тюнера** (`tools/kalman_tuner/tune_kalman.py`),
без изменений `core`/консоли. В `compute_error` добавлены:

* оконный квантиль `P99.9` по тактам ИМУ (200 Гц): ряд режется на окна
  `metric.window_s` (по умолчанию 5 с), в каждом берётся `P99.9`; берутся худшее
  и среднее окно отдельно для train/valid — так локальный артефакт виден
  отдельно от «фонового» хвоста;
* доля выбросов (`metric.outlier_pos_m`, по умолчанию 1 м) на 200 Гц;
* моменты распределения ошибки позиции (асимметрия, куртозис; нормальный ≈ 3);
* член J по худшему окну включается `metric.consistency_weight` (по умолчанию
  **0.0** — член выключен и J бит-в-бит совпадает с прежним; проверено: при
  весе 0 ΔJ=0, при весе 0.1 ΔJ = 0.1·win_q/TOL_POS).

Все новые величины попадают в `eval.json` (ключи `win_q_*`, `outlier_frac_*`,
`kurt_pos_*`, `n_win_*`), поэтому оконная диагностика доступна и офлайн по
сохранённым оценкам. Отдельный инструмент отчёта — `13C_tail_report.py`.

рассогласование фильтра, но **отдельным, поштучным** членом, а не агрегатом по
наборам. Обоснование выбора:

* тюнер оптимизирует **один** набор за прогон (`DATA_DIR` один на конфиг),
  мульти-наборного агрегата в нём нет — общий (по всем наборам) штраф
  потребовал бы перестройки основного цикла;
* ключ `metric.consistency_weight` уже занят членом **оконного хвоста** (13C),
  смешивать два разных смысла в одном ключе нельзя;
* среднее по наборам остаётся **офлайн-диагностикой**: оно пишется в `eval.json`
  каждой оценки, а сводится скриптом/отчётом.

Реализация (`tools/kalman_tuner/tune_kalman.py`, только метрика):

* член `J += NIS_WEIGHT·|mean(NIS/dof) − NIS_TARGET| / NIS_TARGET` **отдельно**
  по train и valid (свои окна по времени), ключи `metric.nis_weight`
  (по умолчанию **0.0** — член выключен) и `metric.nis_target` (по умолчанию 1.0);
* `imitator` в тюнере вызывается с `--consistency` → в рабочем каталоге
  оценки появляется `tools/consistency.txt`; устаревший файл перед прогоном
  удаляется (файл пишется лениво, только при кадрах коррекции);
* `_read_nis()` пропускает `#`-комментарии и строку заголовка (`time nis dof`),
  отбрасывает кадры выставки (`t < skip_first_s`), кадры с `nis < 0`
  (квадратичная форма не может быть отрицательной — численный мусор) и
  нефинитные значения;
* диагностика пишется **всегда**, независимо от веса: `nis_mean_train/valid`,
  `nis_n_train/valid`, `nis_penalty_train/valid` в `eval.json`; строки в
  `best_params.txt` и в breakdown-выводе тюнера (`13C-Н NIS/dof -> ...`).

**Проверка механики (smoke, `figure8_8ms`, паспортный `σ_ref`):**

* при `NIS_WEIGHT = 0.0` J бит-в-бит совпадает с вызовом без `consistency_path`
  (старый код) — регрессии нет;
* при `NIS_WEIGHT = 0.5` ΔJ_train и ΔJ_valid равны ровно
  `0.5·|mean(NIS/dof) − 1|` по соответствующим окнам (совпадение до 1e-12);
* `eval.json` содержит ключи `nis_*`; прогон на паспортных σ даёт
  `mean(NIS/dof)` ≈ 63/66 (фильтр переуверен по позиции — согласуется с
  `reports/blockc_measurements.md`, §6.1).

**Тонкость приёмки.** Тюнер A/B запускается с `--ref-truth` (метрика J — по
наземной истине `truth.txt`, как штатные прогоны 13A/13G). Пресет, однако,
несёт только `[meta] error_ref = reference.txt`: имена файлов, которыми
проверялся подбор, в пресет не попадают, поэтому `--bias-report` по этому
пресету сверяет оценки с СНС-эталоном, а не с истиной. Оценки смещений при
этом остаются согласованными по `norm_err` (эталон входит только в колонку
`truth`), но абсолютные `error`-колонки A/B читаются против `reference.txt`.
Тот же эффект уже отмечен для пресетов `presets/truth_13g/*`.

**СЕРИЯ НЕДЕЙСТВИТЕЛЬНА (дефект тюнера).** Первая серия A/B (веса 0 и 0.1 на

(пробрасывались только `DATA_DIR`/`WORK_ROOT`). Поэтому в работниках молча
терялись все ключи `metric`/`horizon` и `PARAMS`, если конфиг отличался от
встроенных умолчаний. Прямая проверка реальным spawn-процессом:

| Поле | Родитель (из конфига) | Работник (дефект) |
|---|---|---|
| `NIS_WEIGHT` | 0.1 | **0.0** (умолчание) |
| `SKIP_FIRST_S` | 130.0 | **30.0** (умолчание) |
| `PARAMS.sigma_pos` | 2.35442e-07 | **7.85e-07** (умолчание) |

## Связь с планом смещений (Этапы 0–6)

Подбор 13A/13B/13G велся на прежней структуре измерения (связка
`evalAccelAttitude` + `correctTilt` + трим, фиктивный `R` по позиции, оценка
дрейфа курса входом в `maneuver_tilt`). Этапы 0–6 плана смещений
(`docs/bias_estimation_plan.md`, итоги — `docs/bias_estimation_stages.md`)
изменили саму постановку: измерение акселя — одно (горизонт, 2 оси, форма
Джозефа, `R = (σ_a·√dt)²·I`), `P0`/`Q` — по физическим σ, курс — из первого
отсчёта СНС с гейтом `gyro-compassing`, скрытый оцениватель (R1) снят. После
таких правок старые пресеты `truth_13b`/`truth_13g` перестают быть оптимумом:
их σ компенсировали дефект измерения (см. разбор R2/R3), а не физический шум.

Поэтому блок C (13C в `docs/DEVELOPMENT_PLAN.md`) делается заново, от
`metric.consistency_weight`: цель — привести `NIS/dof` к ≈1. Измерения Этапа 5
(`reports/consistency_summary_s5.txt`) показывают, что одним `R` оба семейства
наборов не согласовать: `σ_pos` в фильтре ≈ 0.17 м против фактического шума СНС
0.8–5 м, поэтому на всех наборах `dataset_shum` `NIS/dof` = 9.9…307.9 (`R`
мал), а на `data/raw` фильтр наоборот консервативен (`NIS/dof` = 0.077).
Порядок: сначала выставить `sig_pos`/`sig_v` по ориентиру σ ≈ 1.5 м
(`dataset_shum`), затем уже подбирать остальные σ, оценивая цену для
наблюдаемости смещений (`ba`/`bg` в `bias_report`).
