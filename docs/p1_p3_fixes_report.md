## Аннотация

В `src/core/ins/ins_filter.h` и `src/core/navigation/trajectory.h` выполнены две правки error-state фильтра, которые были отмечены как существенные в `eskf_brief_report.md`:

- **П3** — обновление ковариации переведено с упрощённой формы `P = (I − K·H)·P` на устойчивую **Joseph-форму** `P = (I−K·H)·P·(I−K·H)ᵀ + K·R·Kᵀ` в двух контурах: `correct()` (по СНС) и `correctTilt()` (по акселерометру).
- **П1** — после обнуления вектора ошибок добавлен вызов `ins::apply_reset_covariance(st.P)` — согласование ковариации после reset. При текущей эйлеровой параметризации `G = I`, поэтому функция выполняет числовое согласование P (симметризация и страховка диагонали), а не полный `P ← G·P·Gᵀ`; правка архитектурная и подготавливает переход на quaternion (П4).

Отчёт фиксирует **что и зачем менялось** и **теоретическое обоснование**. Раздел 4 (графики) не заполнен: см. пояснение в нём.

## 1. Исходное состояние (до правок)

### 1.1 П3 — упрощённая формула обновления ковариации

До правки обновление ковариации в `ins::correct` (`ins_filter.h`) выглядело так:

```cpp
P = (I − K·H)·P;      // упрощённая форма
```

Такая формула **корректна только при оптимальном коэффициенте Калмана** `K = P·Hᵀ·S⁻¹`. При неточных `Q`/`R`, округлениях или вырожденности `S` она:

- теряет **симметрию** `P`;
- может привести к **потере неотрицательной определённости** `P`, из-за чего диагональ (дисперсии) может стать отрицательной;
- создаёт риск **осцилляций** усиления `K` и нестабильности оценки.

Та же формула использовалась и в `correctTilt()` — поправка по акселерометру работает на частоте ИМУ (200 Гц), т.е. численно «нагружается» каждый такт, и риск накопления нарушений симметрии особенно актуален.

### 1.2 П1 — обнуление ошибок без пересчёта ковариации

В ESKF после применения ошибок к номиналу и обнуления `x` теория требует пересчитать ковариацию:

```
P ← G·P·Gᵀ,   G = ∂(новая параметризация) / ∂(старая параметризация)
```

До правки вызов согласования отсутствовал — ковариация «помнила» уже снятые ошибки и оставалась завышенной относительно фактического состояния оценки.

## 2. Внесённые изменения

### 2.1 П3: Joseph-форма в `correct()` (коррекция по СНС)

Файл: `src/core/ins/ins_filter.h`.

До:

```cpp
P = multiply_matrix(E_KH, P, KF_STATE, KF_STATE);
```

После:

```cpp
const Matrix E_KH = matrix_diff(E_matrix(KF_STATE),
                                multiply_matrix(Kj, Hj, KF_MEAS, KF_STATE), KF_STATE);
const Matrix KRK = multiply_matrix(
    multiply_matrix(Kj, Rj, KF_MEAS, KF_MEAS),
    transpose_m(Kj, KF_MEAS), KF_MEAS, KF_STATE);
P = matrix_sum(
    multiply_matrix(multiply_matrix(E_KH, P, KF_STATE, KF_STATE),
                    transpose_m(E_KH, KF_STATE), KF_STATE, KF_STATE),
    KRK, KF_STATE);
```

Сопутствующая правка: матрица шума измерений `Rj` теперь вычисляется один раз и переиспользуется и в `S = H·P·Hᵀ + R`, и в `K·R·Kᵀ` — исключает расхождение R между шагами внутри одного кадра.

### 2.2 П3: Joseph-форма в `correctTilt()` (коррекция по акселерометру)

Та же замена повторена в `correctTilt()` с размерностями контура наклона (`KF_TILT_MEAS = 2`) и собственной `Rt`:

```cpp
const Matrix KRK = multiply_matrix(
    multiply_matrix(K, Rt, KF_TILT_MEAS, KF_TILT_MEAS),
    transpose_m(K, KF_TILT_MEAS), KF_TILT_MEAS, KF_STATE);
```

Внимание на конвенцию кода: `transpose_m(Kj, KF_MEAS)` / `transpose_m(K, KF_TILT_MEAS)` — вторым аргументом передаётся **число столбцов** матрицы K (размер измерений), а не размерность состояния. Ошибка здесь тихо даёт мусор без ошибок компиляции.

### 2.3 П1: `apply_reset_covariance()` и точки вызова

Добавлена функция в `src/core/ins/ins_filter.h`:

```cpp
// Согласование ковариации после ESKF-reset (inject + zero δx).
// В каноническом ESKF: P ← G·P·Gᵀ, где G — якобиан reset-операции.
// Для аддитивных групп (координаты, скорости, смещения датчиков) G = I;
// для эйлеровых углов (additive, mod 2π) G = I при малых δx.
// Практический вклад: числовое согласование P — симметризация и
// страховка диагонали (см. далее). TODO(П4): при переходе на quaternion
// вычислить G_att = J_r(δθ) и применить P_att ← G_att·P_att·G_attᵀ.
inline void apply_reset_covariance(Matrix &P)
{
    const int n = KF_STATE;

    // 1) Симметризация: P ← (P + Pᵀ)/2.
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
        {
            const double s = 0.5 * (at(P, i, j, n) + at(P, j, i, n));
            at(P, i, j, n) = s;
            at(P, j, i, n) = s;
        }

    // 2) Страховка диагонали: отрицательные дисперсии → 1e-15.
    for (int i = 0; i < n; i++)
        if (at(P, i, i, n) < 0.0)
            at(P, i, i, n) = 1e-15;
}
```

Вызовы добавлены в `src/core/navigation/trajectory.h`:

- `applyTiltKalmanCorrections()` — после обнуления `x[7..KF_STATE)`;
- `applyKalmanCorrections()` — после полного обнуления `x`.

## 3. Теоретическое обоснование

### 3.1 Почему Joseph-форма

Пусть после коррекции `x̂ = x + K·(z − H·x)`. Ковариация:

```
P⁺ = E[(x − x̂)(x − x̂)ᵀ]
```

Подстановка `x̂` даёт общее выражение (Joseph-form), верное **при любом K**, не только оптимальном:

```
P⁺ = (I − K·H)·P·(I − K·H)ᵀ + K·R·Kᵀ
```

Свойства:
- **симметрия** сохраняется по построению (сумма симметричных членов);
- **неотрицательная определённость** гарантирована, даже если `K` далёк от оптимального или `S` плохо обусловлена;
- при оптимальном `K` и точной арифметике результат совпадает с классическими `P⁺ = (I−K·H)·P` и `P⁺ = P − K·S·Kᵀ` — форма не меняет математику фильтра, а делает его **устойчивым к численным ошибкам**.

Упрощённая `P = (I−K·H)·P` следует из Joseph-формы только в предположении оптимального `K`, которое на практике нарушается (неточные сигмы, плавающая арифметика, возбуждение манёвра).

### 3.2 Почему `apply_reset_covariance` (П1)

При обнулении error-state `x` после инжекции в номинал параметризация, вообще говоря, меняется: старые ошибки (Эйлеровы углы, малые приращения) «упаковываются» в новую параметризацию. Формальный пересчёт:

```
P ← G·P·Gᵀ,   G = I + ∂(снятой поправки)/∂(x)
```

В текущем коде ошибки **линейны** (позиция, скорость, смещения прибавляются напрямую; углы прибавляются в глобальных Эйлеровых координатах с wrap ±π), поэтому `G = I`. Формально `P` при этом не меняется, но численно predict и коррекции накапливают ошибки округления: на недиагонали теряется симметрия, на диагонали могут появиться отрицательные дисперсии. Поэтому `apply_reset_covariance()` выполняет практическое согласование `P` — симметризацию `P ← (P + Pᵀ)/2` и страховку диагонали (отрицательные дисперсии → `1e-15`); при переходе на quaternion (П4) сюда добавится `G_att = J_r(δθ)`.
