# Методики подбора коэффициентов фильтра Калмана: 13A, 13B, 13C, 13H

Введение для тех, кто слышит об этом впервые. Документ объясняет, **зачем**,
**что** и **как** подбирается, чем отличаются подходы 13A/13B/13C, почему в
отчёте 13C «точек с отклонениями» больше, чем в 13B, и чем планируемый полный
подбор 13H отличается от текущего (раздел 9). Точные числа и таблицы —
в `docs/kalman_tuning_report.md`; план этапа — в `docs/DEVELOPMENT_PLAN.md`
(раздел «Этап 13»).

---

## 1. Зачем вообще подбирать коэффициенты

В комплексе БИНС + СНС работает **error-state фильтр Калмана** (ESKF) на
15 состояний: ошибки координат (3), скорости (3), углов (3), смещения
акселерометра (3), смещения гироскопа (3). Фильтр объединяет показания
инерциальных датчиков (БИНС) с редкими, но абсолютными измерениями СНС.

Качество фильтра зависит от **шумовых коэффициентов** (сигм, обозначаются `σ`):
насколько мы доверяем датчикам, СНС и как быстро, по нашему мнению, «уходят»
их смещения. В коде это матрицы шумов процесса и измерения, но настраивают их
не напрямую, а через восемь скалярных коэффициентов:

| Коэф. | Смысл | Типичная `σ_ref` |
|---|---|---|
| `sigma_g` | шум гироскопа, рад/√с | 3.394e-4 |
| `sigma_a` | шум акселерометра, м/с²/√с | 3.05e-3 |
| `sigma_bg` | дрейф смещения гироскопа, рад/с/√с | 1.16e-5 |
| `sigma_ba` | дрейф смещения акселерометра, м/с²/√с | 2.0e-5 |
| `sigma_pos` | шум положения СНС, рад | 7.85e-7 |
| `sigma_h` | шум высоты СНС, м | 5.0 |
| `sigma_v` | шум скорости СНС, м/с | 0.1 |
| `sigma_ang` | шум курса СНС, рад | 0.0175 |

Подобрать их «на глаз» нельзя: коэффициенты связаны между собой, и плохой
набор даёт ошибку положения в десятки метров вместо единиц. **Подбор** — это
автоматический поиск таких восьми `σ`, при которых ошибка фильтра минимальна.

Инструмент — `tools/kalman_tuner/tune_kalman.py` (Python). Он запускает
консольный `imitator.exe` с очередным набором `σ`, считает по выходным файлам
ошибку и ищет минимум.

## 2. Общий конвейер подбора (одинаков для 13A/13B/13C/13G)

Подбор идёт в **логарифмическом пространстве**:

```
u = log10(σ / σ_ref)          σ = σ_ref · 10^u
```

Так поиск равномерен по порядкам величины (шаг `+1` — это ×10 к сигме). Для
каждой оси задаётся интервал `u`: симметричный `[-span, +span]` или
асимметричный `[u_lo, u_hi]`.

Схема (4 стадии):

1. **Глобальная разведка Sobol** — 64 псевдослучайных, но равномерно
   распределённых точек в 8-мерном пространстве `u`. Ищем перспективные области,
   а не точный минимум. Ранний стоп, если 16 точек подряд не улучшают лучший
   результат.
2. **Локальная полировка Nelder-Mead** — 80 оценок от лучших точек + старт в
   окрестности `u=0` (номинал).
3. **Уточняющая сетка** ±0.5 декады вокруг найденного «бассейна» (32 точки) и
   вторая полировка — подтверждение минимума.
4. **Центроид плато** — финальный выбор не одной точки, а центра области
   `J ≤ J_min + 0.05`: так результат устойчив к «плоскому дну».

Воспроизводимость: фиксированный `SEED=42`; каждый прогон `imitator` идёт в
своём изолированном рабочем каталоге (`cwd/tools`), поэтому оценки не мешают
друг другу и распараллеливаются (8 воркеров).

Конфиг подбора — JSON (`tuner_config.<набор>.json` и производные
`truth_cfg*/cfg_<набор>.json`). Файл настраивает всё: данные, коэффициенты и
границы, метрику, горизонт, оптимизатор.

### Горизонт и train/valid

Начало записи (выставка, «грубая» начальная ориентация) отбрасывается —
`skip_first_s` (для синтетики 130 с). Оставшееся время режется на две части:
первые 60 % — **train** (на нём идёт оптимизация), последние 40 % — **valid**
(независимая проверка). Это защищает от **переобучения**: хороший результат
должен быть и там, и там (`J_valid` не сильно хуже `J_train`). Если
`J_valid / J_train > 2.0`, включается откат к точке с лучшим `J_valid`.

## 3. Метрика J — по чему измеряется «хорошо»

Метрика (штраф, который минимизируется) считается по ошибкам относительно
эталонной траектории и складывается из:

```
J = P95(pos)/TOL_POS  +  P95(vel)/TOL_VEL  +  P95(hdg)/TOL_HDG
  + TIE_WEIGHT·Mean
  + REG_LAMBDA·Σu²
  + WALL_PENALTY (если включён)
  + TAIL_WEIGHT·P99.9(pos@200Гц)/TOL_POS
  + CONSISTENCY_WEIGHT·(худшее окно)/TOL_POS   (13C, по умолчанию выключен)
```

- **P95** — 95-й процентиль ошибки: устойчивая «типичная худшая» ошибка, её не
  сдвигают отдельные выбросы.
- **Допуски** `TOL_POS=5 м`, `TOL_VEL=0.5 м/с`, `TOL_HDG=1°` приводят разные
  величины (метры, м/с, градусы) к безразмерному виду.
- **Mean** (с весом 0.05) — вторичный критерий для выбора среди почти равных.
- **Регуляризация** `REG_LAMBDA·Σu²` (0.005) штрафует удаление от номинальных
  `σ_ref`: не даёт увести `σ` в «нефизичную» крайность.
- **`TAIL_WEIGHT`·P99.9@200Гц** — штраф за редкие короткие «прострелы» на тактах
  ИМУ: P95 к ним почти слеп (см. §5).
- **`WALL_PENALTY`** (13B) — штраф за близость `u` к границе интервала
  (см. §7).
- **`CONSISTENCY_WEIGHT`** (13C) — штраф за худшее локальное окно
  (по умолчанию 0, то есть выключен; см. §8).

Ошибки берутся между `result.txt` (оценка фильтра) и эталоном. Именно **что
считать эталоном** — главное отличие 13A, описанное дальше.

## 4. 13A — переход на наземную истину

**Проблема.** Изначально ошибка считалась относительно бортового
`reference.txt` — это траектория, восстановленная по самим измерениям СНС.
Получался замкнутый круг: если фильтр почти копирует входные измерения СНС, он
почти копирует и эталон, и метрика это «хвалит». В итоге оптимизатор подгонял
**похожесть на эталон**, а не точность.

**Решение (13A).** У синтетических наборов есть `truth.txt` — настоящая
наземная истина (траектория, по которой синтезировались датчики). Переключаем
метрику на неё: флаг `--ref-truth` (задаёт переменную `TUNE_REF_TRUTH=1`), и
`run_eval` подставляет `truth.txt` вместо `reference.txt`.

**Что ещё в 13A:**
- границы — **симметричные** (`u ∈ [-span, +span]`), как в базовом v3;
- набор `square_noisefree` исключён: у него повреждён `truth.txt`.

**Результат.** Ошибка по истине оказалась в разы меньше, чем по эталону
(отношение P95_truth / P95_ref = 0.05–0.74 на разных наборах): фильтр был
точнее, чем считалось. После переориентации подбора `P95(truth)` улучшился в
1.2–8.5 раза на 8 наборах. Пресеты — `presets/truth/tuned_<набор>.ini`
(штатные `presets/tuned_<набор>.ini` не тронуты).

Артефакты: `tools/kalman_tuner/gen_truth_configs.py`, `truth_cfg/`,
`validate_truth.py`, `full_runs/_truth_13A_comparison.txt`.

## 5. Сетка: где именно считается ошибка (важно для 13B vs 13C)

Это ключ к вопросу «почему в 13C больше точек с отклонениями». Замер ошибки
идёт на двух разных **сетках отсчётов**:

- **`result.txt` — 200 Гц** (шаг 0.005 с): тактовая частота фильтра. На одном
  и том же интервале времени здесь примерно в 20 раз больше отсчётов, чем на
  сетке эталона.
- **`truth.txt` — около 5–10 Гц** (шаг ~0.1–0.2 с): собственная частота истины.

Два способа сопоставить два ряда:

1. **На сетке истины** (так считает отчёт 13B, `compare_presets_stats.py`):
   для каждой строки `truth.txt` берётся **ближайшая** строка `result.txt`.
   Число точек = число строк истины (`n ≈ 2 000`).
2. **На тактах фильтра** (так считает 13C, `13C_tail_report.py` и метрика
   тюнера): `truth.txt` **интерполируется** на каждый такт `result.txt`
   (200 Гц). Число точек ≈ 40 000.

Порог (например «>0.5 м») — это ошибка в метрах, сама по себе от частоты не
зависит. Но **число точек выше порога** прямо пропорционально количеству
отсчётов. Поэтому один и тот же набор даёт:

| Набор | >0.5 м на 5 Гц (13B) | >0.5 м на 200 Гц (13C) | n_valid (200 Гц) |
|---|---|---|---|
| square650 | 1535 | 30360 | 41999 |
| square_harsh | 2128 | 40022 | 41999 |
| high_dynamics | 760 | 14709 | 41999 |

Отношение ≈ 20 (30360/1535 ≈ 19.8). Это **не ухудшение** фильтра и **не
регрессия** 13C относительно 13B — просто считаются разные интервалы
дискретизации. Корректная для сравнения величина — **доля** (проценты), а не
абсолютное число точек:

| Набор | доля >0.5 м, 5 Гц | доля >0.5 м, 200 Гц |
|---|---|---|
| square650 | 1535 / 2128 = 72.1 % | 30360 / 41999 = 72.3 % |
| square_harsh | 2128 / 2128 = 100 % | 40022 / 41999 = 95.3 % |
| high_dynamics | 760 / 2128 = 35.7 % | 14709 / 41999 = 35.0 % |

Доли совпадают: тела распределений ошибок одинаковы, меняется только густота
отсчётов.

**Практический вывод:**
- **200 Гц** лучше для поиска **коротких прострелов**: интерполяция оценивает
  ошибку в 20 раз чаще и не пропускает всплеск между отсчётами истины. Поэтому
  «хвостовой» член метрики (P99.9) и диагностика 13C считаются на 200 Гц.
- **5–10 Гц** — «родная» сетка истины, удобна для сопоставления с первичными
  данными, но слепа к субсекундным выбросам.
- Для сравнения наборов между собой используйте **долю времени** или
  **суммарное время** вне допуска, а не сырые счётчики: они зависят от частоты
  и длины окна.

Именно поэтому в таблице 13C счётчики на порядок больше, чем в 13B. В
`kalman_tuning_report.md` это отмечено пометкой под таблицей 13C.

## 6. 13B — асимметричные границы и штраф за стенку

**Проблема.** В диагностике 13.0 обнаружилось «прилипание к стенкам»: оптимум
по `sigma_a` упирался в верхнюю границу в 5 из 9 наборов — значит, интервал
обрезал настоящий минимум. Симметричные границы были неинформативны.

**Решение (13B).**
- **Асимметричные интервалы** `u ∈ [u_lo, u_hi]`: центр берётся по оптимумам
  13A, а полуширина задаётся отдельно снизу и сверху (запас −0.15 / +0.25
  декады). Задаются в конфиге полями `u_lo`/`u_hi` (или `u_bounds`); функция
  `rebuild_bounds()` собирает массивы `U_LO`/`U_HI`, по которым строятся и
  сетка Sobol, и ограничения Nelder-Mead.
- **`WALL_PENALTY`** — штраф за близость к границе: если `u` входит в
  пограничную зону `eps_frac` (5 % ширины интервала), к J добавляется
  `w·(расстояние)²` с `w = 0.1`. Это «отталкивает» оптимум от стенки.
  Управляется секцией `optim.wall_penalty {w, eps_frac}`.

**Результат.** Прилипание к стенкам снизилось с 5/9 наборов (только `sigma_a`)
до **4/64 осей**: `sigma_pos` у нижней границы в
`straight_10ms`/`figure8_8ms`/`spiral_climb`, `sigma_bg` у верхней в
`square_harsh`. `J_valid` улучшился в 7/8 наборах. Пресеты —
`presets/truth_13b/tuned_<набор>.ini`.

**Важное ограничение (снято в 13G).** Границы 13B выведены из оптимумов
**имеющихся** наборов, поэтому **не универсальны** — на новых данных могут не
подойти. В этапе **13G** (выполнено 2026-10-14) они заменены на фиксированные
универсальные интервалы-константы (см. §8).

Артефакты: `gen_13b_configs.py`, `truth_cfg_13b/cfg_<набор>.json`,
`full_runs/full_13b_<набор>.log`.

## 7. 13C — робастность хвоста, выбросы, распределение

**Проблема.** Одного P99.9 недостаточно, чтобы понять природу хвоста: это
единичный выброс или «тяжёлое» распределение? В ранних прогонах у набора
`square_650` был устойчивый одиночный артефакт 138 м — метрика его «видела»,
но не отличала от систематического хвоста.

**Решение (13C)** — только в **метрике тюнера** (ядро и консоль не меняются).
В `compute_error` добавляются:

- **Оконный P99.9.** Ряд тактов 200 Гц режется на окна `WINDOW_S = 5 с`; в
  каждом берётся `P99.9`. Запоминаются **худшее** и **среднее** окно отдельно
  для train/valid. Если максимум локализован в одном окне — это локальный
  артефакт; если худшее окно ≈ среднему — хвост «размазан».
- **Доля выбросов** — доля тактов с ошибкой выше `OUTLIER_POS_M = 1 м`.
- **Моменты распределения** ошибки позиции: асимметрия (skew) и **куртозис**
  (для нормального распределения ≈ 3.0; больше — тяжёлый хвост).
- **Член J по худшему окну** — `CONSISTENCY_WEIGHT` (по умолчанию **0.0**).
  При нуле член выключен и J **бит-в-бит** совпадает с прежним (обратная
  совместимость). При весе 0.1 вклад равен `0.1·(худшее окно)/TOL_POS`.

Все новые величины пишутся в `eval.json` (`win_q_*`, `outlier_frac_*`,
`kurt_pos_*`, `n_win_*`, `skew_pos_*`), поэтому оконную диагностику можно
разбирать и офлайн по сохранённым оценкам.

**Результат.** В текущих truth-пресетах оконный P99.9 практически совпадает с
общим P99.9, а время максимума попадает в то же окно — значит, хвост
распределён, а не сосредоточен в единичном простреле; метрика устойчива к
выбору окна. 13B снижает куртозис в шумных наборах (`square_harsh` 4.08→3.12,
`figure8_8ms` 4.05→3.70). Артефакт 138 м в текущих пресетах не
воспроизводится.

Артефакты: `13C_tail_report.py`, `full_runs/_13C_tail_13a.md`,
`full_runs/_13C_tail_13b.md`.

## 8. 13G — фиксированные универсальные интервалы

**Проблема.** Асимметричные `u_lo/u_hi` 13B построены по разбросу оптимумов
**имеющихся** наборов → неприменимы к будущим данным; плюс после 13B осталось
4/64 стенки (`sigma_bg`↑ в `square_harsh`; `sigma_pos`↓ в
`straight_10ms`/`figure8_8ms`/`spiral_climb`).

**Решение (13G)** — снова **фиксированные интервалы**, одинаковые для любых
наборов (симметричные спаны): σ_g ±2.7, σ_a ±3.0, σ_bg/σ_ba ±2.2, σ_pos ±2.0,
σ_h ±1.6, σ_v ±1.5, σ_ang ±1.6. Сохранён штраф за близость к стенке
(`wall_penalty {w:0.1, eps_frac:0.05}`). Глобальный `σ_ref` сохранён; `σ_bg`/`σ_ba`
продолжают подбираться (паспортная фиксация отменена директивой 13H: смещения
ИМУ неизвестны). Только тюнер, ядро/консоль не меняются.

**Результат.** **0/64 стенок** (против 4/64 у 13B). `J_valid` лучше/равно 13A в
7/8; относительно 13B — лучше в 2, равно в 2, хуже в 4, но позиционная точность к
истине — на уровне лучшего из 13A/13B (см. `docs/kalman_tuning_report.md`,
раздел «Этап 13G»; полный отчёт `full_runs/_13G_report.md`). Координатные профили
J (`scan_13g.py`): `σ_bg` имеет внутренний минимум у 6/8 наборов, `σ_ba`
практически плоский (неидентифицируем).

Артефакты: `gen_13g_configs.py`, `truth_cfg_13g/cfg_<набор>.json`,
`run_tune_13g.ps1`, `13g_report.py`, `presets/truth_13g/`,
`full_runs/full_13g_<набор>.log`, `full_runs/_13G_report.md`.

## 10. 13H — полный подбор всех коэффициентов (сравнение с 13A/13B/13C/13G)

13A/13B/13C/13G подбирают только **восемь** σ (шумовые коэффициенты Q/R). При этом
начальная ковариация **P0** захардкожена в ядре (`aligner.h:47-85`), и часть её
членов **сцеплена** с подбираемыми σ: `σ_bg`↔неопределённость курса,
`σ_pos`↔P0-положение, `σ_h`↔P0-высота. Политика трима (`tilt/*`) и параметры
выставки вообще не подбираются. Этап **13H** (планируется) расширяет подбор до
**всех** коэффициентов точности БИНС/СНС (28 осей), развязывает P0 и выносит её
в параметры (опциональные ключи, дефолты = текущим → бит-паритет).

| | 13A/13B/13C (текущий) | 13H (полный) |
|---|---|---|
| Число подбираемых осей | 8 (Q/R) | **28** (Q/R + P0 + tilt + выставка) |
| P0 | захардкожена, сцеплена с σ | **подбирается, развязана** |
| Tilt-политика | не подбирается | подбирается |
| Скрининг идентифицируемости | нет | **есть (13H.1)** |
| Понижение размерности | нет | **есть (13H.2)** |
| Объектив | `J` по набору | **мультинаборный `mean+λ·max`** |
| Интервалы `u` | 13G универсальные (13B — из оптимумов) | фиксированные универсальные |
| Правки `core` | нет | P0/tilt-ключи (опц., дефолты) |

**Лучше:**
- **Охват** — подбираются P0 и `tilt/*`, а не только 8 σ; на манёвровых наборах
  (`high_dynamics`, `square_harsh`) это резерв, недоступный текущему алгоритму.
- **Развязка конфаундов** — профиль J по `σ_bg` больше не искажён вкладом P0-курса.
- **Идентифицируемость** — обязательный скрининг + понижение размерности вместо
  слепого поиска по 28 осям.
- **Робастность** — единый агрегированный пресет вместо пресета под каждый набор.
- **Универсальность** — фиксированные интервалы/`σ_ref` для будущих наборов.

**Хуже:**
- **Дороже/сложнее** — правки `core`+GUI+тюнер; риск бит-паритета (митигируется
  опциональными ключами с текущими дефолтами).
- **Больше осей** → дороже глобальный поиск; без скрининга задача нереалистична.
- **Риск балласта** — если P0 вымывается за окно метрики (`skip_first_s`≈130 с),
  выигрыш сведётся к 13G (только 8 σ + универсальные интервалы).
- **Провал универсальности** — часть коэффициентов может оказаться набор-зависимой,
  и единый робастный пресет проиграет набор-специфичному.

**Вывод.** 13H даёт максимальный потолок точности, но дороже и рискованнее 13G;
при слабой идентифицируемости P0 эффект сводится к версии 13G. Путь: 13G
(тюнер-only, **выполнено 2026-10-14**) → 13H.0–13H.1 как проверка гипотезы о
полезности P0/tilt → полный 13H только при подтверждении.

## 11. Глоссарий

- **σ (сигма)** — коэффициент шума (стандартное отклонение) в фильтре.
- **`σ_ref`** — опорное («номинальное») значение σ, вокруг которого идёт поиск;
  `u = log10(σ/σ_ref)`.
- **`u`** — логарифмическая координата: `+1` = σ больше `σ_ref` в 10 раз.
- **Sobol** — квазиравномерная последовательность точек для глобального поиска.
- **Nelder-Mead** — метод локальной оптимизации без градиента (симплекс).
- **Train / valid** — части горизонта (60 % / 40 %) для обучения и независимой
  проверки; контроль переобучения.
- **P95 / P99.9** — 95-й / 99.9-й процентиль ошибки.
- **Хвост / прострел** — редкая короткая большая ошибка.
- **Куртозис** — «острота» распределения; 3.0 — нормальное, больше — тяжёлый хвост.
- **Стенка** — граница интервала `u`, к которой «прилип» оптимум.
- **`wall_penalty`** — штраф за близость к стенке.
- **`consistency_weight`** — вес члена J по худшему окну (13C; 0 = выключен).
