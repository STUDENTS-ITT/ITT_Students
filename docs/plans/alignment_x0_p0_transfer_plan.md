### 1.2. Текущая инициализация `NavState`

`nav::initialAlignment` (`aligner.h`) выполняет:

```cpp
st.att = att;                            // heading/pitch/roll из выставки
st.lat/lon/alt = first.lat/lon/alt;      // первый отсчёт СНС (scan.first)
st.V = {first.vn, first.vh, first.ve};   // первый отсчёт СНС
st.P = initialCovariance();              // фиксированная диагональ
return st;
```

**Не инициализируются из выставки/усреднения:**
- `st.x` — нулевой (`Vector(ins::KF_STATE, 0.0)` по умолчанию). **`x0` фактически нулевой.**
- `st.ba`, `st.bg` — нулевые (нет оценки смещений акселерометров/гироскопов по начальному окну).
- `st.bg_static` — нулевой.
- Время/производные интегрирования заполняются по ходу старта.

### 1.3. Текущая `P0` (`aligner.h::initialCovariance`)

Фиксированная диагональная матрица, **не зависящая** от реального качества окна выставки:

| Компоненты (ESKF 15 состояний) | Значение (смысл) | Диагональ `P0` |
|---|---:|---|
| `[0..1]` широта/долгота | ~50 м → `50/R_EARTH` рад | `(50/R_E)^2` |
| `[2]` высота | ~10 м | `p_h = 10.0` (в текущем коде; **при переносе сверить размерность/соглашение**) |
| `[3..5]` скорость | ~2.5 м/с | `p_v = 2.5` (аналогично) |
| `[6]` курс | ~15° | `(15°)^2` (в рад^2) |
| `[7..8]` тангаж/крен | ~0.1° | `(0.1°)^2` |
| `[9..11]` `ba` | малые начальные оценки | `9e-6` |
| `[12..14]` `bg` | малые начальные оценки | `1e-8` |

Особенности:
- Нет связи `P0` с разбросом ИМУ/СНС на окне выставки.
- Нет внедиагональных корреляций (например, `наклон ↔ ba`).
- Нет разделения `σ_sample / σ_mean`.
- `x0 = 0`, `ba/bg = 0`.

### 1.4. Существующие, но не используемые в `main.cpp` механизмы

- `nav::alignBins()` (`bins_alignment.h`): стационарная выставка до `motion_start` (скользящее среднее, `ψ=atan2(-wz,wx)`, `φ/θ` по акселерометрам, оценка `bg` по средним). Возвращает `AlignmentResult` (`att, g, duration, samples, bg`), но **не** формирует `x0/P0` по статистике окна и **не** интегрирован в текущий `main.cpp`.
- `get_angle_start()` (`Aligner.cpp`) — тяжёлая обработка (блоки `BUF_rot`, медиана+EMA, запись `Aligner.dat`), концептуально ближе к старой схеме, чем к `AveragingWindow`.

### 1.5. Ограничения текущей схемы

1. Номиналы координат/скорости привязаны к `scan.first` (первый СНС), а не к согласованному последнему отсчёту окна выставки.
2. Углы и СНС-номинал берутся из разных источников/моментов (`Aligner` по ИМУ + `scan.first`).
3. `P0` не отражает реальную неопределённость конкретного прогона/окна.
4. `x0 = 0`, `ba/bg = 0` — фильтр стартует без статистически обоснованной начальной ошибки и без начальных оценок смещений из окна покоя.
5. 180-с стартовый участок фактически отложает полноценную коррекцию по СНС/фильтру, что может конфликтовать с целью «короткая выставка + запуск ESKF».

## 2. Целевое состояние (to-be, по эталонному подходу)

Цель: статистическая инициализация по окну выставки.

| Аспект | Текущее | Целевое |
|---|---|---|
| Окно выставки | Разведка по всему файлу + отдельная грубая выставка углов | `AveragingWindow(T_align, has_heading_ref)` с накоплением ИМУ/СНС до `t <= T_align` |
| Номинал | `scan.first` (СНС) + углы `get_angle_start` | **`sns_last`** (последний СНС-отсчёт окна) + углы/оценки из окна |
| `x0` | `0` | `initialErrorsFromAveraging(...)`: согласованная разность `(last − mean)` / начальные оценки для компонент, оценённых по среднему |
| `P0` | фиксированная диагональ | `initialCovarianceFromAveraging(...)`: `σ_sample` для компонент с номиналом из последнего отсчёта, `σ_mean` для параметров, оценённых по среднему; корреляции `наклон ↔ ba`; floors |
| `ba/bg` | `0` | `ba_est`, `bg_est` из окна (`f_mean/w_mean`, `C_b^n`, `g(lat,alt)`, `ω_earth(lat)`) |
| Оценка качества окна | нет явного гейта покоя | `checkRest` + `rest_ok/rest_reason`; политика fallback при плохом окне |
| Стартовый участок | 180 с без `nav::step` | уточняется (см. Этап 0): сократить/параметризовать/сделать опциональным |

### 2.1. Ключевая связка, которую необходимо сохранить

**Номинал = последний отсчёт окна (`sns_last`) для компонент, задаваемых конкретным отсчётом.**

| Что | Номинал | Сигма в `P0` | Обоснование |
|---|---|---|---|
| pos/vel/hdg-компоненты, привязанные к последнему СНС/кадру | `last` | `σ̂_sample = Δ/k(N)` | Неопределённость одного отсчёта; выбор последнего — произвольный внутри распределения |
| Параметры, оценённые усреднением (`ba`, `bg`, leveling/наклоны по `f_mean`, иные mean-based) | оценка по среднему | `σ̂_mean = σ̂_sample/√N` | Неопределённость среднего при независимых выборках |

Где:
- `Δ = max|x_i - \bar{x}|` по окну;
- `k(N)=E[max_{i=1..N}|Z_i|]`, `Z_i ~ N(0,1)` (таблица Monte Carlo + интерполяция; для больших `N` — `sqrt(2*ln N)`);
- для СНС координат пересчёт метров ↔ радианы через `R_EARTH` и `R_EARTH*cos(lat)`.

Дополнительно:
- `bg_est = \bar{\omega}_body - C_b^n(\varphi, \text{att}) * \omega_{earth}(\varphi)` (по средним угловым скоростям);
- `ba_est` по среднему вектору удельной силы и опорной гравитации в навигационной СК (сверить знаки/конвенцию проекта);
- корреляции `наклон ↔ ba` в `P0` (знаки/индексы — под конвенцию фильтра данного проекта);
- floors на диагонали `P0`.

## 4. Порядок внедрения и контроль рисков

Рекомендуемый порядок:
1. **Этап 0–1** — `AveragingWindow` + проверка статистик/`k(N)`/оценок без переключения основного цикла.
2. **Этап 3** — `P0` (проще валидировать по диагонали/масштабам).
3. **Этап 2** — `x0` и привязка `ba/bg` к состоянию фильтра.
4. **Этап 4** — переключение `main.cpp` на `sns_last` + окно `T_align`, решение по 180-с старту.
5. **Этап 5** — конфиг, логи, регрессия.

Главные риски:
- **Несогласованность номинала и типа сигмы** (`sample` vs `mean`) → завышенная/заниженная `P0`, плохая сходимость. Контроль: зафиксировать таблицу маппинга (раздел 2.1) и проверить по логам.
- **Разная конвенция СК/знаков** (оси ИМУ, `C_b^n`, знаки `pitch/roll/heading`, компоненты `x`, порядок `ba/bg`, корреляции `наклон ↔ ba`) → неверная выставка или нестабильность KF. Контроль: сверка с `ins_filter.h`, `attitude_calc.h`, текущими определениями `Attitude/NavState`.
- **Потеря/сдвиг данных после окна `T_align`** при смене схемы чтения → пропуск первого участка или дублирование. Контроль: проверить непрерывность времени ИМУ/СНС на границе окна.
- **Конфликт со стартовым участком 180 с** → двойная логика инициализации. Контроль: явный выбор режима (Этап 0/4).
- **Влияние `SnsGuard`** на наличие `VALID` кадров в окне/после окна. Контроль: диагностика `accepted/rejected/STALE`, отдельный прогон с `gnss_guard_on=0`.

## 5. Согласованные решения (2026-04-22)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Окно выставки и 180-с стартовый участок | `T_align` берётся из 4-й строки `StartupNav.ini` (как в эталонном подходе). При отсутствии/некорректном значении — дефолт `1.0 с` с предупреждением. **180-с стартовый блок `START_SAMPLES`/`startRecord` без `nav::step` удаляется**: после окна усреднения сразу запускается основной цикл `nav::step` с `SnsGuard`. `state.time_prev = align_time` (конец окна). |
| 2 | Источник курса и `sig_heading0` | При наличии `angle.dat`/курса СНС в окне: номинал курса = последний отсчёт окна, `sig_heading0 = max(sig_hdg_cfg, sig_hdg_sample)`. При отсутствии: gyro-compass, `P0(heading)` по формуле `sigma_bg/(cos(lat)*U_EARTH)` (с честным приором), вывод предупреждения. Диагностика gyro-compass допустима в логе. |
| 3 | Fallback при `rest_ok == false`, малом `N`, отсутствии СНС | **Safe fallback + warning, прогон продолжается.** `P0` — паспортный/fallback (`initialCovariance` с floors/дефолтными сигмами), `x0 = 0` (`apply=false`), доверенные оценки `ba/bg` из окна не применяются как подтверждённые выставкой (поведение: `P0/x0` fallback; при необходимости не навязывать `bg_est` в `x0`). В лог/консоль пишутся `rest_reason`, `imu_count/sns_count`, причина fallback. |
| 4 | Размещение `ba_est/bg_est` | **Принятая конвенция.** `state.ba = ba_est` (номинал акселерометра сразу в механизации `accel(row, st.ba)`), `state.bg = {0,0,0}` (номинал гира нулевой), `x0[12..14] = bg_est` (оценка гира как начальная ошибка; применяется при первой коррекции `state.bg += x[12+k]` в `trajectory.h`), `x0[9..11] = 0`. `state.bg_static` оставить `0` (используется только для `hdg_true` в логе), не смешивать с KF-смещением. |

Добавить **опциональный** плоский `params.ini` (`key=value`, аргумент `main` как в эталонном подходе) для переопределения. Дефолты в коде обеспечивают работу без `params.ini`. |

### Пояснения к решениям 3 и 5

**Решение 3 (fallback).** Окно выставки даёт статистику (`Δ`, `σ_sample/σ_mean`, `k(N)`) и оценки `ba/bg/наклонов` в предположении, что объект неподвижен (`rest_ok`). Если гейт покоя не пройден, средние ИМУ/СНС могут отражать движение, а не истинные смещения/уровень; доверять `σ_mean` и `bg_est` рискованно. При малом `N` или отсутствии СНС оценка `k(N)`/`Δ` и номинал `sns_last` становятся ненадёжными. Варианты: (a) *safe fallback* — не прерывать прогон, использовать консервативный паспортный `P0` (floors/дефолтные сигмы) и `x0=0`, явно предупредить; фильтр стартует, но без «переобученной» уверенности; (b) *жёсткий отказ* — остановить инициализацию, полезно для контроля качества стендов, но ломает прогоны на неполных/движущихся начальных участках. Выбран вариант (a).

**Решение 5 (конфигурация).** `StartupNav.ini` уже используется проектом (чтение в `main.cpp`; 4-я строка — время/`T_align` выставки) — это естественное место для `T_align`. Для `P0` и fallback нужны сигмы/приоры (`sig_pos`, `sig_h`, `sig_v`, `sig_hdg`, `sig_bg`, `sig_ba`) и параметры шумов/режимов фильтра; сейчас `KalmanConfig` содержит только `gnss_*`, а `Qj/Rj` используют локальные константы. Расширение `KalmanConfig` сохраняет единый источник параметров KF/выставки. Опциональный `params.ini` (`key=value`) даёт воспроизводимую настройку без перекомпиляции (важно для регрессий/наборов данных), но его отсутствие не должно ломать запуск — поэтому дефолты фиксируются в коде. `gnss_*` не удаляются.
