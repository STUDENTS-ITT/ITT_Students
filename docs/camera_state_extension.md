# Расширение вектора состояния фильтра Калмана: ошибки камеры

**Статус:** черновик (design-документация, в код ещё не внесено).
**Цель:** добавить в error-state фильтр `src/ins/ins_filter.h` состояния, описывающие систематические ошибки, связанные с камерой/видеопотоком, чтобы коррекция по видео работала корректно и СНС стала опциональным источником.

---

## 1. Постановка

Сейчас фильтр — ESKF 15 состояний (ошибки координат/скорости/углов + смещения акселя и гиро). Коррекция выполняется только по СНС. Планируется:

- основное счисление — БИНС + видео (VIO/VO);
- СНС — опциональный источник коррекции (используем, когда данные есть);
- ошибки, связанные с камерой, должны оцениваться фильтром, а не считаться известными.

К «ошибкам камеры» относим **два систематических класса**:

1. **Плечо камеры (lever arm)** `l` — 3 компоненты, вектор из центра ИМУ в точку камеры в СК тела, м. Эквивалентно «монтажному смещению».
2. **Установка/разворот (boresight)** `f_cam` — 3 компоненты, малые углы поворота камеры относительно оси установки (матрица тело→камера известна с ошибкой), рад.

Опционально (для монокуляра) — масштабный фактор `s` (1 компонента, см. раздел 13). Этот документ описывает базовый вариант с плечом и установкой (всего к состоянию добавляется 6 компонент).

## 2. Нумерация нового вектора состояния

```
 x[0..2]   δφ, δλ, δh        — ошибки координат (рад, рад, м)
 x[3..5]   δVn, δVh, δVe     — ошибки скорости (м/с)
 x[6..8]   δψ, δθ, δφ        — ошибки углов (рад)
 x[9..11]  δba               — смещение акселерометра (м/с²)
 x[12..14] δbg               — смещение гироскопа (рад/с)
 x[15..17] δl                — ошибка плеча камеры, СК тела (м)   ←НОВОЕ
 x[18..20] δf                — ошибка установки камеры, СК тела (рад) ←НОВОЕ
 x[21]     δs                — ошибка масштаба, безразмерная (только монокуляр, раздел 13) ←ОПЦИОНАЛЬНО
```

Изменяемая константа:

```cpp
constexpr int KF_STATE = 21;     // было 15; 22 — только с масштабным фактором (монокуляр)
constexpr int KF_CAM_MEAS = 6;   // новое: [3 позиция + 3 угла] или [3 скорость + ...]
```

## 3. Соглашения и базовые величины (как в коде)

- СК навигационная: `V = [Vn, Vh, Ve]` (север, вверх, восток). Координаты на выходе — градусы.
- СК тела: X — вперёд, Y — вверх, Z — вправо.
- `C = C_b^n` — матрица направляющих косинусов тело→навигационная (`bodyToNavMatrix`, повороты Z-Y-X).
- Углы внутри кода — радианы. Курс растёт по часовой стрелке.
- Матрица хранится построчно в `std::vector<double>`; **число столбцов передаётся отдельным аргументом** (`multiply_matrix`, `transpose_m`, `at`).
- Используются векторные функции из `matrix_ops.h`: `vector_product`, `multiply_m`, `transpose_m`.
- Оси поворота углов Эйлера в навигационной СК (уже определены в `Fj_matrix`, `ins_filter.h:124-126`):

```cpp
n_psi   = {0, -1, 0};                          // ось курса (вниз, т.к. курс по часовой)
n_theta = {-sin(heading), 0, cos(heading)};    // ось тангажа
n_gamma = {C[0:0], C[1:0], C[2:0]};            // ось крена = продольная ось тела в нав. СК
```

Полезная величина — вектор плеча камеры в навигационной СК:

```cpp
l_nav = C · l;    // bodyToNav(C, l)
```

## 4. Модель измерения камеры (лоуз-каплет, 6DoF-поза)

Камера даёт оценку позы (позиция и углы) в навигационной СК:

- позиция: `p_cam = p + C·l` (где `p` — точка ИМУ);
- ориентация: `C_cam = C·C_cb` (направляющие косинусы), где `C_cb` — известная монтажная матрица тело→камера.

**Инновация (вектор z, размерность KF_CAM_MEAS = 6):**

```
 z[0..2] = p_cam_meas − (p_nom + C·l_nom)                    [м, ENU-порядок]
 z[3..5] = angle_diff( att_cam_meas, att_cam_nom )           [рад, wrap ±π]
```

где `att_cam_nom` — углы Эйлера, извлечённые из `C·C_cb_nom`.

Далее каждый блок строится как `innovation = H·x + шум`, поэтому задаём построчно, **какие ошибки x отбрасываются в каждый компонент z**.

## 5. Расширение матрицы F (`Fj_matrix`, `ins_filter.h`)

Напомним, как сделано сейчас: `F = I + T·A` (дискретизация 1-го порядка), элементы уже содержат `T`. Диагональ — 1.

### 5.1 Установка и плечо — «константы» (диагональ)

```cpp
// δl и δf — медленно меняющиеся параметры:
at(Fj, 15, 15, KF_STATE) = 1.0;   at(Fj, 18, 18, KF_STATE) = 1.0;
// ...аналогично 16,17 и 19,20
```

### 5.2 Влияние плеча на скорость (если камера/оптика даёт скорость, опционально)

Скорость точки камеры: `V_cam = V + C·(ω_b × l)`, где `ω_b` — угловая скорость тела на такте (складывается из `gyro_raw = ins::gyro(row, bg)` в `trajectory.h`).

Дифференцируем по `δl`:

```
δV_cam = δV + C·[ω_b]_× · δl
```

`[ω_b]_×` — кососимметричная матрица:

```
          [ 0    -wz    wy ]
[ω]×  =   [ wz    0    -wx ]
          [-wy    wx     0 ]
```

Добавляемый блок F (строки 3..5 — ошибки скорости, столбцы 15..17 — δl):

```cpp
// B = C · [ω_b]_×   (3×3)
for (int r = 0; r < 3; r++)
    for (int c = 0; c < 3; c++)
    {
        double B = 0.0;
        for (int m = 0; m < 3; m++)
        {
            B += at(C, r, m, 3) * SKEW[m][c];   // SKEW — матрица [ω_b]_×
        }
        at(Fj, 3 + r, 15 + c, KF_STATE) = T * B;
    }
```

Если измерений скорости камеры нет — этот блок можно не включать (влияние плеча войдёт только через H, раздел 6).

### 5.3 Других связей F нет

Ошибка установки δf напрямую в динамику скорости/позиции не входит (она сказывается только на извлечении углов камеры), поэтому в F для строк 18..20 — только единичная диагональ.

**Итого F** — прежние блоки (0..14) не меняются, добавляются: единичная диагональ 15..20 и, при необходимости, блок 5.2.

## 6. Матрица наблюдения H_cam (новая, `camera_processor.h`)

Размерность `H_cam`: `KF_CAM_MEAS × KF_STATE` = `6 × 21`. Строим по строкам.

### 6.1 Строки 0..2 — позиция камеры (метры, ENU)

Из `p_cam = p + C·l`:

```
δ(p_cam) = R·δφ   (север)      R = R_EARTH
δ(p_cam) = R·cos(φ)·δλ (восток)
δ(p_cam) = δh       (вверх)
δ(p_cam) += C·δl                     ← столбцы 15..17
δ(p_cam) += ( n_axis × l_nav )·δang  ← столбцы 6..8, для ψ,θ,γ
```

Покомпонентно:

```cpp
// координаты x[0..2] → метры
H[0][0] = R_EARTH;                 // δφ → север
H[1][1] = R_EARTH * cos(lat);      // δλ → восток
H[2][2] = 1.0;                     // δh → вверх

// плечо: столбцы 15..17 = C
for (int r = 0; r < 3; r++)
    for (int c = 0; c < 3; c++)
        H[r][15 + c] = at(C, r, c, 3);

// углы: столбцы 6 (ψ), 7 (θ), 8 (γ) — по образцу Fj_matrix
Vector cxl = vector_product(n_psi,   l_nav);   // δp_cam ← δψ
Vector cth = vector_product(n_theta, l_nav);   // δp_cam ← δθ
Vector cgm = vector_product(n_gamma, l_nav);   // δp_cam ← δγ
for (int r = 0; r < 3; r++)
{
    H[r][6] = cxl[r];
    H[r][7] = cth[r];
    H[r][8] = cgm[r];
}
```

> **Проверить знак** относительно существующего блока «δV̇ ← углы» (`ins_filter.h:131-136`): в коде `F[3+r][6+k] = T·(n_axis × f_nav)`. Для позиции знак выбирается так, чтобы при `C_true = C·(I + [δΘ]_×)` инновация была `z = измерение − номинал` без двойного минуса (см. раздел 10).

### 6.2 Строки 3..5 — углы камеры (рад)

- **Ошибки углов ИМУ x[6..8]** входят «единично» в пределах монтажа: после вычитания номинальных углов монтажа `att_cam_meas − att_mount` остаток инновации ≈ ошибка угла ИМУ. Для малых углов — `I_3` (как в GPS-контуре, где H на углы тоже единичный, `ins_filter.h:191`).

```cpp
H[3][6] = 1.0;   H[4][7] = 1.0;   H[5][8] = 1.0;
```

- **Установка δf (столбцы 18..20).** Малый телесный разворот δf после переноса в навигационную СК даёт малый вектор поворота `δΘ = C·δf`. Связь малого поворота с ошибками Эйлера:

```
[ n_psi | n_theta | n_gamma ] · δang_euler = δΘ = C·δf
```

Отсюда блок H (строки 3..5, столбцы 18..20):

```cpp
// M = [ n_psi | n_theta | n_gamma ]   (3×3, столбцы из раздела 3)
// Minv = return_matrix(M, 3)          (обратная по Гауссу-Жордану)
// Block = Minv · C
for (int r = 0; r < 3; r++)
    for (int c = 0; c < 3; c++)
        H[3 + r][18 + c] = /* (Minv · C)[r][c] */;
```

> Для малых pitch/roll матрица `M` близка к единичной (оси почти совпадают с осями нав. СК), поэтому численно `Minv·C ≈ C`. Проверяем на реальных манёврах.

### 6.3 Строки для скорости камеры (опционально; если есть optical flow)

```
 z_vel = V_cam_meas  −  ( V + C·(ω_b × l) )
 H[0..2][3..5]   = I_3
 H[0..2][15..17] = C·[ω_b]_×     (тот же блок, что в разделе 5.2)
```

## 7. Матрица шума измерения камеры R_cam

`R_cam` — диагональ `KF_CAM_MEAS × KF_CAM_MEAS`, задаётся по качеству VO/VIO (адаптивно, аналогично `evalAccelAttitude` в `trajectory.h`):

```cpp
// позиция: ~0.1..1 м (зависит от глубины/степени); углы: ~0.5..2°
R[0..2] = (0.3)^2 ...   R[3..5] = (1° · DEG_TO_RAD)^2
```

**Гейт по инновации** (защита от выбросов): `zᵀ·S⁻¹·z < χ²_df` (Махаланобис), как и для СНС. При невыполнении — пропускаем коррекцию камеры в этом кадре.

## 12. Наблюдаемость и возбуждение

- **Плечо δl** наблюдаемо на вращении аппарата (ω≠0): тогда коррекция по позиции камеры раскрывает смещение ИМУ↔камера. В прямолинейном полёте δl и ошибка позиции ИМУ не разделяются — фильтр оставляет их в исходных значениях (малая Q не даст увести).
- **Установка δf** наблюдаема при наклонах (pitch/roll) и разворотах; на стоянке не выявляется.
- **Практика:** начинать с `lc = {0,0,0}`, `fc = {0,0,0}`, а раскрытие произойдёт в первые маневры (аналог того, как работает `maneuver_tilt.h`). Если нет ни вращений, ни данных — состояния «спят».

## 13. Масштабный фактор монокуляра δs

### 13.1 Что это

Монокамера не определяет абсолютный масштаб сцены: из потока кадров восстанавливается геометрия только с точностью до масштабного множителя `s`. Если VIO/VO отдаёт позицию в «условных метрах», то истинная позиция камеры

```
p_cam = s · p̂_vo
```

где `p̂_vo` — поза, выданная трекером (без масштаба), `s` — неизвестная положительная константа (например, `s = 1.2` значит, что истинные расстояния на 20% больше оценённых). Ошибка оценки масштаба напрямую превращается в ошибку позиции, поэтому без её оценивания фильтр будет сноситься по позиции тем сильнее, чем дальше пройденная дистанция.

Стереокамера, структура-из-движения с известной базой или монокуляр с известной глубиной (например, по дальномеру) уже дают метрический масштаб — в этих случаях `s ≈ 1` и состояние `x[21]` не нужно.

### 13.2 Модель измерения

Масштаб можно рассматривать как «множитель» к позиции камеры: инновация позиции камеры (раздел 6.1) остаётся той же, но к истинному значению позиции камеры в навигационной СК добавляется вклад масштаба:

```
p_cam_true = p + C·l + s·p̂_vo
```

Линеаризация по `δs`:

```
δ(p_cam) ≈ p̂_vo · δs
```

### 13.3 Добавление в состояние

```cpp
constexpr int KF_STATE = 22;            // только для монокуляра; было 21
x[21] = δs                              // ошибка масштаба, безразмерная
```

### 13.4 Матрица наблюдения H (строки позиции, столбцы 21)

В позиционных строках `H_cam` (раздел 6.1) добавляется последний столбец:

```cpp
// инновация z[0..2] = H·x + s·p̂_vo + шум
for (int r = 0; r < 3; r++)
    H[r][KF_STATE - 1] = p_vo[r];      // столбец 21 (δs) = поза из VIO
```

где `p_vo` — позиция, выданная VIO/VO в метрах (в той же ENU-укладке, что и строки позиции).

### 13.5 Динамика (F) и шум

Масштаб — «почти константа», его дрейф мал:

```cpp
// F: единичная диагональ
at(Fj, 21, 21, KF_STATE) = 1.0;

// Q: маленькая, чтобы не давать масштабу убежать
const double sig_s = 1e-5;              // дрейф масштаба, 1/√c
at(Qj, 21, 21, KF_STATE) = sig_s * sig_s * T;
```

### 13.6 Начальная ковариация

```cpp
const double p_s = 0.1 * 0.1;           // 10% неопределённости масштаба (1σ)
pdiag[21] = p_s;
```

### 13.7 Инжекция

```cpp
st.scale += st.x[21];                   // номинал масштаба в NavState
// x[21] обнуляется общим циклом, см. 10.1
```

### 13.8 Как масштаб определяется на практике

- В комплексировании с БИНС масштаб наблюдаем через **корреляции с СНС/барометром**: пока есть хотя бы один опорный абсолютный источник (СНС), фильтр «вытаскивает» `s` из сравнения оценённой дистанции с истинной.
- Дополнительно можно подключить известную высоту полёта (аэродром, полоса) или дальность до характерной геометрии.
- Без опоры масштаб не наблюдаем (недоопределённость — VIO и истинная позиция масштабируются одинаково), и состояние «спит» на его начальном значении.

## 14. Относительные измерения (VIO/VO) — частный случай

Если видео даёт **относительное** изменение позы между кадрами (а не абсолют), то коррекция такая же, но инновация строится по разности приращений:

```
z = (Δp_vo, Δatt_vo) − (вычисленное БИНС Δp_cam, Δatt_cam)
```

H при этом та же (6×21), а плечо/установка входят через те же блоки. Это позволяет в будущем смешивать абсолютный СНС и относительный VIO в одном фильтре без переделки F/H.
