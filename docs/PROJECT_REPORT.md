# Отчёт о проделанной работе: создание Qt-приложения `imitator_gui`

> **Про консольную версию.** Отчёт описывает Qt-версию (GUI, тюнер, пресеты,
> тесты, `settings.ini`). В NoQT GUI и пресетов нет, `settings.ini` не
> читается, а модулей `simulation.*`, `data_source.*`, `filter_settings.*`,
> `ini_parser.*` не существует — см. `docs/noqt_deviations.md`.

**Проект:** `ITT_Students_Qt_Version` — Qt 6.12.0 GUI-обвязка над комплексом
БИНС + СНС с error-state фильтром Калмана (ESKF, 15 состояний).
**Отчёт охватывает:** весь путь от исходного консольного проекта до текущего
состояния приложения.
**Составлен:** 2026-10-11. **Обновлён:** 2026-10-12 (этап 13 — улучшение подбора
КФ: 13.0/13A/13B/13C выполнены, 13G запланирован).

## 1. Исходная точка: консольный проект ITT_Students

До создания приложения существовал консольный комплекс на C++ (`imitator`) и
Python-визуализация (`tools/plot_trajectory.py`):

- **Ядро ESKF (15 состояний):** ошибки координат (3), скорости (3), углов (3),
  смещения акселерометра (3), смещения гироскопа (3). Счисление БИНС + коррекция
  по СНС, выставка по акселерометру.
- **Входные данные:** `imu.dat` (200 Гц), `gps.dat` (5 Гц), `angle.dat`
  (100 Гц), `StartupNav.ini`. Стыковка углов с СНС — **по времени**, число строк
  не совпадает.
- **Выход:** три текстовых файла по 10 МБ (`result.txt`, `reference.txt`,
  `errors.txt`), которые просматривались скриптом. Это и было главной болью,
  ради которой создавалось приложение.

### 1.1 Доработки фильтра до создания приложения (замечания П1–П12)

Параллельно велась работа по замечаниям к фильтру
(`docs/filter_diff_vs_head.md`, `docs/p1_p3_fixes_report.md`):

- **П3 — Joseph-форма** обновления ковариации
  `P = (I−K·H)·P·(I−K·H)ᵀ + K·R·Kᵀ` в `correct()` (по СНС) и `correctTilt()`
  (по акселерометру): гарантирует симметрию и положительную полуопределённость
  `P` при любом `K`, а не только оптимальном.
- **П1 — `apply_reset_covariance`**: симметризация и страховка диагонали `P`
  после инжекции ошибок в номинал (при текущей эйлеровой параметризации G = I,
  поэтому пересчёт по существу не нужен — правка численно-архитектурная).
- **П2 — развязка tilt-контура:** обнуление строк `K` для `x[0..6]`, чтобы
  акселерометрическая коррекция (200 Гц) не «протягивалась» в координаты/курс.
- **П5 — `predict()` после интегрирования номинала:** устранён систематический
  сдвиг на `dt` между предсказанием и коррекцией.
- **`KalmanConfig` + `kalman_cfg`:** сигмы шумов вынесены из литералов в
  конфигурацию; добавлены `outage_start_s`/`outage_end_s` (окно искусственного
  пропадания СНС).
- **Калибровка P₀** по σ (`aligner.h`), **`argv[1]/argv[2]`** (каталог данных и
  `params.ini`), чтение `angle.dat` как радиан.
- Значения σ прогона №6 (2026-09-27): J_train 0.1768 / J_valid 0.1835,
  P95 pos 0.255/0.259 м.

Также разработаны (design-документация, в код не внесены) направления
модернизации: `docs/camera_state_extension.md` (состояния ошибок камеры —
плечо, установка, масштаб монокуляра), `docs/navigation_enhancements.md`
(матричная экспонента F/Q, адаптивное Q, оценка δt, loop closure),
`docs/gnss_guard_design.md` (защита комплексирования от отказов СНС).

## 2. Решение о создании приложения: `docs/qt_integration_proposal.md`

Ключевое архитектурное решение — **разделить проект на слои** (иначе Qt
«растёкся» бы по кодовой базе):

```
src/core/     — Qt-независимое ядро (C++17, STL) → статическая библиотека esfcore
src/console/  — консольный imitator (main.cpp), линкуется с esfcore
src/gui/      — Qt 6 приложение imitator_gui (QtWidgets)
```

Правила, принятые сразу и соблюдаемые по сей день:

- **В `src/core` не должно быть ни одного `#include <Q...>`** — проверяется
  автоматическим тестом `core_has_no_qt`.
- **Графики — только на `QPainter`** (не QtCharts/QtGraphs/QtQuick3D):
  QtCharts тянет QML-стек, не даёт контроля над 10⁵ точками и чаще меняет API.
- Используются **только LGPL-модули** Qt: Core, Gui, Widgets, Concurrent, Sql,
  PrintSupport, Test; в перспективе SerialPort, Network.
- Углы внутри — радианы, на выход — градусы (`RAD_TO_DEG`), конвертация в одном
  месте. Матрица хранится построчно (row-major), число столбцов передаётся явно.

### 2.1 Порядок внедрения (этапы 1–7 плана)

1. Разделение слоёв и CMake, паритет консоли **бит-в-бит**.
2. Тесты на core (`QtTest`) — до появления GUI.
3. Вынос параметров в `settings.ini` (свой INI-ридер в core, без QSettings).
4. `SimulationWorker` + QtSql (SQLite-история), отображение прогресса.
5. `PlotView` на QPainter (компоненты `x`, траектория БИНС/СНС).
6. `MainWindow` целиком (док-панели, таблицы, лог, сравнение прогонов).
7. Опционально: SerialPort, WebSocket, PDF-отчёт.

## 3. Реализация ядра приложения

### 3.1 Ядро и сборка (`src/core` → `esfcore`)

- `esfcore` — статическая библиотека (C++17, STL). Автотест `core_has_no_qt`
  ищет `#include <Q` и падает при нарушении.
- Единая точка расчёта — `nav::runSimulation`; GUI получает данные через
  `StepTelemetry` (указатель может быть `nullptr` — тогда консольный путь
  считает ровно тот же объём, что и раньше).
- Паритет с оригиналом `C:\ITT_Students` **проверен по SHA-256**: `result.txt`,
  `reference.txt`, `errors.txt` совпадают.
- Исправлен предсуществующий баг `time_first` (`simulation.cpp`): сентинель
  `== 0.0` не отличал «не установлено» от «первое время = 0» → заменён на
  `steps == 1`.

### 3.2 Параметры фильтра

- `FilterSettings` + собственный INI-ридер в core (без `QSettings`); значения по
  умолчанию совпадают с прежними константами. Поддерживается legacy `params.ini`.
- GUI: таблица «параметр / значение / единицы / диапазон», сохранение/загрузка
  `settings.ini`, сброс к умолчаниям.
- 8 коэффициентов КФ в `ParamsPanel` (`filter/sigma_*` из
  `filterSettingDescriptors`).

### 3.3 Расчёт и наблюдение

- `SimulationWorker` (QThread), приём телеметрии через потокобезопасный кольцевой
  буфер, перерисовка ~25 Гц.
- Пауза и ползунок темпа; `RunPacer` живёт в core и тестируется в
  `test_simulation` (в том числе остановка на `requestStop`).
- База SQLite: `runs`, `samples`, `filter_errors`, `covariances`.
- NIS / NEES: `ins::correct` по необязательному указателю заполняет
  `CorrectionStats` (`NIS = innovᵀ·S⁻¹·innov`, `NEES = innovᵀ·P_meas⁻¹·innov`,
  `dof = KF_MEAS = 9`). При `nullptr` консольный вывод не меняется.

### 3.4 Графики на QPainter (8 вкладок)

| Вкладка | Содержимое |
|---|---|
| Траектория | БИНС против СНС в метрах от точки старта |
| Координаты | Север/Восток (м) и высота |
| Углы | Курс, тангаж, крен |
| Скорости | Vn, Vh, Ve |
| Ошибки x | 15 компонент на кадрах коррекции СНС |
| Инновации | 9 компонент |
| Ковариация | 15 диагоналей `P` |
| Согласованность | NIS и NEES с линией ожидания (`dof = 9`) |

- Зум колесом относительно курсора, панорамирование перетаскиванием, сброс
  диапазона двойным щелчком и по меню; Ctrl — только X, Shift — только Y.
- Агрегация min/max по пиксельным колонкам (200 Гц × 600 с рисуется огибающей),
  прореживание рядов до 2000 точек.
- Экспорт: PNG/JPG, SVG (`QSvgGenerator`), PDF (`QPdfWriter`), CSV таблицы,
  лог в файл.
- Кэш кадра в `QPixmap`: ключ — размер виджета, версия содержимого и границы
  осей; `setCacheEnabled(false)` отключает; курсор рисуется поверх кэша.

### 3.5 Сравнение прогонов и PDF-отчёт

- Меню «Сравнение»: второй прогон выбирается из истории SQLite; ряды
  добавляются пунктиром; опция «показывать разность» (`текущий − второй`),
  координаты приводятся к метрам от общей точки, стыковка по ближайшему времени.
- `PdfReport` (`src/gui/export/pdf_report.*`): титул, сводка NIS/NEES, RMS и
  максимум по 15 компонентам ошибок, выборка таблицы NIS/NEES, затем графики —
  тем же кодом QPainter (`renderTo`). Меню «Экспорт → Сводный отчёт в PDF…».

### 3.6 История: сортировка и фильтр

- `HistoryModel` (`QAbstractTableModel`) — источник данных; в `ParamsPanel`
  `QSortFilterProxyModel`: сортировка по клику (по умолчанию свежие сверху) и
  фильтр по строке (имя, дата, каталог), `mapToSource` при открытии.

## 4. Устойчивость чтения и новый формат данных

### 4.1 Повреждённые датасеты `dataset_shum` (2026-10-09)

Проверка на реальных данных выявила: **все 9 наборов повреждены** — острова
бинарного мусора в `imu.dat` (у `figure8_8ms` — ещё и в `gps.dat`), `angle.dat`
чист. 7 наборов падали на `std::stod`, а 2 «проходивших» тихо обрывались на байте
`0x1A` (CRT в текстовом режиме трактует Ctrl-Z как EOF). Решение: датасеты не
править, а сделать чтение устойчивым:

- `stod` в `try`/`catch`, повреждённая строка пропускается;
- файлы открываются в **бинарном режиме** (`std::ios::binary`);
- регрессионный тест `test_data_io::skipsGarbageRows`.

Итог: все 9 наборов проходят до конца без крэша и без тихой обрезки
(exit=0; последняя строка `result.txt` совпадает с последним моментом `imu.dat`).
Бит-паритет на валидных файлах сохранён.

### 4.2 Новый формат `.data`

Универсализация единого интерфейса ридеров с **автоопределением формата** (не
параллельный API): время `ЧЧ:ММ:СС.нс`, imu 7 колонок, gps 7 колонок, angle 14
колонок. Добавлены `parseTimestamp` + fallback `stod`, автодетект по `':'` в
первом токене, `parseAlignImuRow` в `Aligner.cpp`, выбор файла `.dat`→`.data`
(впоследствии вынесен в `FileDataSource`, этап 8), фикстуры в
`test_data_io`/`test_simulation`. Реальных `.data`-наборов на диске нет — их
поставляет генератор.

## 5. Этапы развития приложения (`docs/DEVELOPMENT_PLAN.md`, принят 2026-10-08)

Принцип порядка: сначала лёгкие независимые фичи, затем анимация (опирается на
экспорт), затем крупный генератор, затем документация, затем страховка
(паритет+CI перед рефакторингом ядра), затем подбор КФ, в конце — потоки и
деплой. Каждый этап — законченное состояние (зелёная сборка, `ctest`, отдельный
коммит).

### Этап 1 — Конфигурации и история (выполнено)

- «Сохранить settings.ini как…» (Save As).
- Пресеты параметров — каталог `presets/*.ini` рядом с приложением, кнопка-меню
  «Пресеты ▾» во вкладке «Параметры» (сохранить/загрузить/удалить).
- В `runs` добавлена колонка `settings_ini TEXT` (снимок `FilterSettings` в INI),
  миграция `ADD COLUMN` для старых БД; при открытии прогона — просмотр/применение.

### Этап 7 — Подбор коэффициентов КФ (выполнено)

Готовый алгоритм из `C:\TUNE_KALMAN` перенесён без правок ядра:

- **`tools/kalman_tuner/tune_kalman.py`** — Sobol-разведка → Nelder-Mead с
  несколькими стартами, расширение границ при выходе на стенки, фиксированный
  SEED, метрика J_train/J_valid по p95/tail с train/valid-сплитом.
- 8-й коэффициент `sigma_h` (в старом тюнере зафиксирован на 5.0 м).
- Выход — пресет `presets/tuned*.ini` (читается консолью и GUI).
- **GUI-вкладка «Подбор»** (`tuning_panel.*`): выбор каталога/интерпретатора/режима
  (полный / `--quick` / `--global-only`), фоновый `QProcess` с `PYTHONIOENCODING=utf-8`,
  вывод в консоль вкладки, «Остановить», «Применить пресет…».
- **Баг финализации (исправлен 2026-10-10):** на Windows воркеры `Pool`
  пересоздают модуль и использовали шаблонные `sigma_ref` вместо конфига, из-за
  чего пресет получался с другими σ, чем реально отработали. Исправление:
  `save_preset` берёт значения из `params.ini` финального прогона.
- **Синтетика (`dataset_shum`, 9 наборов):** подбор quick и полный (~2.3 ч),
  валидация `validate_presets.py` (репликация протокола тюнера). Итог: p95
  ≈ 1.6–10.5 м против 34–57 м у дефолтного пресета (выигрыш ~10×). Подбор —
  опциональная функция, дефолты тюнер не трогает, применение выключено по
  умолчанию.
- **Известные ограничения** (вынесены в этап 13 «Улучшение алгоритма подбора КФ»,
  в работе): σ у стенок/плато (`g`/`a` на верхней, `pos`/`v` занижены,
  `bg`/`ba` не идентифицируются); устойчивый одиночный выброс набор `square_650`
  138 м при t≈638.3.

### Этап 8 — `IDataSource` в core (выполнено 2026-10-11)

Развязка ядра от файлов: счисления читает входные потоки через абстрактный
интерфейс, а не напрямую из `imu.dat`/`gps.dat`.

- **Интерфейс `data_io::IDataSource`** (`src/core/data_io/data_source.h`):
  `open()` (открытие/перемотка с начала), `hasAngle()`, `imuRowCount()`,
  `nextImu(row)`, `nextSns(SnsSample)`, `startupNav(...)`, `close()`, `error()`.
- **`FileDataSource`** — файловая реализация: переносит из `runSimulation`
  прежний выбор файлов (`imu.dat`/`imu.data` и т.д.), разбор потоков через
  `ImuReader`/`SnsReader` и чтение `StartupNav.ini`.
- **`MockDataSource`** — источник в памяти (данные задаются заранее): для тестов
  и как будущая основа потоковых источников.
- **`nav::RunOptions::source`** (`IDataSource *`, `nullptr` — файлы по `data_dir`);
  `runSimulation` читает оба потока и выполняет выставку **только через интерфейс**.
- **Выставка:** вынесена в `alignFromImuProvider(...)` (`aligner.hpp`), принимающий
  поставщика строк ИМУ; `get_angle_start` оставлен тонкой файловой обёрткой для
  совместимости. Это позволило гонять выставку и по файлу, и по памяти без
  дублирования математики.
- **Исправление адаптеров:** `ImuReader::open`/`SnsReader::open` теперь закрывают
  прежний файл и сбрасывают состояние потока — иначе повторное `open()` на том же
  объекте (перемотка источника) оставляло `failbit` и чтение сразу давало EOF.
- **Паритет подтверждён:** `test_parity` (консоль vs GUI бит-в-бит) и новый
  `test_data_source` (прогон через `MockDataSource` == через `FileDataSource`
  **побайтово** по всем трём файлам); плюс сверка с дорефакторным `imitator.exe`
  на `data/raw` — SHA-256 `result/reference/errors` совпали.
