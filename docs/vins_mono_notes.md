# Алгоритм видеонавигации VINS-Mono

**VINS-Mono** (Monocular Visual-Inertial System) — система оценки состояния по монокулярной камере и IMU, предложенная группой HKUST Aerial Robotics (Tong Qin, Peiliang Li, Shaojie Shen, 2017–2018). Это минимальный сенсорный набор, из которого можно восстановить **метрическую 6-DoF** навигацию: масштаб, крен и тангаж наблюдаемы благодаря IMU.

Оригинальная статья: [Qin, Li, Shen. *VINS-Mono: A Robust and Versatile Monocular Visual-Inertial State Estimator*](https://arxiv.org/abs/1708.03852).  
Код: [HKUST-Aerial-Robotics/VINS-Mono](https://github.com/HKUST-Aerial-Robotics/VINS-Mono).

---

## 1. Зачем нужен IMU вместе с монокамерой

Чисто визуальный монокулярный SLAM (ORB-SLAM, DSO и т.п.) не восстанавливает **метрический масштаб**. IMU даёт:

- наблюдаемый масштаб (при достаточном ускорении платформы);
- наблюдаемые крен и тангаж (направление силы тяжести);
- заполнение «дыр» визуального трекинга (размытие, слабая текстура, смена освещения).

Цена: система сильно нелинейна, нельзя стартовать «из покоя» без возбуждения акселерометра, критичны инициализация, смещения IMU и внешняя калибровка камера–IMU. Дрейф остаётся в **4 степенях свободы**: \((x, y, z)\) и рыскание (yaw).

## 2. Системный пайплайн

```
изображения + IMU
        │
        ▼
┌───────────────────────┐
│  Предобработка        │  KLT + углы, прединтеграция IMU
└───────────┬───────────┘
            ▼
┌───────────────────────┐
│  Инициализация        │  SfM → выравнивание визуала и IMU
└───────────┬───────────┘
            ▼
┌───────────────────────┐
│  VIO (скользящее окно)│  совместная нелинейная оптимизация
└───────────┬───────────┘
            ├──────────────► relocalization (DBoW2 + признаки)
            ▼
┌───────────────────────┐
│  Pose graph (4-DoF)   │  глобальная согласованность, замыкание петель
└───────────────────────┘
```

Модули VIO, relocalization и pose graph работают **параллельно** с разной частотой.

**Системы координат:**

| Обозначение | Смысл |
|-------------|--------|
| \((\cdot)^w\) | мировая СК; ось \(z\) совпадает с направлением тяжести |
| \((\cdot)^b\) | СК тела = СК IMU |
| \((\cdot)^c\) | СК камеры |
| \(b_k\), \(c_k\) | IMU / камера в момент \(k\)-го кадра |
| \(\mathbf{q}^w_b, \mathbf{p}^w_b\) | ориентация (кватернион Гамильтона) и положение IMU в мире |
| \(\mathbf{g}^w = [0,0,g]^\top\) | вектор тяжести в мире |

## 3. Предобработка измерений

### 3.1. Визуальный фронтенд

Для каждого нового кадра:

1. Трекинг уже найденных точек — **KLT optical flow**.
2. Детекция новых углов (Harris / Shi–Tomasi), чтобы держать **100–300** точек; минимальное расстояние между точками для равномерного покрытия.
3. Undistort → проекция на **единичную сферу**.
4. Отсечение выбросов: RANSAC по **фундаментальной матрице**.

**Выбор кейфрейма** (два критерия):

- средний параллакс относительно предыдущего кейфрейма выше порога; вращение компенсируется короткой интеграцией гироскопа, чтобы не считать кейфреймом чистое вращение (там нельзя триангулировать);
- число треков упало ниже порога — кадр берётся, чтобы не потерять трекинг.

### 3.2. Прединтеграция IMU

Сырые измерения:

\[
\hat{\mathbf{a}}_t = \mathbf{a}_t + \mathbf{b}_{a_t} + \mathbf{R}^t_w \mathbf{g}^w + \mathbf{n}_a,
\quad
\hat{\boldsymbol{\omega}}_t = \boldsymbol{\omega}_t + \mathbf{b}_{w_t} + \mathbf{n}_w.
\]

Шум измерения — гауссов; смещения \(\mathbf{b}_a, \mathbf{b}_w\) — **случайное блуждание**.

Прямая интеграция в мировой СК зависит от \(\mathbf{p}, \mathbf{v}, \mathbf{q}\) в начале интервала. В оптимизационном VIO эти состояния постоянно меняются — повторная интеграция слишком дорогая.

**Идея прединтеграции:** перенести интеграл в локальную СК кадра \(b_k\) и накопить величины, зависящие только от IMU:

\[
\boldsymbol{\alpha}^{b_k}_{b_{k+1}},\quad
\boldsymbol{\beta}^{b_k}_{b_{k+1}},\quad
\boldsymbol{\gamma}^{b_k}_{b_{k+1}}
\]

(приращение положения, скорости и относительная ориентация). Они зависят от смещений, но не от абсолютной позы \(b_k\).

При малом изменении смещения результат поправляют **якобианом первого порядка**; при большом — пересчитывают. Ковариация ошибки прединтеграции распространяется линейной моделью в непрерывном / дискретном времени. В реализации обычно **метод средней точки** (mid-point).

Модель измерения IMU между кадрами связывает \(\boldsymbol{\alpha}, \boldsymbol{\beta}, \boldsymbol{\gamma}\) с \(\mathbf{p}, \mathbf{v}, \mathbf{q}\) и разностями смещений соседних кадров.

## 4. Инициализация оценщика

Монокулярный VIO нельзя «включить» с нулевыми начальными условиями: масштаб не виден камерой, система нелинейна, смещения IMU неизвестны. VINS-Mono использует **слабо связанную** схему.

### Шаг 1. Vision-only SfM в скользящем окне

1. Найти пару кадров: \(\ge 30\) общих точек и параллакс \(\ge 20\) пикселей (с компенсацией вращения).
2. **Five-point algorithm** — относительные \(\mathbf{R}\) и \(\mathbf{t}\) с точностью до масштаба.
3. Триангуляция точек, затем **PnP (EPnP)** для остальных кадров окна.
4. Полный **bundle adjustment** по ошибке репроекции.

Референс — первый кадр камеры \(c_0\). Позы переводятся в СК IMU по приближённой внешней калибровке \((\mathbf{p}^b_c, \mathbf{q}^b_c)\). Неизвестный масштаб \(s\) связывает визуальную структуру с метрикой.

### Шаг 2. Калибровка смещения гироскопа

Относительный поворот из SfM сравнивается с \(\boldsymbol{\gamma}\) из прединтеграции. Линеаризация по \(\delta\mathbf{b}_w\) даёт МНК-оценку смещения гироскопа. Затем IMU **переинтегрируют** с новым \(\mathbf{b}_w\).

Смещение акселерометра на этом этапе **не оценивают**: оно слабоотделимо от тяжести на коротком окне.

### Шаг 3. Скорость, тяжесть, масштаб

Линейная система по \(\boldsymbol{\alpha}, \boldsymbol{\beta}\) и позам SfM:

\[
\mathcal{X}_I = \bigl[\mathbf{v}^{b_0}_{b_0},\ldots,\mathbf{v}^{b_n}_{b_n},\; \mathbf{g}^{c_0},\; s\bigr].
\]

Решение — МНК по всем соседним парам кадров окна.

### Шаг 4. Уточнение тяжести

Модуль \(g \approx 9.81\,\mathrm{m/s^2}\) известен, у \(\mathbf{g}\) остаётся **2 DoF**. Тяжесть параметризуют на касательной плоскости сферы:

\[
\mathbf{g} = g\,\hat{\bar{\mathbf{g}}} + w_1\mathbf{b}_1 + w_2\mathbf{b}_2,
\]

итеративно уточняют \(w_1, w_2\).

### Шаг 5. Переход в мировую СК

Поворот \(c_0 \to w\), чтобы тяжесть легла на ось \(z\). Скорости переводят в мир, трансляции SfM умножают на \(s\). Эти величины — старт **нелинейного** VIO.

Та же процедура используется для **восстановления после сбоя**.

## 5. Тесно связанный VIO (скользящее окно)

### 5.1. Вектор состояния

\[
\mathcal{X}
=
\bigl[
\mathbf{x}_0,\ldots,\mathbf{x}_n,\;
\mathbf{x}^b_c,\;
\lambda_0,\ldots,\lambda_m
\bigr],
\]

\[
\mathbf{x}_k
=
\bigl[
\mathbf{p}^w_{b_k},\;
\mathbf{v}^w_{b_k},\;
\mathbf{q}^w_{b_k},\;
\mathbf{b}_a,\;
\mathbf{b}_g
\bigr],
\quad
\mathbf{x}^b_c = \bigl[\mathbf{p}^b_c,\; \mathbf{q}^b_c\bigr].
\]

\(\lambda_l\) — **обратная глубина** признака относительно первого наблюдения (компактнее, чем 3D-точка). Внешняя калибровка камера–IMU оценивается **онлайн**.

### 5.2. Целевая функция (MAP)

\[
\min_{\mathcal{X}}
\Biggl\{
\|\mathbf{r}_p - \mathbf{H}_p\mathcal{X}\|^2
+
\sum_{k\in\mathcal{B}}
\|\mathbf{r}_{\mathcal{B}}(\hat{\mathbf{z}}^{b_k}_{b_{k+1}}, \mathcal{X})\|^2_{\mathbf{P}^{b_k}_{b_{k+1}}}
+
\sum_{(l,j)\in\mathcal{C}}
\rho\bigl(\|\mathbf{r}_{\mathcal{C}}(\hat{\mathbf{z}}^{c_j}_l, \mathcal{X})\|^2_{\mathbf{P}^{c_j}_l}\bigr)
\Biggr\}.
\]

- \(\{\mathbf{r}_p, \mathbf{H}_p\}\) — **приор** после маргинализации;
- \(\mathbf{r}_{\mathcal{B}}\) — невязка прединтегрированного IMU;
- \(\mathbf{r}_{\mathcal{C}}\) — визуальная невязка;
- \(\rho(\cdot)\) — норма Хьюбера для выбросов.

Решатель в оригинале — **Ceres**.

### 5.3. Невязка IMU

Сравнение предсказанных по позам/скоростям \(\boldsymbol{\alpha}, \boldsymbol{\beta}, \boldsymbol{\gamma}\) с прединтеграцией плюс разность смещений соседних кадров. Ошибка ориентации — векторная часть кватерниона (3D error-state).

### 5.4. Визуальная невязка на единичной сфере

Не ошибка в пикселях плоскости pinhole, а разность лучей на сфере. Это единообразно работает для wide-angle / fisheye.

Признак \(l\) впервые виден в кадре \(i\) с обратной глубиной \(\lambda_l\). Его переносят в кадр \(j\) цепочкой преобразований:

камера \(i\) → IMU \(i\) → мир → IMU \(j\) → камера \(j\).

2D-невязка — проекция разницы единичных векторов на **касательную плоскость** наблюдения.

### 5.5. Маргинализация (ограничение сложности)

Стратегия (два случая для «предпоследнего» кадра):

| Предпоследний кадр | Действие |
|--------------------|----------|
| **Кейфрейм** | оставить в окне; **выкинуть самый старый** кадр вместе с визуальными и инерциальными измерениями → Schur complement → новый приор |
| **Не кейфрейм** | выбросить визуальные измерения кадра, но **сохранить** IMU и продолжить прединтеграцию к следующему кадру |

Цель: в окне остаются кадры с **достаточным параллаксом** и возбуждением акселерометра; граф остаётся разреженным.

Линеаризация в точке маргинализации фиксируется (возможна субоптимальность); для локального VIO это приемлемо.

### 5.6. Выход на частоте камеры и IMU

- Полная оптимизация окна может быть медленнее частоты кадров. Тогда **motion-only BA**: оптимизируют только последние позы и скорости, глубины/смещения/экстраинзики фиксированы — порядка миллисекунд, \(\sim 30\,\mathrm{Hz}\).
- Между кадрами последнюю оценку **проталкивают вперёд** сырыми IMU — обратная связь для управления дроном на частоте IMU.

### 5.7. Детекция отказа

Признаки сбоя:

- слишком мало треков в последнем кадре;
- скачок позиции/ориентации между оценками;
- резкий скачок смещений или внешней калибровки.

При сбое — возврат к инициализации и **новый сегмент** pose graph.

## 6. Relocalization (замыкание петли на уровне признаков)

Скользящее окно ограничивает вычислительную стоимость, но накапливает дрейф в \(x,y,z\) и yaw.

1. **Детекция места:** DBoW2. Дополнительно \(\sim 500\) углов с дескрипторами **BRIEF** (отдельно от точек VIO). Сырые изображения не хранят — только дескрипторы.
2. **Сопоставление:** BRIEF matching + двухэтапный RANSAC:
   - 2D–2D: фундаментальная матрица;
   - 3D–2D: PnP по 3D точкам текущего окна.
3. **Тесная интеграция:** позы старых кадров петли считаются **константами**. В ту же оптимизацию окна добавляют визуальные невязки сопоставленных признаков. Можно использовать **несколько** прошлых кадров сразу — многоракурсные ограничения, более гладкая оценка. Размер вектора состояния окна не растёт.

## 7. Глобальная оптимизация pose graph (4-DoF)

Крен и тангаж наблюдаемы → оптимизируют только \(\mathbf{p}^w\) и yaw \(\psi\).

Когда кейфрейм **маргинализируется** из окна, он становится вершиной графа.

**Рёбра:**

- **последовательные** — относительные \(\hat{\mathbf{p}}^i_{ij}\) и \(\hat{\psi}_{ij}\) из VIO к нескольким предыдущим кейфреймам;
- **петли** — те же 4-DoF относительные преобразования из relocalization.

Невязка ребра \((i,j)\):

\[
\mathbf{r}_{i,j}
=
\begin{bmatrix}
\mathbf{R}(\hat{\phi}_i, \hat{\theta}_i, \psi_i)^{-1}(\mathbf{p}^w_j - \mathbf{p}^w_i) - \hat{\mathbf{p}}^i_{ij} \\
\psi_j - \psi_i - \hat{\psi}_{ij}
\end{bmatrix},
\]

где крен/тангаж \(\hat{\phi}, \hat{\theta}\) берутся из VIO и не оптимизируются.

Для рёбер петли — норма Хьюбера; для последовательных — нет (выбросы уже отфильтрованы в VIO).

Pose graph и relocalization — **разные потоки**: relocalization всегда использует актуальную (или предыдущую готовую) конфигурацию графа.

**Управление размером:** кейфреймы с петлями сохраняют; остальные можно прореживать пропорционально пространственной плотности.

## 8. Сводка алгоритма (пошагово)

```
для каждого IMU-отсчёта:
    накопить прединтеграцию к следующему кадру
    (опционально) IMU-rate: forward-propagate последнюю позу VIO

для каждого изображения:
    KLT + новые углы + undistort + RANSAC
    решить, кейфрейм ли кадр (параллакс / число треков)

    если ещё INITIAL:
        копить окно; при достаточном параллаксе:
            SfM → bias гироскопа → (v, g, s) → уточнить g
            перейти в мировую СК → NON_LINEAR

    иначе (NON_LINEAR):
        оптимизация окна: приор + IMU + визуал [+ петли]
        детектировать сбой → при необходимости реинициализация
        сдвинуть окно / маргинализация (Schur)
        если кейфрейм ушёл из окна → вершина pose graph
        motion-only BA при необходимости (частота камеры)

параллельно:
    DBoW2; при петле — matching + tightly-coupled relocalization
    4-DoF pose graph
```

## 9. Особенности реализации и применения

- **ROS**-версия для Linux; мобильная — VINS-Mobile (iOS).
- Онлайн-оценка **extrinsic** камера–IMU; режимы с грубым начальным приближением или калибровкой «с нуля» при вращении устройства.
- Поздние расширения линейки: временная калибровка камера–IMU, rolling shutter, VINS-Fusion (стерео / GPS).
- Типичные сценарии: навигация MAV, AR, длительные handheld-траектории (километры).

---

## 10. Ключевые идеи, которые отличают VINS-Mono

| Идея | Зачем |
|------|--------|
| Прединтеграция IMU на многообразии + коррекция bias | не переинтегрировать IMU при каждом шаге оптимизации |
| SfM + линейное выравнивание | устойчивый старт без предположения «стоим на месте» |
| Тесная оптимизация в окне | совместная оценка позы, скорости, bias, масштаба, extrinsics |
| Обратная глубина + невязка на сфере | компактное состояние, поддержка широкого угла |
| Маргинализация, а не полный BA | постоянное время |
| Relocalization на уровне признаков, не только относительная поза | гладкость и точность замыкания |
| 4-DoF pose graph, не 6/7-DoF | не ломать наблюдаемые крен/тангаж |
