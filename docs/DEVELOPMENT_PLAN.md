# План развития imitator_gui

Принят 2026-10-08. Связан с `FUTURE_PROPOSALS.md` (общий перечень идей) и
`docs/qt_integration_proposal.md` (этапы 1–6 уже выполнены).

## Принцип порядка

Сначала лёгкие независимые фичи (быстрый видимый результат), затем анимация
(опирается на инфраструктуру экспорта), затем крупный генератор (изолирован в core),
затем документация (описывает уже сделанные фичи), затем страховка (паритет+CI —
перед рефакторингом ядра), затем подбор коэффициентов КФ (опирается на
воспроизводимость прогонов паритета), в конце — потоковые источники и деплой.

Каждый этап — законченное состояние: сборка зелёная, `ctest` проходит,
отдельный коммит. Общие правила на всех этапах:

- `core` без Qt (проверяется тестом `core_has_no_qt`);
- комментарии по-русски, без лишних восклицательных знаков;
- проверка: `cmake --build build --target imitator_gui` + `ctest --test-dir build --output-on-failure`;
- минимальные изменения, без переписывания фильтра без необходимости.

Трудоёмкость: S — малый, M — средний, L — крупный.

## Этап 7 — Подбор коэффициентов фильтра Калмана (L)

Задача проекта: подобрать коэффициенты шумов ESKF. Готовый алгоритм подбора уже
существует в отдельном репозитории `C:\TUNE_KALMAN` — это та же линия ядра, но
сборка монолитная, оптимизатор на Python (`tune_kalman_v3.py`): Sobol-разведка →
Nelder-Mead с несколькими стартами, расширение границ при выходе на стенки,
фиксированный SEED, метрика J_train/J_valid по p95/tail с train/valid-сплитом
(против переобучения).

Совместимость с нашим core достигается без правок ядра:
- консольный `imitator` принимает файл настроек аргументом:
  `imitator <data_dir> <settings.ini>` (src/console/main.cpp);
- плоский params.ini старого тюнера с 7 ключами `sigma_g…sigma_ang` читается 1-в-1
  через `applyLegacyParamsFile` (filter_settings.cpp:131); `sigma_ang → sig_hdg`;
- изоляция точки прогона: `utils::toolsDir` берёт `<cwd>/tools` (paths.h:45-53) —
  каждой точке свой каталог, как `local_*/` в TUNE_KALMAN;
- в GUI все 8 коэффициентов уже выставлены в ParamsPanel (`filter/sigma_*` из
  `filterSettingDescriptors`); NIS/NEES в `CorrectionStats` — дополнительный
  индикатор согласованности при подборе.

Шаги:
- A. Перенести оптимизатор (по образцу tune_kalman_v3.py) в `tools/kalman_tuner/`:
  драйвер запускает `build/imitator.exe <data_dir> <work/params.ini>` в
  изолированных cwd, извлекает метрики из result/reference/errors.txt
  (p95/mean/tail, train/valid-сплит), считает J.
- B. Добавить 8-й коэффициент `sigma_h` (в старом тюнере зафиксирован на 5.0 м).
- C. Данные: сначала run_hk-подобные (паритет с результатами v3), затем синтетика
  из этапа 4 и формат `.data` (этап 12, выполнен).
- D. Сохранение результата: best-точка → пресет `presets/tuned.ini` (этап 1) +
  отчёт в духе `tuning_runs_comparison.md`; воспроизводимость — фиксированный SEED.
  Замечание (баг финализации, исправлен 2026-10-10): на Windows воркеры `Pool`

### Подбор — опциональная функция

Выход тюнера — только пресет `presets/tuned.ini` через существующие
`loadFilterSettings`/`dumpFilterSettings`. Дефолты и текущий settings.ini тюнер
не трогает никогда. Применение — явный выбор, выключено по умолчанию:
- GUI: переключатель «Применять подобранный пресет» (off) + выбор конкретного
  пресета из списка (Этап 1); выбор хранится в `run/`-секции settings.ini.
- Консоль: подбор действует только если settings-файл указывает на пресет
  (`imitator <data_dir> <preset.ini>`), иначе — прежнее поведение.
- Паритет/воспроизводимость штатных прогонов (Этап 6) от присутствия тюнера
  не зависят.

## Этап 12 — Поддержка нового формата входных данных `.data` — ВЫПОЛНЕНО

Вводная из ветки `ITT_Students-Katya` (папки `dataset_shum`, `imitator_sq`,

(файлы `imu.data`/`gps.data`/`angle.data`). Реализовано вместе с этапом 8
(`IDataSource`): автоопределение формата стало деталью файловой реализации
источника.

### Различия форматов (проверено на реальных файлах)

| Параметр | Старый `.dat` | Новый `.data` |
|---|---|---|
| время | число, секунды | `ЧЧ:ММ:СС.нс` (например `00:00:00.006000128`) |
| imu | 8 кол.: time, ns, wx…az | 7 кол.: time, wx…az |
| gps | 8 кол. (idx 2..7: lat, lon, alt, vn, vh, ve), lat/lon в ° | 7 кол. (idx 1..6), lat/lon в ° |
| angle | 5 кол. (idx 2..4: roll, pitch, yaw), рад | 14 кол. (idx 11..13), рад |
| заголовок | 1 строка | 1 строка |

Важно: текущее ядро уже трактует углы angle как радианы (data_reader.cpp:142-144;
подтверждает test_data_io.cpp:134-137). Комментарий в data_reader.h про «градусы»
устарел.

### Дизайн-решение: универсализация, а не второй интерфейс

Единый интерфейс `ImuReader`/`SnsReader` с автоопределением формата при `open()`
(первый токен первой строки данных содержит `:` — новый формат; колонок angle
14+ — новый). Формат-специфичный разбор — изолированные свободные функции в
`data_io` (`parseTimestamp`, `parseImuLine`, раскладки gps/angle), покрываются
тестами. Публичные сигнатуры не меняются: 8-колоночный `row` и `SnsSample` —
единый канонический контракт для simulation/GUI/тестов и будущих IDataSource.
Отдельный параллельный интерфейс не нужен: различия форматов синтаксические,
второй ридер продублировал бы ~80% логики. Алгоритмические датасет-хаки
(курс +16°, `repairEulerReference`, `headingReferenceUsable` из imitator_sq) в
ридеры не переносить: они относятся к эталону/счислению, а не к разбору.

### Шаги

- A. `data_io`: `parseTimestamp` (ЧЧ:ММ:СС + fallback stod), `parseImuLine` →
  8-кол row; `SnsReader` — раскладки gps (7/8 кол) и angle (14/5 кол) по формату.
- B. `Aligner.cpp`: заменить `sscanf("%lf %*s …")` на разбор с `parseTimestamp`
  (теперь ЧЧ:ММ:СС время читается корректно — выставка по реальным меткам).
- C. Выбор файлов `имя.dat` → при отсутствии `имя.data` вынесен в
  `FileDataSource` (этап 8); `runSimulation` работает через `IDataSource`.
- D. Тесты: `test_data_io` (парсинг `imu.data`, `gps.data`+`angle.data` 14 кол),
  `test_simulation::runsNewFormatDataset` (полный прогон на `.data`),
  `test_data_source::fileSourceReadsNewFormat` (FileDataSource выбирает `.data`)
  и `test_data_source::realDataFormatSanity` (sanity-прогон на реальном наборе
  `ITT_Students-Katya/imitator_sq/test/line_dataset`, `QSKIP` при отсутствии).
  Паритет на старых данных подтверждён `test_parity` (бит-в-бит).

### Итог реализации

Формат `.data` поддержан универсальным ридером (`ImuReader`/`SnsReader`) без
отдельного интерфейса; публичные сигнатуры не менялись. Реальный набор
`line_dataset` (imu/gps/angle + `StartupNav.ini`, time=120) прогоняется
end-to-end: выставка по `StartupNav`, вывод `result/reference/errors`. Проверено
вручную на `build/src/console/imitator.exe` и покрыто `realDataFormatSanity`.

### Риски

- Бит-паритет консоли на `.dat` — главный критерий.
- Не менять сигнатуры `ImuReader`/`SnsReader` (ими пользуются GUI, счётчики,
  `ForwardingSink`).
- core без Qt (чистый STL).

### Связанные находки (в задачу «входной формат» не вошли)

Автономная БИНС (`V_free`/`*_ins` в trajectory.h imitator_sq), единый выход
`kalman15_line2.txt` (58 колонок), `dN/dE` в метрах в errors, спецификация
генератора в `dataset_shum/params.json` (профиль, шумы, seed) — пригодится на

## Этап 13 — Улучшение алгоритма подбора коэффициентов КФ (M) — В РАБОТЕ

Этап 7 дал рабочие пресеты, но прогоны вскрыли системные ограничения
оптимизатора. Прогноз: ценность — умеренная, только если возникнет
необходимость полагаться на настроенные σ вне dataset_shum/run_hk. Ставится
после этапов 4/7, до возможного встраивания подбора в «боевой» контур.

> Введение в методики 13A/13B/13C (для тех, кто слышит впервые, включая тему
> размера сетки 200 Гц vs истина) — `docs/kalman_tuning_methods.md`.

Проблемы, выявленные на полных (не quick) прогонах 9 наборов (см. шаги F/I,
2026-10-10):
- **Параметры у стенок, а не в минимуме**: `sigma_g`/`sigma_a` упираются в
  верхнюю границу, `sigma_pos`/`sigma_v` систематически занижаются (фильтр
  «верит GPS сильнее»), `sigma_bg`/`sigma_ba` на плато (плохо идентифицируются),
  `sigma_ang`/`sigma_h` — внутри. Границы поиска по ряду осей не информативны.
- **J-ландшафт на синтетике отличается от run_hk**: на run_hk J≈0.12–0.35,
  на dataset_shum J≈1.2–3.8 — дефолтный конфиг даёт на синтетике p95 34–57 м,
  поэтому вокруг результатов нужен контроль адекватности, а у оптимизатора нет
  явного механизма штрафа за «копию эталона» при обработке noisefree-данных.
- **Одиночный выброс в метрике**: square_650 имеет устойчивый артефакт 138 м на
  ~21 строке при t≈638.3 (переход «разворот→спуск»); метрика P99.9@200Гц его
  учитывает, но более гранулярная оценка хвоста по окнам (пропорция выбросов,
  проверка нормальности распределения ошибок) позволила бы отделить сбой
  данных от качества подбора.

**Принцип универсальности интервалов** (2026-10-12): u-интервалы (`u =
log10(σ/σ_ref)`) задаются как **фиксированные константы**, одинаковые для любых
(в т.ч. будущих) наборов, и **не** выводятся из оптимумов имеющихся наборов.
Достаточное условие — те же интервалы не теряют точности относительно 13A/13B
(ни одна ось не у стенки и `J_valid` не хуже); паспортные данные датчиков и
классы точности для этого не требуются. Асимметричные границы 13B, построенные
по оптимумам восьми имеющихся наборов, этому принципу **не удовлетворяют** —
их предстоит заменить на фиксированные универсальные (13G). Проверено: все
оптимумы 13A и 13B лежат внутри фиксированных симметричных спанов 13A
(σ_g ±2.7, σ_a ±3.0, σ_bg/σ_ba ±2.2, σ_pos ±2.0, σ_h ±1.6, σ_v ±1.5,
σ_ang ±1.6), поэтому замена не должна стоить точности.

Итоговый план (принят 2026-10-11) — только тюнер, без изменений `core`:
- **13.0 Диагностика/baseline** (P0, S): аудит `eval.json` полных прогонов
  (профили J по σ, доля точек у стенок, неинформативные оси `bg`/`ba`); базовые
  числа `validate_presets.py` на 9 наборах + `run_hk` — точка отсчёта.
- **13A Целевая метрика = наземная истина** (P0, M): синтетика —
  `result.txt ↔ truth.txt`, `run_hk` — `reference.txt` (истины нет). Сейчас σ
  подгоняются под «копирование» бортового эталона — это первый реальный прирост.
- **13B Идентифицируемость/границы** (P0, M): неинформативные σ (`bg`/`ba`, при
  необходимости `g`/`a`) фиксировать на паспортных `params.json`; `σ_ref` из
  `noise_si` набора, асимметричные границы и штраф за близость к стенке.
- **13C Согласованность/робастность** (P1, M): член J по NEES/NIS
  (`metric.consistency_weight`); tail по окнам ~5 с + доля выбросов (устойчивость
  к артефакту `square_650`, 138 м).
- **13D Оптимизатор** (P1, M/L): бенчмарк Sobol→NM против multi-start NM / CMA-ES /
  Bayesian (Optuna) на фиксированном бюджете и SEED; warm-start, параллелизм по
  наборам; полная обратная совместимость конфигов и пресетов.
- **13E Агрегированный пресет** (P1, M): единый robust-пресет по 9 наборам +
  `run_hk` (min-max / медиана с ограничением худшего случая).
- **13G Информативность `σ_bg`/`σ_ba`, опора `σ_ref` и универсальные интервалы**
  (P1, M, отдельный этап): вынести из «отложенной» части 13B.
  **Задать интервалы как фиксированные константы** (симметричные спаны 13A),
  одинаковые для любых наборов, не из разброса оптимумов имеющихся наборов, без

Порядок: 13.0 → 13A → 13B → 13C → 13G → 13D/13E (13D независим; 13G желателен

Риск для бит-паритета и алгоритмов — отдельный контроль, если tuning упрётся.

Критерий приёмки этапа: для фиксированного набора тот же или лучший J_valid при
уменьшенном времени, ни одна из осей не в упоре на неинформативной стенке,

либо обоснованно зафиксированы на `params.json`; `σ_ref` взят из `noise_si`;
интервалы — фиксированные константы (не из разброса оптимумов имеющихся наборов);
без потери точности vs 13A/13B (ни одна ось не упирается в стенку; `J_valid` не

стенок 0/64 ✓, `σ_ref` оставлен глобальным (перенос на `noise_si` отложен —

### Этап 13H — Полный подбор всех коэффициентов точности БИНС/СНС (L, планируется)

Введён 2026-10-13. Руководящая директива: смещения ИМУ неизвестны «никоим
образом», паспортные значения в ядре — заглушки «чтобы что-то работало»,
поэтому фиксировать/доверять им нельзя; **подбирать все** коэффициенты точности.
Это переформулирует 13G: фиксация `σ_bg`/`σ_ba` по паспорту отменяется (у
большинства наборов RW смещений = 0, паспортная фиксация даёт `log10(0)`).

Реестр подбираемых величин (28 осей):

| Группа | Ключи | Где | Роль |
|---|---|---|---|
| Q-процесс | `sigma_g`, `sigma_a`, `sigma_bg`, `sigma_ba` | params.ini | шум в предсказании |
| R-измерения | `sigma_pos`, `sigma_h`, `sigma_v`, `sigma_hdg` | params.ini | шум СНС |
| P0 | `p0_pos`, `p0_alt`, `p0_vel`, `p0_pitch`, `p0_roll`, `p0_heading`, `p0_ba`, `p0_bg` | **hardcode** `aligner.h:47-85` | нач. неопределённость |
| Tilt-политика | `gyro_off_rad_s`, `settle_s`, `brake_body_accel`, `tau_fast_s`, `tau_slow_s`, `fast_err_rad`, `level_acc_rad`, `bias_gain`, `bias_max_rad_s`, `divergence_deadband_rad` | params.ini | гейтинг/трим на манёврах |
| Запуск | `align_time_override_s`, `align_fallback_s` | params.ini | длительность выставки |

`outage_*` — сценарный тест, в точность не входит.

Принципы (почему нельзя «просто бросить 28 σ в оптимизатор»):
- **Идентифицируемость**: слабые оси (P0, `sigma_ba`, часть `tilt/*`) по J не
  различимы — оптимизатор гуляет по плоскому плато. Сначала скрининг, потом подбор.
- **Сцепки/конфаунды**: сейчас сцеплены `σ_bg`↔P0-курс, `σ_pos`↔P0-поз,
  `σ_h`↔P0-выс — развязать (вынести P0).
- **Масштабная инвариантность**: фильтр почти инвариантен к общему масштабу Q и R
  → в пространстве есть «плоское» направление. Лог-нормировка + регуляризация.
- **Робастность**: пресет хорош агрегированно, а не на одном наборе.

Пространство и объектив:
- `u = log10(θ/θ_ref)`, `θ_ref` — универсальные константы (не паспорта),
  интервалы — фиксированные симметричные спаны, общие для любых наборов
  (принцип универсальности 2026-10-12).
- `J_s` — текущий v3 (P95pos/TOL + tie·Mean + tail·P99.9/TOL + reg);
  агрегат `J_agg = mean_s J_s + λ·max_s J_s` (λ≈0.3) либо жёсткий min-max.
- Регуляризация: `reg = λ_u·Σu²` + запрет «копии СНС» (σ_pos,h,v → очень малым).

Этапы:
- **13H.0 Инструментарий** (M): вынести P0 в `KalmanConfig`/InitCov (ключи
  `init/p0_*`, дефолты = текущим → бит-паритет), привязки в
  `filter_settings.cpp`, использование в `aligner.h`, таблица GUI; обобщить
  реестр тюнера на произвольные ключи; `scan_13g.py` → `scan_sensitivity.py`.
- **13H.1 Скрининг** (M): для каждой из 28 осей — координатный профиль J на
  2–3 реперных наборах; классификация сильная/слабая/сцепленная (кривизна +
  попарный скан); таблица «оставить/зафиксировать/развязать/убрать».
- **13H.2 Понижение размерности** (S): зафиксировать слабые по обоснованию,
  развязать P0 → ожидаемо ~10–14 свободных осей.
- **13H.3 Глобальный поиск** (L): Sobol (n≈256–512) по свободным осям,
  мультинаборный `J_agg`; бенчмарк CMA-ES/Optuna-TPE (сливается с 13D);
  warm-start от текущих пресетов.
- **13H.4 Полировка и робастная агрегация** (M): NM мульти-старт +
  basinhopping; B5-сетка; E1b-центроид; робастный пресет по 9 наборам + run_hk;
  контроль стенок.
- **13H.5 Верификация/приёмка** (S): против baseline по всем наборам
  (J, P95/P99/MAX pos/vel/hdg, доля выбросов); ни одна ось не у стенки;
  бит-паритет консоли; `ctest` 15/15; cross-check по истине.
- **13H.6 Автоматизация** (S): конвейер `gen_configs → scan → run → aggregate →
  report` (`full_runs/_13H_*.md`), фиксированные SEED/бюджеты.

Стоимость: 1 прогон ≈ 2.5–4.5 с; мультинаборный eval (9×) ≈ 30 с; d≈14,
512 Sobol × 30 с / 8 воркеров ≈ 32 мин + полировка ~1–2 ч (ночной прогон).

Риски: слабые оси раздувают поиск (митиг. — фиксация по профилю); сцепки →
ложные оптимумы (развязка P0); «копия СНС» (запрет интервалов + tail); переобучение
(train/valid + мультинаборный агрегат); правки ядра ломают паритет (опциональные
ключи, дефолты = текущим); дорого (понижение размерности + detached-параллель).

Порядок: `13G (минимальный, тюнер-only)` → `13H.0` → `13H.1–13H.2` →
`13H.3–13H.4` → `13H.5–13H.6`.

Критерий приёмки: `J_agg` не хуже baseline, ни одна ось не у стенки, бит-паритет
консоли и GUI-вкладки сохранены.

#### 13H: чем лучше и чем хуже текущего алгоритма

Текущий алгоритм (13A/13B/13C): один конвейер Sobol-64 → NM-80 →
B5-сетка 32 → центроид плато, метрика v3 по наземной истине, **8 свободных σ**
(Q/R), P0 захардкожена и сцеплена с σ, `tilt/*` и выставка не подбираются,
`σ_ref` — глобальный шаблон, интервалы 13B выведены из имеющихся наборов.

Лучше:
- **Охват**: впервые подбирается P0 и политика трима (`tilt/*`), а не только 8 σ —
  на манёвровых наборах (`high_dynamics`, `square_harsh`) это реальный резерв,
  который текущий алгоритм физически не может использовать.
- **Развязка конфаундов**: вынос P0 устраняет двойную роль `σ_bg`↔курс,
  `σ_pos`↔P0-поз, `σ_h`↔P0-выс — сейчас профиль J по σ_bg искажён вкладом P0-курса.
- **Дисциплина идентифицируемости**: скрининг до оптимизации + понижение
  размерности вместо слепого поиска по 28 осям; меньше ложных оптимумов.
- **Робастность**: явный мультинаборный агрегат (`mean+λ·max`) вместо пресета
  под каждый набор; устойчивее к переобучению на один датасет.
- **Универсальность**: фиксированные интервалы/`θ_ref` для будущих наборов,
  тогда как границы 13B привязаны к разбросу имеющихся оптимумов.

Хуже:
- **Стоимость и сложность**: правки `core` (P0/tilt-ключи) + GUI + тюнер;
  риск для бит-паритета (митигируется опциональными ключами с текущими дефолтами).
- **Больше осей → больше оценок**: при d≈14 глобальный поиск дороже, чем 8-осевой;
  без скрининга задача становится нереалистичной.
- **Риск недообучаемости слабых осей**: если P0 действительно вымывается за окно
  метрики (`skip_first_s`≈130 с), лишние оси — балласт; выигрыш может оказаться
  близок к 13G (только 8 σ + универсальные интервалы).
- **Провал универсальности**: часть коэффициентов может оказаться набор-зависимой —
  тогда единый робастный пресет проиграет набор-специфичному.

Вывод: 13H даёт максимальный потолок точности (за счёт P0/tilt и развязки), но
дороже и рискованнее 13G; при слабой идентифицируемости P0 эффект сводится к
версии 13G. Разумный путь — минимальный 13G (только тюнер) как быстрый выигрыш,
затем 13H.0–13H.1 как проверка гипотезы о полезности P0/tilt, и только при
подтверждении — полный 13H.
