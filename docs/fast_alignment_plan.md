# План: выставка 1 секунда усреднения + начальные x0/P0 по окну

Документ описывает переход NoQT-версии от «выставки по длинному окну покоя»
(120 с и более, как в текущем `Aligner.cpp`) к короткому окну усреднения
**1 секунда** с честной оценкой начальных неопределённостей (x0 и P0) по данным
самого окна.

Ключевая идея: выставка — это не «120 секунд накопления», а работа систем в
режиме покоя. Формально выставка = 1 секунда усреднения, по которой оцениваются
**максимальные отклонения от среднего** (шум) и **смещения** (bias) для
начальных `x0`/`P0` фильтра Калмана. Остальное время стоянки (например,
119 с в наборе `square_650`) работает уже фильтр Калмана.

Схема шумов: за окно по каждому каналу накапливаются среднее и максимум
отклонения `Δ = max|x(t) − mean|`; из `Δ` по коэффициенту `k(N) = E[max|N(0,1)|]`
получается СКО отсчёта, а делением на `√N` — СКО среднего (§3.2). Масштаб `σ`
в `P₀` выбирается по источнику номинала: последний отсчёт СНС → СКО отсчёта,
среднее окна → СКО среднего (§4.4). Начальные ошибки `x₀` несут знаковые
оценки: «последний отсчёт − среднее» по каналам СНС и оценку смещения гиро
`bg_est` (§4.3).

## 1. Согласованные решения

| Вопрос | Решение |
|---|---|
| Границы окна выставки | **от начала файла до `T_align`**: файлы всегда читаются с начала, перемотки нет |
| Длина окна выставки | **1 с**; задаётся 4-й строкой `StartupNav.ini` (время выставки) |
| Что делает 4-я строка `StartupNav.ini` | конец окна усреднения = момент включения фильтра (прежде — «время выставки» в том же смысле) |
| Старт фильтра | сразу после усреднения, t = T_align (≈1 с); первая секунда не интегрируется — она усредняется |
| Перемотка потоков ИМУ/СНС | **нет** — окно читается из того же потока, что и цикл, с начала файла |
| Паритет с Qt-версией | ломается сознательно; расхождение фиксируется в `docs/noqt_deviations.md` |
| Курс при отсутствии `angle.dat` | gyro-compassing с честным P0 = `cfg.sig_bg / Ω_h` ≈ 0.215 рад + WARNING |
| Применение x0 | x0 остаётся в векторе состояния; применяется штатными инъекциями |
| Горизонтальный ba | паспортный P0 = 5 мг; разделение угла и ba доучит фильтр на стоянке |
| Оценка шумов | по **максимуму отклонения от среднего** в окне: `σ̂_отсчёта = Δ/k(N)`, `σ̂_среднего = σ̂_отсчёта/√N`, `k(N) = E[max|N(0,1)|]` (§3.2) |
| Номинал СНС | **последний отсчёт окна**: позиция, высота, скорости, курс |
| Начальные ошибки `x₀` | `x₀[0..6]` = «последний отсчёт − среднее окна» (СНС); `x₀[12..14]` = `bg_est`; остальное — 0 (§4.3) |
| Floors на σ | `σ_наклон ≥ 2·σ_ba_гор/g`, `σ_ba_верт ≥ σ_ba_паспорт/10`, `σ_bg_гор ≥ σ_bg_паспорт/5` |
| Гейт покоя | провал → WARNING + консервативная P0 (паспорт), `bg_est` не применяется |
| Гейт R4 (годность gyro-compassing) | переводится в диагностику: в окне 1 с он всегда «провалится» из-за шума среднего |
| Формат `result/reference/errors` | не меняется |
| Аналитика `bias_log`/`bias_report` | остаётся в коде, включается флагами |
| `sigma_v` в `params.ini` | не меняется |

Что решено «по умолчанию» (без отдельного согласования):

- окно усреднения — отрезок файла от его начала до `T_align` (значение берётся
  из `StartupNav.ini`); при отсутствии файла — `ALIGN_FALLBACK_S = 1.0`
  (fallback точки старта — по первому отсчёту СНС — сохраняется);
- первый кадр коррекции — по **последнему** отсчёту СНС, прочитанному в окне;
- новая диагностика пишется отдельным файлом `tools/init.txt`;
- формат `errors.txt` (`time` + `x0..x14`) не меняется.

### Почему отдельный модуль `averaging`, а не доработка `Aligner.cpp`

Старая выставка в этом репозитории — `nav::alignFromImuProvider`
(`src/navigation/Aligner.cpp:67`, плюс обёртка `alignFromFileData`): она
действительно усредняет ИМУ — блоки `BUF_rot = 3000` отсчётов, `FastMedian` +
`EMA_Filter`, в конце курс по gyro-compassing, тангаж/крен по средним
ускорениям, `ba` из наклона. Но её контракт не покрывает то, что нужно новой
схеме:

| Что нужно для 1-секундной выставки | Есть в `alignFromImuProvider`? |
|---|---|
| окно от начала файла до `T_align` | нет: читает поток **с начала файла** до `iter` и сам его потребляет (по смыслу совпадает, но это не реализуемо без «отматывания» назад) |
| среднее и **максимальное отклонение** по каждому каналу ИМУ | нет: наружу отдаются только сглаженные средние |
| σ̂ отсчёта/среднего по длине окна `N` | нет |
| статистика СНС: номинал (последний отсчёт), среднее окна, σ, круговое среднее курса | нет: СНС не читает вообще |
| `bg_est`, гейт покоя, причина отказа | нет (`bg` не оценивается, есть только `omega_h_horiz` для R4) |
| блочная фильтрация под окно 1 с | блок 3000 отсчётов ≈ 15 с при 200 Гц, т.е. на 1 с блоки и EMA вырождаются в одно окно |

Поэтому усреднение вынесено в Qt-независимый `src/navigation/averaging.{h,cpp}`
(окно, средние/максимумы/σ, круговое среднее курса, `ba`/`bg`, гейт,
`rest_reason`), а `Aligner.cpp` оставлен без изменений — как эталон старого
поведения и как источник `initialCovariance`/`initialAlignment` (паспортный
fallback при провале гейта).

## 3. Новый модуль `src/navigation/averaging.{h,cpp}`

Ответственность модуля — один проход по окну выставки и выдача всех величин,
необходимых для инициализации фильтра.

Границы окна: **от начала файла до `T_align`** (4-я строка `StartupNav.ini`).
Файлы читаются с начала, перемотки нет; в окно попадает всё, что прочитано до
`T_align` включительно. При `T_align = 1.0` это первая секунда набора.

### 3.1 Что считаем

| Величина | Как | Обозначение |
|---|---|---|
| Средняя удельная сила | среднее по отсчётам окна в СК тела | `f̄` |
| Средняя угловая скорость | среднее по отсчётам окна в СК тела | `ω̄` |
| Максимум отклонения акселя | `max |a(t) − ā|` по каждой оси окна | `Δa` |
| Максимум отклонения гиро | `max |ω(t) − ω̄|` по каждой оси окна | `Δω` |
| Шум среднего акселя | `σ̂_отсчёта(Δa)/√N`, см. 3.2 | `σ_ā` |
| Шум среднего гиро | `σ̂_отсчёта(Δω)/√N`, см. 3.2 | `σ_ω̄` |
| Тангаж, крен | из `f̄`: `θ = asin(f̄_X/g)`, `φ = atan2(−f̄_Z, f̄_Y)` | |
| Последний отсчёт СНС | позиция, высота, скорости окна | `p_посл` |
| Разброс СНС | `max |x(t) − x̄|` по каналам позиции, высоты, скорости | `Δp`, `Δh`, `Δv` |
| Курс (номинал) | последний отсчёт курса в окне; иначе gyro-compassing | `ψ` |
| Круговое среднее курсов | оценка «истины» для ошибки номинала курса | `ψ̄_круг` |
| Разброс курса | `max |normalize(ψ(t) − ψ̄_круг)|` | `Δψ` |
| Смещение акселя | `ba = f̄ − Cᵀ·[0, g, 0]` | `ba` |
| Смещение гиро | `bg = ω̄ − navToBody(C, ω_Земли)` | `bg` |
| Гейт покоя | три проверки, см. 3.4 | |

### 3.2 Шум по максимуму отклонения от среднего

В окне по каждому каналу накапливаются две величины: среднее `mean` и
**максимум отклонения** `Δ = max |x(t) − mean|`. `Δ` — робастная (не требующая
нормальности) мера разброса отсчётов: она не «размазывает» выброс, а, наоборот,
показывает его величину.

Из `Δ` СКО получается через коэффициент `k(N) = E[max|N(0,1)|]` — математическое
ожидание максимума модуля `N` стандартных нормальных (численно, Монте-Карло на
4·10⁵ выборок):

| N | 5 | 9 | 20 | 50 | 100 | 201 | 500 |
|---|---|---|---|---|---|---|---|
| `k(N)` | 1.57 | 1.84 | 2.17 | 2.51 | 2.75 | 2.97 | 3.24 |

```
σ̂_отсчёта  = Δ / k(N)              — СКО одного отсчёта
σ̂_среднего = σ̂_отсчёта / √N        — СКО среднего по окну
```

Какая из двух величин идёт в `P₀`, определяется тем, **откуда взят номинал**:

| номинал взят из | ошибка номинала | σ в `P₀` |
|---|---|---|
| **последнего отсчёта** СНС | ошибка конкретного отсчёта | `σ̂_отсчёта` |
| **среднего** окна (наклон, `ba`, `bg`) | ошибка среднего | `σ̂_среднего` |

Правило обязательное: `σ` в `P₀` должен соответствовать источнику номинала.
Иначе, например, `P₀(bg) = (1321 °/ч)²` (сырой максимум) вместо
`(31 °/ч)²` — фильтр не выучил бы смещение гиро за прогон (время обучения
`P₀/Q_bg` ≈ 3300 с при `Q_bg` из run_hk).

Полы (паспорт/конфиг) обязательны в любом случае: в наборе `square_noisefree`
все максимумы ровно нулевые, без полов получилось бы `P₀ = 0` → `K = 0` →
фильтр не работает вообще.

**Реализация.** Максимум отклонения от *итогового* среднего требует двух
проходов, поэтому окно буферизуется: 1 с × 200 Гц × 6 каналов ≈ 10 КБ. Второй
проход по буферу даёт точные `Δ` и круговое среднее курса.

**Проверка на данных** (`square_650`, окно 1 с: 201 отсчёт ИМУ, 9 СНС, 9 углов):

| канал | `Δ` (максимум) | `σ̂_отсчёта` | истинная σ отсчёта | `σ̂_среднего` | истинная σ среднего |
|---|---|---|---|---|---|
| `ω_x` | 1321 °/ч | 445 °/ч | 371 | 31 °/ч | 26 |
| `ω_z` | 1105 °/ч | 372 °/ч | 350 | 26 °/ч | 25 |
| `a_x` | 11.46 мг | 3.86 мг | 4.57 | 0.27 мг | 0.32 |
| `a_y` | 12.70 мг | 4.28 мг | 4.47 | 0.30 мг | 0.32 |
| lat | 2.05 м | 1.12 м | 1.28 | 0.37 м | 0.43 |
| alt | 3.74 м | 2.04 м | 2.10 | 0.68 м | 0.71 |
| `v_h` | 0.074 м/с | 0.040 м/с | 0.055 | — | — |
| курс | 0.311° | 0.169° | 0.204 | 0.056° | 0.068 |

Схема воспроизводит истинные шумы отсчётов и среднего с точностью 10–20 %,
не требуя предположения о нормальности отсчётов.

### 3.3 Смещения

**Акселерометр.** В покое `f_б = C_б^нᵀ·[0, g, 0] + ba`, поэтому
`ba = f̄ − Cᵀ·[0, g, 0]`.

- Вертикальная составляющая (`ba_Y`, ось Y тела — «вверх») наблюдаема:
  `σ(ba_Y) = σ_ā` (шум среднего).
- Горизонтальная составляющая **структурно неразделима** от наклона, если
  наклон получен из того же акселерометра: `θ_ном = θ_ист + ba_X/g`,
  `φ_ном = φ_ист − ba_Z/g`. Поэтому в номинал горизонтальный ba не попадает,
  а его неопределённость задаётся паспортом (5 мг).

**Гироскоп.** На стоянке гироскоп измеряет относительную скорость
`ω_изм_б = C_б^нᵀ·ω_Земли_н + bg`, где
`ω_Земли_н = [U_EARTH·cos φ, U_EARTH·sin φ, 0]`
(`navAngularRate` при V = 0). Отсюда

```
bg = ω̄ − navToBody(C, ω_Земли_н)
```

Оценка осмысленна только при известном курсе (курс из СНС): при
 gyro-compassing курс неизвестен и оценка вырождается. Ошибка оценки
определяется шумом среднего гиро: `σ(bg) ≈ σ_ω̄` (утечками через ошибки курса и
наклона можно пренебречь: `Ω_h·δψ ≈ 5·10⁻⁸ рад/с`).

Оценка вертикального канала гиро (`bg_Y`, ось «вверх») наименее точная:
сигнал — вертикальная составляющая вращения Земли `U_EARTH·sin φ ≈ 11 °/ч`
против шума `σ_ω̄`, поэтому для вертикали P0 остаётся паспортным.

### 3.4 Гейт покоя

Окно усреднения имеет смысл только на стоянке. Проверки (по средним окна):

| Проверка | Порог | Смысл |
|---|---|---|
| `|v̄_СНС| ≤ 4·σ̂_v̄·√3` | 0.11 м/с на `square_650`, 1.54 м/с на `square_harsh` | платформа не движется |
| `|ω̄ − Cᵀ·ω_Земли| ≤ 1e-2 + 4·σ̂_ω̄` | 0.0039 рад/с (≈ 800 °/ч) на `square_650`, 0.0138 на `square_harsh` | грубое вращение на окне отсутствует |
| `|f̄_Y − g| ≤ 10 мг` | 0.098 м/с² | вертикальная удельная сила в пределах нормы |

`σ̂_v̄` — СКО **среднего** скорости СНС из максимума отклонения окна
(`σ̂_отсчёта/√M`), но не ниже паспортного `cfg.sig_v/√M`. Паспортного
`cfg.sig_v` здесь недостаточно: у `square_harsh` фактический шум СНС 0.5 м/с
против паспортных 0.048 — по паспорту гейт **ложно** проваливался на стоянке.
То же с угловой скоростью: её оценка из окна 1 с шумнее паспортного смещения
(`σ_ω̄` = 31 °/ч на `square_650` и 119 °/ч на `square_harsh` против 103 °/ч
паспорта, а у `run_hk` измеренный `|bg| ≈ 590 °/ч`). Порог поэтому составной —
запас на смещение (с уровнем шумного МЕМС) плюс 4σ̂ оценки.

Признак покоя по горизонтальной удельной силе **не используется**: она включает
в себя наклон и сама по себе не говорит о неподвижности.

Провал гейта — не ошибка, а предупреждение: печатается WARNING, P0
подставляется консервативная (паспортная), `bg_est` не применяется, прогон
продолжается. Замеренные значения, пороги и причины провала пишутся в
`tools/init.txt`.

**Ограничение принципиальное:** за окно 1 с постоянное вращение и постоянное
смещение гироскопа неразличимы (на этом же и держится гирокомпасирование),
поэтому порог по ω — это именно защита от **грубого** вращения (>~1 °/с), а не
измерение смещения. Медленный поворот (доли градуса в секунду) гейт пропустит:
его вклад в ошибку уровня за 1 с меньше флора `P₀` (0.573°).

### 3.5 Lookahead

Текущая выставка (`Aligner.cpp:157`) читает отсчёты ИМУ до первого `t > окна`
и этот отсчёт **теряет** — для окна в 120 с это несущественно, для окна в 1 с
теряется первый такт основного цикла. Новая функция возвращает «лишний»
отсчёт вызывающему коду, который кладёт его обратно в поток.

## 4. Начальные x0 и P0

### 4.1 Соглашение о знаках (не меняется)

| Компонента | Смысл | Инъекция |
|---|---|---|
| `x[0..2]` | `номинал − истина` (широта, долгота, высота) | `lat −= x[0]` и т. д. |
| `x[3..5]` | `номинал − истина` (скорости) | `V −= x[3]` и т. д. |
| `x[6..8]` | `номинал − истина` (курс, тангаж, крен) | `att −= x[6..8]` |
| `x[9..11]` | `истина − номинал` (смещение акселя) | `ba += x[9..11]` |
| `x[12..14]` | `истина − номинал` (смещение гиро) | `bg += x[12..14]` |

Инъекции выполняют `applyTiltKalmanCorrections` (аксель-апдейт, 200 Гц) и
`applyKalmanCorrections` (кадр СНС, 10 Гц) — готовые механизмы, новый код для
применения x0 не нужен.

### 4.2 Номинал после окна

Номинал — лучшая доступная оценка состояния на момент `t = T_align`
(окончание окна). Всё, что усреднение улучшает, кладётся в номинал; P0
описывает остаточную неопределённость.

| Состояние | Значение | Источник |
|---|---|---|
| Широта, долгота, высота | координаты СНС | **последний** отсчёт СНС окна (состояние относится к `t = T_align`) |
| Скорости | `v_n`, `v_h`, `v_e` последнего отсчёта СНС | **последний** отсчёт СНС окна |
| Тангаж, крен | из `f̄` | окно усреднения (акселерометр — «горизонт») |
| Курс | последний отсчёт курса в окне | `angle.dat`; иначе gyro-compassing |
| `ba` | `f̄ − Cᵀ·[0,g,0]` | окно усреднения |
| `bg` | **0** | оценка переносится в `x0` — см. 4.3 |

Выбор «последний отсчёт» для каналов СНС сознательный: это состояние системы
именно на момент `t = T_align` (оно и есть в моменте окончания окна), а его
ошибка **наблюдаема** — отклонение последнего отсчёта от среднего по окну
(§4.3). Круговое среднее дало бы ошибку в √M раз меньше, но не дало бы
знаковой оценки этой ошибки: осталось бы только «неопределённость в `P₀`».

### 4.3 Вектор x0

В `x₀` попадают только **знаковые** оценки ошибки номинала — то, что в окне
действительно измерено:

1. **Каналы СНС.** Номинал — последний отсчёт окна. На стоянке истинные
   позиция и скорости постоянны, поэтому лучшая доступная оценка истины —
   среднее по окну, а отклонение последнего отсчёта от среднего и есть
   (с точностью до ошибки среднего) ошибка номинала. Знак известен — это и
   есть начальная ошибка.
2. **Смещение гиро.** `bg_est = ω̄ − navToBody(C, ω_Земли)` — оценка с
   известным знаком. В номинал она не кладётся: её шум (`σ_ω̄ ≈ 31 °/ч`)
   сравним с самой величиной смещения (на `square_650` истинное
   `bg = [20, −15, 10] °/ч`), и запечь такую оценку в номинал — значит заранее
   ошибиться. Вектор ошибок с честной `P₀` позволяет фильтру взять оценку и
   при этом оставить право её уточнить.

| Компонента | Значение | Комментарий |
|---|---|---|
| `x0[0..2]` | `последний СНС − среднее СНС` | широта/долгота (рад), высота (м); на `square_650`: lat −1.80 м, alt +2.55 м |
| `x0[3..5]` | `последний − среднее` по скоростям | на `square_650`: `v_h` −0.073 м/с |
| `x0[6]` | `normalize(ψ_посл − ψ̄_круг)` | на `square_650`: −0.009° |
| `x0[7..8]` | 0 | наклон из `f̄`; систематическая часть его ошибки (`ba_гор/g`) **неизвестна** — горизонтальный ba в покое не наблюдаем → описывается полом в `P₀` и корреляцией `P[7][9]`, `P[8][11]` |
| `x0[9..11]` | 0 | `ba` уже в номинале; горизонтальная часть оценки ≈ 0 по построению (уровень по `f̄` «съедает» горизонтальное смещение) |
| `x0[12..14]` | `bg_est` | **новое**: применяется первым аксель-апдейтом (`applyTiltKalmanCorrections`: `st.bg += x[12+k]`) |

Знаки: `x[0..8] = номинал − истина` ⇒ `x0[0..6] = номинал − истина ≈
последний − среднее` ✓; `x[12..14] = истина − номинал`, номинал `bg = 0` ⇒
`x0[12..14] = bg_est` ✓.

Аксель-апдейт не имеет в `H_accel` колонок смещения гиро, поэтому
`x0[12..14]` не меняется при коррекции — только инъецируется в номинал и
обнуляется.

### 4.4 Новая P0

Обозначения: `g` — нормальное ускорение (Клеро), `sig_pos`, `sig_h`, `sig_v`,
`sig_hdg` — из `ins::kalman_cfg`; `σ_ā`, `σ_ω̄` — шумы средних, посчитанные по
максимумам отклонения (§3.2); `Δp`, `Δh`, `Δv`, `Δψ` — разбросы каналов СНС в
окне; `N` — число отсчётов ИМУ в окне, `M` — число отсчётов СНС в окне;
`σ_ba_гор = 5 мг = 4.905e-2 м/с²` — паспорт (`aligner.h:54`);
`σ_ba_паспорт = σ_ba_гор`; `σ_bg_паспорт = 5.0e-4 рад/с = 103 °/ч`
(`aligner.h:55`); `R_Земли = 6378137 м`.

```
σ̂_отсчёта(Δ) = Δ / k(N)          σ̂_среднего = σ̂_отсчёта / √N

σ_pos_lat = max( σ̂_Δlat / R_Земли , sig_pos )                 [рад]
σ_pos_lon = max( σ̂_Δlon / (R_Земли·cos φ) , sig_pos/cos φ )   [рад]
σ_h       = max( Δalt , sig_h )                              [м]
σ_v       = max( max|Δv| , sig_v )                           [м/с]
σ_hdg     = max( Δψ , sig_hdg )                              [рад]
σ_наклон  = max( sqrt(σ_ba_гор² + σ_ā_гор²)/g , 2·σ_ba_гор/g )
σ_ba_верт = max( σ_ā_Y , σ_ba_паспорт/10 )
σ_bg_гор  = max( σ_ω̄_гор , σ_bg_паспорт/5 )
σ_bg_верт = σ_bg_паспорт

P[0][0] = σ_pos_lat²   P[1][1] = σ_pos_lon²   P[2][2] = σ_h²
P[3..5] = σ_v²                   P[6][6]   = σ_hdg²
P[7][7] = P[8][8] = σ_наклон²
P[9][9] = P[11][11] = σ_ba_гор²  P[10][10] = σ_ba_верт²
P[12][12] = P[14][14] = σ_bg_гор²  P[13][13] = σ_bg_верт²
P[7][9] = +σ_ba_гор²/g   P[9][7] = +σ_ba_гор²/g
P[8][11] = −σ_ba_гор²/g   P[11][8] = −σ_ba_гор²/g
```

Долгота нормируется на `cos φ` (как в `Rj_matrix`): в метрах ошибка по востоку
та же, что по северу, но в радианах долготы она в `1/cos φ` больше. Без
нормировки при `φ = 47.6°` (`cos φ = 0.674`) неопределённость по долготе
занижалась бы в 1.5 раза, и фильтр слишком доверял бы оценке долготы.

Индексы осей тела: `x[9..11]` = `ba` (X — вперёд, Y — вверх, Z — вправо),
`x[12..14]` = `bg` в том же порядке; вертикальный канал — средний (Y).

Floors — страховка от слишком оптимистичной P0, если окно попалось тихим
(в `square_noisefree` все максимумы нулевые → без полов `P₀ = 0` → `K = 0` →
фильтр не работает).

Числа по `square_650` (окно 1 с: `N` = 201 отсчёт ИМУ, `M` = 9 СНС):

| величина | из окна | паспорт / конфиг | итог |
|---|---|---|---|
| `σ_pos` | `Δlat` 2.05 м, `Δlon` 2.13 м → 1.16 м (lat), 1.72 м (lon/`cos φ`) | `sig_pos` 1.5 м | **1.5 м / 2.2 м** (пол) |
| `σ_h` | `Δalt` 3.74 м → 2.04 м | `sig_h` 5 м | **5 м** (пол) |
| `σ_v` | `Δv` max 0.074 м/с → 0.040 м/с | `sig_v` 0.048 м/с | **0.048 м/с** (пол) |
| `σ_hdg` | `Δψ` 0.311° → 0.169° | `sig_hdg` 0.0705° | **0.169°** |
| `σ_наклон` | `σ_ā_гор` 0.27 мг → 0.0155° | `2σ_ba_гор/g` 0.573° | **0.573°** (пол) |
| `σ_ba_верт` | `σ_ā_Y` 0.30 мг | `σ_ba/10` 0.51 мг | **0.51 мг** (пол) |
| `σ_bg_гор` | `σ_ω̄_гор` 31 °/ч | `σ_bg/5` 20.6 °/ч | **31 °/ч** |
| `σ_bg_верт` | — (оценка из 1 с недостоверна) | паспорт | **103 °/ч** |

Сверка с фактическими шумами эталона на `square_650`: ошибка последнего отсчёта
СНС ≈ 1.3 м (позиция), 2.1 м (высота), 0.055 м/с (скорость), 0.20° (курс) —
все внутри 2σ построенной `P₀`.

Обоснования:

- **Позиция/высота** — номинал взят из СНС, поэтому σ = разброс отсчётов
  эталона (`Δ`), а не прежнее паспортное `2σ_pos`; пол — по `sig_pos`/`sig_h`.
- **Скорость** — вместо прежних «2.5 м/с» (свободный масштаб) берётся разброс
  отсчётов СНС с полом `sig_v`: скорость на стоянке известна с точностью
  эталона.
- **Курс** — разброс курсов эталона в окне с полом `sig_hdg`.
- **Тангаж/крен** — ошибка наклона складывается из структурной (`ba_гор/g`)
  и шумовой (`σ_ā/g`) частей. Потолок точности наклона в покое:
  `2·σ_ba_гор/g = 0.573°` (при `σ_ba_гор` = 5 мг).
- **Смещения акселя** — вертикальное наблюдаемо (`σ_ā_Y`, с полом),
  горизонтальные паспортные (5 мг) — в покое они структурно неотделимы от
  наклона.
- **Смещения гиро** — горизонтальные каналы: по оценке из окна, с полом по
  паспорту; вертикальный канал: паспорт (оценка из 1 с недостоверна, см. 3.3).
- **Корреляции «наклон ↔ ba_гор»** — физические: выставка по акселю кладёт в
  тангаж и крен не истинный наклон, а сумму наклона и `ba_гор/g`, поэтому
  `x[7] = +ba_X/g`, `x[8] = −ba_Z/g`, откуда
  `P[7][9] = +σ_ba_гор²/g`, `P[8][11] = −σ_ba_гор²/g`.
  Коэффициент корреляции
  `ρ = P[7][9]/√(P[7][7]·P[9][9]) = σ_ba_гор/(g·σ_наклон)`: с полом ровно 0.5.

Положительная полуопределённость P0 проверяется собственными значениями
(PSD) — отдельная проверка этапа B.

## 5. Порядок фаз прогона

```
1. Разбор аргументов, params.ini.
2. StartupNav.ini → точка старта и T_align (окно). Нет файла → первый отсчёт СНС + T_align = 1.0.
3. ФАЗА УСРЕДНЕНИЯ: чтение ИМУ до t ≤ T_align и СНС до t ≤ T_align
   (окно буферизуется: 201 отсчёт ИМУ, 9 СНС, 9 углов).
   → f̄, ω̄, Δa, Δω, σ_ā, σ_ω̄, разбросы СНС Δp/Δh/Δv/Δψ, углы, курс,
     ba, bg_est, вердикт гейта → tools/init.txt.
4. ИНИЦИАЛИЗАЦИЯ: номинал (позиция — последний отсчёт СНС окна), новая P0, x0.
5. ОСНОВНОЙ ЦИКЛ: первый отсчёт ИМУ с t > T_align (dt первого такта = t − T_align,
   state.time_prev = T_align).
   Первая коррекция — по **первому кадру СНС за окном**; далее — обычный ход цикла.
6. ОТЧЁТ по смещениям (--bias-report), NIS (--consistency) — по флагам.
```

**Почему первая коррекция не по последнему отсчёту окна.** Последний отсчёт
окна уже израсходован как номинал (§4.2): его инновация тождественно нулевая,
а обновление только уменьшило бы `P` на `R`, ничего не измерив, — то есть
посчитало бы один и тот же отсчёт дважды. Поэтому последний отсчёт окна
служит лишь опорой (`hold_ref`) для сравнения времени кадров, а первая
коррекция выполняется по первому кадру за окном — независимым измерением.

Поток при этом не перематывается: «лишний» отсчёт ИМУ (первый с `t > T_align`)
возвращается в цикл (`pending_row`), а первый кадр СНС за окном становится
начальным `last_ref`. На такте `t ≈ T_align + 5 мс` новый кадр ещё не пришёл,
поэтому коррекция на нём не выполняется (`do_correction = false`) — первая
запись `errors.txt` появляется на времени первого кадра за окном.

Временная шкала: **прогон идёт с начала файла** — окно усреднения
`t ∈ [начало файла, T_align]` (обычно `[0, 1]`) его первая фаза, а не «прогрев
до старта». Фильтр Калмана включается на `t = T_align` и идёт до конца файла;
на всём оставшемся пути работает обычный цикл коррекций СНС/аксель-апдейта.
Время в `result/reference/errors.txt` и в `bias.txt` отсчитывается от нуля
набора, как и раньше: первые записи появляются с `t ≈ T_align` (для окна 1 с —
≈ 1 с), потому что до этого фильтр не пишет (усредняет).

Формулировка «прогон стартует с 1 с» неверна: стартует с 1 с **фильтр**, а
прогон включает и окно усреднения.

## 8. Риски и ограничения

1. **Ухудшение шумов начальных оценок.** Окно 1 с против 120 с: `σ_ω̄`
   2.1 → 31 °/ч, `σ_наклон` (шумовая часть) 0.0016° → 0.0155° (пол 0.573°).
   Это цена решения: выставка формально 1 с, остальное делает фильтр.
2. **Масштаб максимума отклонения.** `Δ` — это примерно `k(N)·σ_отсчёта`
   (k(201) ≈ 2.97), а не `σ_отсчёта` и уж точно не `σ_среднего`
   (`Δ/√N` занизил бы σ примерно в 3 раза, а «как есть» завысил бы в 42 раза
   для каналов ИМУ). Коэффициент `k(N)` зависит от числа отсчётов, поэтому
   берётся из таблицы §3.2, а не «3» для всех каналов.
3. **Потолок точности наклона.** Горизонтальный ba структурно неразделим от
   наклона в покое, поэтому `σ_наклон ≥ 2·σ_ba_гор/g = 0.573°` (при
   `σ_ba_гор` = 5 мг). Разделение появляется, только когда есть независимый
   источник наклона (СНС) или манёвры.
4. **`bg_est` из 1 с шумнее самой оценки.** На `square_650` шум `σ_ω̄ ≈ 31 °/ч`
   против истинных `bg = [20, −15, 10] °/ч`: применение оценки может ухудшить
   стартовую RMS-ошибку. Поэтому: применять только при пройденном гейте,
   `P₀(bg)` — по полу (паспорт/5), в `init.txt` писать и оценку, и её σ.
5. **Нулевые максимумы.** В наборе `square_noisefree` все максимумы равны нулю
   (идеально чистые данные) → без паспортных полов `P₀ = 0` → `K = 0` →
   фильтр не работает. Полы обязательны не «для красоты», а по существу.
6. **Согласованность P0 и реальной ошибки.** Слишком тугая P0 «зажимает»
   ошибку (фильтр не сможет её убрать), слишком свободная — затягивает
   сходимость. Отсюда floors на σ и проверка «стартовая ошибка vs 2σ(P0)».
7. **Временная шкала отчётов.** Окна отчёта по смещениям (1/10/30 с) теперь
   отсчитываются от `t ≈ 1 с`; это ожидаемо, метрики сравниваются в пределах
   одной версии.
