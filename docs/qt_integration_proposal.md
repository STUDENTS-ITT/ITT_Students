# План внедрения Qt 6.12.0 в проект ITT_Students

Документ описывает, какие возможности Qt 6.12.0 имеет смысл использовать в этом
проекте (БИНС + СНС комплексирование, error-state KF, консольное приложение
`imitator` + Python-скрипт `plot_trajectory.py` для сравнения траекторий).

---

## 0. Границы применимости

- Распространение бинарника не планируется, поэтому GPLv3-модули
  (`QtCharts`, `QtGraphs`, `QtQuick 3D`, `QtDataVisualization`) юридически
  допустимы.
- Тем не менее ниже предлагается **набор только из LGPL-модулей**
  (`QtCore`, `QtGui`, `QtWidgets`, `QtConcurrent`, `QtSql`, `QtSerialPort`,
  `QtNetwork`, `QtTest`) и собственный рендер графиков на `QPainter`.
  Причина прагматическая: `QtCharts` тянет за собой QML/QtQuick-стек,
  не даёт нужного контроля над агрегацией 10^5 точек, и его API меняется
  заметно чаще `QPainter`.
- **Ядро фильтра остаётся без Qt.** Новых внешних зависимостей, кроме
  стандартной библиотеки, не добавлять (это требование исходного AGENTS.md).

## 1. Архитектурное разделение

Проект разделяется на два слоя — это ключевое решение, без него Qt
«растечётся» по всей кодовой базе.

```text
ITT_Students_Qt_Version/
├── CMakeLists.txt              # корневой, собирает оба слоя
├── src/
│   ├── core/                   # Qt-независимое ядро -> статическая библиотека esfcore
│   │   ├── CMakeLists.txt
│   │   ├── ins/                # ins_filter.h, attitude_calc.h, imu_processor.h
│   │   ├── navigation/         # trajectory.h, position_calc.h, maneuver_tilt.h,
│   │   │                       # gps_processor.h, Aligner.cpp/.hpp
│   │   ├── math_lib/           # matrix_ops.h, transformations.h,
│   │   │                       # statistics.h, interpolation.h
│   │   ├── data_io/            # data_reader.*, data_writer.*
│   │   └── utils/              # constants.h, paths.h, types.h
│   ├── console/                # main.cpp консольного imitator
│   └── gui/                    # Qt-приложение imitator_gui
│       ├── CMakeLists.txt
│       ├── main.cpp
│       ├── MainWindow.{h,cpp}
│       ├── core_bridge/        # адаптеры: запуск ядра, чтение результатов
│       ├── workers/            # SimulationWorker
│       ├── views/plots/        # PlotView, TimeSeriesPlot, TrajectoryPlot
│       ├── models/             # QAbstractTableModel поверх result/errors
│       └── settings/           # работа с QSettings, редактор параметров
├── data/                       # входные данные (не переносить в src)
├── docs/
└── tools/                      # plot_trajectory.py остаётся как есть
```

Правило: **в `src/core` не должно быть ни одного `#include <Q...>`**.
Проверяется grep-ом в CI.

## 2. Что реализовать на Qt — по модулям

### 2.1 Qt Widgets — рабочее место оператора (главный выигрыш)

Тема сейчас уехала в три текстовых файла по 10 МБ, которые нужно
просматривать скриптом. GUI собирает это в одну панель.

- `QMainWindow` + `QDockWidget` — перемещаемые панели:
  - «Панель управления» — выбор каталога `data/raw`, кнопки Старт/Пауза/Стоп,
    ползунок скорости воспроизведения.
  - «Дерево входов» — `QTreeView` по `imu.dat` / `gps.dat` / `angle.dat` /
    `StartupNav.ini` с подсветкой отсутствующих файлов.
  - «Лог» — `QPlainTextEdit` в режиме только чтения с цветовой маркировкой
    уровней сообщений.
  - «Состояние фильтра» — текущие 15 компонент `x`, диагонали `P`,
    innovation `z`, номер такта, время.
- `QSplitter` — основная раскладка «данные | графики | лог».
- `QTableView` + `QSortFilterProxyModel` — табличное представление
  `result.txt` / `errors.txt` с сортировкой и фильтром по времени.
- `QFileDialog` / `QMessageBox` для выбора файлов и сообщений об ошибках
  вместо `printf` в консоли.

### 2.2 Qt Concurrent / QThread — отзывчивый UI

- `SimulationWorker` на `QObject`, переносимый в `QThread`
  (либо `QtConcurrent::run` + `QFutureWatcher`), выполняет цикл
  `nav::step()` по всем строкам `imu.dat`.
- Сигналы: `progress(int percent, double t)`, `sampleReady(const NavState&)`,
  `finished()`, `failed(QString)`.
- Передача состояния — через `QMetaObject::invokeMethod` с
  `Qt::QueuedConnection`, либо через потокобезопасный кольцевой буфер
  (`QMutex` + `std::vector`), чтобы не гонять 200 Гц сигналов в GUI.
- Для плавного отображения — пересчёт и перерисовка графиков не чаще
  20–30 раз в секунду, остальное отбрасывается.

### 2.3 QPainter — собственные графики вместо QtCharts

Набор нужных графиков определяется текущей отладкой:

| График | Данные | Зачем |
|---|---|---|
| Траектория БИНС vs СНС | `result.txt` + `reference.txt`, проекция на плоскость | То же, что сейчас делает `plot_trajectory.py` |
| Компоненты ошибок `x[0..14]` | `errors.txt`, 15 кривых на 3 графиках (поз./скор./углы) | Проверка сходимости ESKF |
| Диагонали `P[0..14]` | из `ins_filter.h` | Поведение ковариации, П1/П4 из `eskf_brief_report.md` |
| Инновация `z` (9 компонент) | из `correct` | Согласованность измерений |
| NIS / NEES | требует доступа к `P` и `x` | Формальная проверка фильтра |
| Широта/долгота/высота | `result.txt` | Геометрия маршрута |
| Скорости `Vn/Vh/Ve` | `result.txt` | Динамика |
| Roll/pitch/yaw | `result.txt`, при наличии — `angle.dat` | Сверка с эталоном углов |

Технические требования к `PlotView`:

- Оси, сетка, легенда, авто-масштабирование.
- Зум колесом мыши, панорамирование перетаскиванием, сброс по кнопке.
- Кэш отрисовки в `QPixmap`; при перерисовке без изменения области
  переиспользовать кэш.
- Агрегация: при密集ном сжатии (больше N пикселей на N точек) рисовать
  min/max-огибающую вместо всех точек — иначе 200 Гц × 600 с = 120 000 точек
  на каждый ряд тормозит отрисовку.
- Экспорт в PNG/SVG через `QPixmap::save` и `QSvgGenerator`.

### 2.4 Qt Sql — история прогонов

- `QSqlDatabase` (SQLite) для хранения результатов прогонов:
  таблицы `runs(id, name, created_at, config_json)`, `samples(run_id, ...)`,
  `filter_errors(run_id, ...)`.
- `QSqlTableModel` + `QSortFilterProxyModel` — просмотр и фильтрация.
- Сравнение двух прогонов (например, до/после изменения `Rj_matrix`)
  без повторного запуска Python.

### 2.5 QSettings — вынос параметров фильтра

Сейчас `Qj_matrix`, `Rj_matrix`, `P0`, пороги адаптации в
`maneuver_tilt.h` зашиты в заголовках. Разнести в `settings.ini`,
читать в core через `QSettings`-совместимый парсер или через простой
собственный INI-ридер (core без Qt).

Редактирование — в GUI: таблица «параметр / значение / единицы / диапазон».

### 2.6 QtTest — модульные тесты

Особенно ценно: тесты ловят тихие ошибки из раздела «Критичные конвенции»:
- `transpose_m(A, cols)` — второй аргумент это **число столбцов A**,
  ошибка компилируется без предупреждений и даёт мусор.
- `multiply_matrix(A, B, cols_A, cols_B)` — проверка совпадения
  внутренней размерности с `cols_A`.
- `predict` / `correct` / `correctTilt`: положительная полуопределённость `P`,
  симметрия, обнуление `x` после коррекции.
- `statistics.h` (Median/EMA) на известных входах.
- `transformations.h`: `bodyToNav`/`navToBody` — обратные друг другу.

Регистрация через `enable_testing()` + `add_test`, запуск `ctest`.

### 2.7 Qt SerialPort / Qt SerialBus — реальное железо (опционально)

- `IDataSource`-абстракция: файловый источник (текущий `data_reader`) и
  последовательный источник (`QSerialPort`).
- Это снимает ограничение «данные только из .dat» и позволяет
  подключить реальный ИМУ по COM/USB или CAN (`QtSerialBus`).

### 2.8 Qt Network — телеметрия и удалённый просмотр (опционально)

- `QWebSocketServer` — раздача текущего состояния и траектории в браузер,
  удобно смотреть графики на планшете.
- `QHttpServer` (Qt 6.8+) — REST для автоматизированных прогонов.

### 2.9 Qt PrintSupport / QPdfWriter — отчёт

- Экспорт результатов прогонов в PDF с таблицами и графиками (вместо
  скриншотов matplotlib).

## 3. Порядок внедрения (этапы)

1. **Разделение слоёв и CMake.** Вынести `src/core` → `esfcore`
   (STATIC), `src/console/main.cpp` → `imitator`. Проверить, что консольная
   версия собирается и даёт **бит-в-бит тот же** `result.txt`.
2. **Тесты на core.** `QtTest` для `matrix_ops.h`, `transformations.h`,
   `statistics.h` — до появления GUI, чтобы дальше работать с гарантией.
3. **Вынос параметров в конфиг.** `settings.ini` + собственный ридер в core
   (без Qt) + значения по умолчанию, совпадающие с текущими константами.
4. **`SimulationWorker` + QtSql.** Прогон ESKF в потоке, запись в SQLite,
   отображение прогресса. Qt Widgets минимальный: кнопки Старт/Стоп.
5. **`PlotView` на QPainter.** Сначала график компонент `x` и траектория
   БИНС/СНС. Далее — остальные.
6. **`MainWindow` целиком.** Док-панели, таблицы, лог, сравнение прогонов.
7. **Опционально:** SerialPort, WebSocket, PDF-отчёт.

Каждый этап оставляет рабочую консольную версию — регрессия проверяется
сравнением выходных файлов.

## 6. Риски и как их снимать

- **Утечка Qt в core.** Проверка grep-ом на `#include <Q` в `src/core`
  в CI-скрипте.
- **Дублирование вывода.** Пока core пишет `tools/*.txt`, GUI может читать
  те же файлы — это ок для первой версии, дублирование состояния убрать
  позже передачей `NavState` через сигналы.
- **Смешение единиц.** Внутри радианы, в GUI градусы. Конвертация — только
  на границе, одним местом (`RAD_TO_DEG`).
- **Тормоза на 120 000 точек.** Сразу ввести агрегацию и кэш в `PlotView`,
  иначе потом придётся переписывать.

## 7. Фактическое состояние реализации

Ниже — что уже сделано в `C:\ITT_Students_Qt_Version` и как это соотносится
с планом выше.

### 7.1 Слои и сборка

- `src/core/` — ядро без Qt, собирается как статическая библиотека `esfcore`
  (C++17, STL). Автоматическая проверка `core_has_no_qt` ищет `#include <Q`
  в `src/core` и падает при нарушении.
- `src/console/main.cpp` — консольная цель `imitator`.
- `src/gui/` — Qt-приложение `imitator_gui` (QtWidgets, графики на `QPainter`).
- Единая точка расчёта — `nav::runSimulation`; GUI получает данные через
  `StepTelemetry` (указатель может быть `nullptr` — тогда консольный путь
  считает ровно тот же объём, что и раньше).

**Паритет с исходной консольной версией** (`C:\ITT_Students`) проверен:
после пересборки обоих вариантов `result.txt`, `reference.txt` и `errors.txt`
совпадают по SHA-256. Сверять нужно, запуская оригинал из каталога, у которого
есть `../data/processed`, — иначе он молча прерывает выставку и считает от
нулевых углов (подробно в разделе 7.7.1).

### 7.2 Параметры фильтра

- `FilterSettings` + собственный INI-ридер в core (без `QSettings`);
  значения по умолчанию совпадают с прежними константами.
- Поддерживается legacy `params.ini` (тот же формат, что у старой версии).
- GUI: таблица «параметр / значение / единицы / диапазон», сохранение и
  загрузка `settings.ini`, сброс к умолчаниям.

### 7.3 Расчёт и наблюдение

- `SimulationWorker` (QThread), приём телеметрии через потокобезопасный буфер,
  перерисовка 25 Гц.
- Пауза и ползунок скорости воспроизведения; `RunPacer` живёт в core и
  тестируется в `test_simulation` (в том числе остановка на `requestStop`).
- База SQLite: `runs`, `samples`, `filter_errors`, `covariances`.

### 7.4 Графики (все на `QPainter`)

| Вкладка | Содержимое |
|---|---|
| Траектория | БИНС против СНС в метрах от точки старта |
| Координаты | Север/Восток (м) и высота |
| Углы | Курс, тангаж, крен |
| Скорости | Vn, Vh, Ve |
| Ошибки x | 15 компонент на кадрах коррекции СНС |
| Инновации | 9 компонент |
| Ковариация | 15 диагоналей `P` |
| Согласованность | NIS и NEES с линией ожидания (`dof = 9`) |

- Зум колесом относительно курсора, панорамирование перетаскиванием, сброс
  диапазона двойным щелчком и по меню; Ctrl — только ось X, Shift — только Y.
- Агрегация min/max по пиксельным колонкам: 200 Гц × 600 с рисуется огибающей.
  В GUI ряды дополнительно прореживаются до 2000 точек (`kMaxPlotPoints`).
- Экспорт: PNG/JPG, SVG (`QSvgGenerator`), PDF (`QPdfWriter`), CSV таблицы,
  лог в файл.
- Кэш кадра в `QPixmap` (пункт 2.3): ключ — размер виджета, версия содержимого
  и границы осей; `setCacheEnabled(false)` отключает кэш, курсор рисуется
  поверх кэша и в содержимое не входит. Инвалидируют кэш все методы, меняющие
  данные или оформление, в том числе `TrajectoryPlot`.
- Тесты: `tests/test_plots.cpp` (масштаб, зум, панорамирование, сброс,
  плотные ряды, SVG, курсор). Проверка времени отрисовки 15×120 000 точек
  намеренно сделана с большим запасом: она ловит патологическое замедление,
  а не абсолютную скорость машины.

### 7.5 Сравнение прогонов (план 2.4)

- Меню «Сравнение»: второй прогон выбирается из истории SQLite.
- Ряды второго прогона добавляются на те же графики пунктиром
  (координаты, углы, скорости, ошибки, инновации, ковариация, NIS/NEES).
- Опция «показывать разность» добавляет ряды «текущий − второй»; координаты
  приводятся к метрам от общей точки отсчёта, сопоставление отсчётов — по
  ближайшему времени.
- Проверяется в `--self-test`: после сохранения прогона он же назначается
  вторым и контролируется, что ряды добавились.

### 7.6 NIS / NEES

- `ins::correct` по указателю заполняет `CorrectionStats`:
  `NIS = innovᵀ·S⁻¹·innov`, `NEES = innovᵀ·P_meas⁻¹·innov`, `dof = KF_MEAS = 9`.
- Параметр необязательный: при `nullptr` лишних обращений матриц не будет,
  поэтому консольный вывод не меняется.

### 7.7 Тесты

`ctest --test-dir build` — 11 тестов: `core_has_no_qt`, `gui_smoke`,
`test_matrix_ops`, `test_transformations`, `test_statistics`, `test_ins_filter`,
`test_data_io`, `test_settings`, `test_simulation`, `test_plots`,
`test_pdf_report`.
`gui_smoke` запускает приложение в offscreen-режиме с полным прогоном
(200 Гц × 600 с), записью в SQLite, чтением прогона из истории, сравнением и
сборкой сводного PDF-отчёта (проверяется сигнатура `%PDF`).
Отдельно в `test_plots` проверяются включение/выключение кэша кадра и то, что
курсор виден уже на первом кадре; в `test_pdf_report` — что экспорт не меняет
ни масштаб, ни экранные метки синхронизации canvas.

### 7.7.1 Сверка выходных файлов с консольным оригиналом

`imitator` из Qt-версии должен давать `result.txt`, `reference.txt` и
`errors.txt`, побайтово совпадающие с консольным оригиналом. Сверять нужно так:

- запускать оригинал из каталога, у которого есть `../data/processed`
  (то есть обычный build-каталог внутри проекта);
- сравнивать результаты в изолированных каталогах, а не в общем `tools/`.

Особенность оригинала (`src/navigation/Aligner.cpp`): если служебный файл
`../data/processed/Aligner.dat` открыть не удалось, он молча прерывает
выставку — начальные углы и смещения акселерометра остаются нулевыми, и весь
прогон считается от нуля (`Pitch`/`Roll` около 0 вместо 1.5°/-0.4°). Ядро
Qt-версии в той же ситуации продолжает работу с отключённым дампом, поэтому
при неверном рабочем каталоге расхождение выглядит как ошибка портирования.

### 7.8 Сводный отчёт PDF (пункт 2.9)

- `PdfReport` (`src/gui/export/pdf_report.*`): титул, сводка NIS/NEES, RMS и
  максимум по всем 15 компонентам вектора ошибок, выборка таблицы NIS/NEES
  по времени, затем графики.
- Графики рисуются тем же кодом `QPainter`, что и на экране: `renderTo()` в
  прямоугольник страницы. Ряды берутся из виджетов вкладок, поэтому в отчёт
  попадает ровно то, что видно на экране (включая второй прогон и метки СНС).
- «Холст» (`MainWindow::currentPlot()`) на время сборки отчёта получает ряды
  блока и возвращает свои обратно — экранный график не меняется.
- Меню «Экспорт → Сводный отчёт в PDF…»; тест `test_pdf_report` проверяет
  сводку, отказ на пустом прогоне, сигнатуру и размер файла, а также
  неизменность состояния холста.

### 7.9 История: сортировка и фильтр

- `HistoryModel` остаётся источником данных (`QAbstractTableModel`), логики
  представления в ней нет.
- `QSortFilterProxyModel` в `ParamsPanel`: сортировка по клику на заголовок
  (по умолчанию — по дате, свежие сверху) и фильтр по строке ввода (имя,
  дата, каталог). Индекс строки при двойном щелчке переводится
  `mapToSource`, поэтому отфильтрованная строка открывает правильный прогон.
- Переход на `QSqlTableModel` не сделан и не требуется: он не дал бы ничего,
  кроме повторного SQL, поскольку `loadRun()` всё равно читает полные ряды
  через `RunStore`.

### 7.10 Что осталось

- SerialPort / WebSocket (пункты 2.7, 2.8) — опциональные, не начаты.
  Реализация потребует интерфейса источника данных в core
  (`nav::runSimulation` сейчас читает только файлы) и не может быть проверена
  без железа.
