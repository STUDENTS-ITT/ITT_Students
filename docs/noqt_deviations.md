# Отклонения NoQT-версии от архитектуры Qt-версии

Документ описывает, чем консольная версия `C:\ITT_Students_NoQT` отличается от
Qt-версии `C:\ITT_Students_Qt_Version`. Остальные документы в `docs/` — копии
материалов Qt-версии: они описывают архитектуру с ядром в `src/core/`, GUI в
`src/gui/` и пресетами тюнера. В NoQT этих частей нет; ниже — что вместо них.

## 1. Структура каталогов

| Qt-версия | NoQT |
|---|---|
| `src/core/` (ядро, Qt-независимое) | `src/` (ядро + движок прогона) |
| `src/console/main.cpp` (обёртка над `nav::runSimulation`) | `src/main.cpp` — **весь движок в одном файле** |
| `src/gui/` (QtWidgets, `QPainter`, тюнер, пресеты) | отсутствует |
| `src/core/navigation/simulation.{h,cpp}` | удалён, движок перенесён в `main.cpp` |
| `src/core/data_io/data_source.{h,cpp}` | удалён, выбор файлов — в `main.cpp` (`pickFile`) |
| `src/core/navigation/filter_settings.{h,cpp}` | удалён, настроек нет |
| `src/core/utils/ini_parser.{h,cpp}` | удалён, INI-ридер не нужен |
| `presets/`, `tests/`, `tools/kalman_tuner/` | отсутствуют |

## 2. Настройки

- **`settings.ini` не читается.** Тюнера и пресетов в NoQT нет и не будет.
  Шумы фильтра — умолчания `ins::kalman_cfg`, пороги сведения наклона —
  умолчания `TiltManeuverPolicy` (экземпляр `TILT_POL` создаётся прямо в
  `navigation/trajectory.h`; прежняя `nav::tiltPolicy()` удалена).
- **Плоский `params.ini` сохранён** — как в исходной версии `C:\ITT_Students`:
  необязательный второй позиционный аргумент `imitator`, разбирается функцией
  `applyParamsFile()` в `main.cpp`. Ключи: `sigma_g`, `sigma_a`, `sigma_bg`,
  `sigma_ba`, `sigma_pos`, `sigma_v`, `sigma_ang`, `outage_start_s`,
  `outage_end_s`.

## 3. Что удалено из ядра как GUI-обвязка

| Было | Стало | Почему |
|---|---|---|
| `nav::StepTelemetry` (телеметрия такта для GUI) | удалено | GUI-обвязка; NIS остаётся через `sink.wantsConsistency()` |
| `nav::RunOptions`, `nav::RunSummary` | удалено | прогона как отдельного модуля больше нет |
| `nav::runSimulation`, `nav::runBiasReport` | удалено | прогон выполняет `main.cpp` |
| `data_io::IDataSource`, `FileDataSource`, `MockDataSource` | удалено | консольной версии достаточно файлового чтения |
| `nav::FilterSettings`, `loadFilterSettings`, `settingsFileHasSections` | удалено | настроек нет |
| `utils::ini_parser` | удалено | см. выше |

## 4. Что сохранено

- Вся математика ESKF (15 состояний) — без изменений: матрицы построчно
  (`at(A,i,j,cols)`), углы внутри в радианах, на выходе в градусах.
- Коррекция pitch/roll по акселю (Этап 2, R2).
- Защита СНС, уровни 1–2 (`gnss_guard.txt`).
- Аналитика: журнал смещений (`bias.txt`), NIS (`consistency.txt`), сводная
  таблица по смещениям (`--bias-report`) — по-прежнему только по явным флагам.
- `dataset_generator` **удалён** из NoQT: он писал `params.json`, из которого
  отчёт `--bias-report` брал истину; в NoQT истина берётся из готовых наборов
  (`truth.txt`), генератор не нужен.

## 5. Проверка паритета

Выход NoQT и консольного `imitator` Qt-версии совпадает побитово по всем шести
файлам: `result.txt`, `reference.txt`, `errors.txt`, `gnss_guard.txt`,
`bias.txt`, `consistency.txt` (сравнение md5 на одном и том же наборе данных).

С оговоркой: побитовое совпадение сохраняется, пока обе версии используют одну
и ту же схему выставки. После перехода NoQT на новую схему (раздел 6) паритет
ломается **сознательно** — расхождение фиксируется в разделе 6.

## 6. Выставка: окно 1 с и новые x0/P0

Подробный план и обоснования — `docs/fast_alignment_plan.md`. Здесь — только
карта отличий от Qt-версии. Схема **реализована и проверена** (раздел 6.2).

| Что | Qt-версия | NoQT (этапы A–E выполнены) |
|---|---|---|
| Окно выставки | длинное окно покоя (из `StartupNav.ini`, 120 с и более) | **1 с** (тот же ключ `StartupNav.ini`, 4-я строка); окно — от начала файла до `T_align`, перемотки нет; нет файла → fallback 1 с |
| Выравнивание средних | медиана + EMA по блокам (3000 отсчётов) | прямое среднее по окну; шум — из **максимума отклонения**: `σ̂_отсчёта = Δ/k(N)`, `σ̂_среднего = σ̂_отсчёта/√N` |
| Номинал СНС | первый отсчёт СНС | **последний** отсчёт окна (состояние на `t = T_align`) |
| Курс в окне | первый отсчёт СНС | номинал — последний отсчёт `angle.dat`; круговое среднее окна — только для `x0[6]` |
| Оценка смещения гиро | нет (`bg` в номинале = 0) | `bg = ω̄ − navToBody(C, ω_Земли)`, оценка в `x0[12..14]` |
| Параметры модели | паспорт | `ba = f̄ − Cᵀ·[0,g,0]`, `bg = 0` (оценка — в `x0`, не в номинале) |
| `x0` | нет (P₀ паспортная, x = 0) | `x0[0..6] = последний − среднее` (широта, долгота, высота, скорости, курс), `x0[7..11] = 0`, `x0[12..14] = bg_est` |
| P₀ | паспортная (σ_ba = 5 мг, σ_bg = 103 °/ч, σ_V = 2.5 м/с, σ_угла = 1°) | по данным окна: σ_pos/σ_h/σ_v/σ_hdg — по разбросу СНС с паспортными полами; σ_наклон = max(√(σ_ba_гор²+σ_ā_гор²)/g, 2σ_ba_гор/g); σ_ba_верт = max(σ_ā_Y, σ_ba/10); σ_bg_гор = max(σ_ω̄_гор, σ_bg/5); σ_bg_верт = σ_bg; корреляции `P[7][9] = +σ_ba_гор²/g`, `P[8][11] = −σ_ba_гор²/g` |
| Первая коррекция | по первому кадру СНС после окна | по **первому кадру СНС за окном** (последний отсчёт окна — номинал, повторно не измеряется); `time_prev = T_align` |
| Начало работы фильтра | после выставки, `t = T_align` | с первого отсчёта ИМУ с `t > T_align` (`dt = t − T_align`); окно усреднения — первая фаза того же прогона |
| Перемотка потоков | есть | нет: окно читается из того же потока, «лишний» отсчёт возвращается (`pending_row`) |
| Гейт покоя | нет | скорость СНС (`4σ̂` среднего, но не паспорт), `|ω̄ − Cᵀω_Земли| ≤ 1e-2 + 4σ̂_ω̄` (≈2060 °/ч — отсекает только грубое вращение, смещение гиро от поворота за 1 с неотличимо), `|f̄_Y − g| ≤ 10 мг`; провал → WARNING + паспортная P₀ + `bg_est` не применяется |
| Диагностика окна | — | новый файл `tools/init.txt` (средние, `Δ`, σ, `ba`/`bg`, гейт и его пороги, `x0`/`σ0`) |
| Гейт R4 (годность gyro-compassing) | влияет на оценку курса | переведён в диагностику (`gyro_compass_ratio` в `init.txt`): в окне 1 с шум среднего всегда «проваливает» порог 0.3 |

### 6.1 Знаки состояния (не менялись)

`x[0..8]` = номинал − истина (вычитаются при инъекции), `x[9..14]` = истина −
номинал (складываются). Поэтому `x0[0..6] = последний − среднее` (это и есть
ошибка номинала), а `x0[12..14] = bg_est` при номинальном `bg = 0`.

### 6.2 Итоги прогонов (11 наборов, окно 1 с)

Ошибки ИНС относительно `truth.txt`: RMSE горизонтальной позиции, максимум,
высота, курс, горизонтальная скорость; «tail» — вторая половина прогона.

| Набор | gate | pos_h RMSE, м | max, м | курс | tail pos |
|---|---|---|---|---|---|
| `static_lownoise_align` | ✓ | 0.08 | 0.43 | 0.05° | 0.08 |
| `static_300` | ✓ | 0.16 | 0.98 | 0.19° | 0.15 |
| `spiral_climb` | ✓ | 0.18 | 0.74 | 0.20° | 0.17 |
| `straight_10ms` | ✓ | 0.20 | 1.98 | 0.20° | 0.22 |
| `figure8_8ms` | ✓ | 0.31 | 2.03 | 0.20° | 0.15 |
| `square_650` | ✓ | 1.25 | 2.65 | 0.20° | 0.93 |
| `square_noisefree` | ✓ | 1.20 * | 9.31 * | 4.68° * | 1.69 |
| `high_dynamics` | ✓ | 1.71 | 3.76 | 0.40° | 1.71 |
| `square_harsh` | ✓ | 5.06 | 11.42 | 0.96° | 3.56 |
| `run_hk` (нет truth) | ✓ | — | — | — | — |
| `noqt_raw` (нет truth) | ✓ | — | — | — | — |

\* `square_noisefree` — артефакт `truth.txt`: на `t ∈ [347, 372]` в истине
записано «будущее» состояние (курс 71.6° уже с `t ≈ 359`, эталон же плавно
поворачивает 5° → 73.7° к `t = 372`). Вне этого интервала ошибки — **0.006 м и
0.004°**; на всём наборе `bg_est = ba_est = 0`, т.е. совпало с истиной.

Ни на одном наборе ошибка не растёт (tail ≤ full), расходимости нет. Курс на
наборах с `angle.dat` равен шуму эталона: канал курса идёт за измерением
(`K ≈ 1`), поэтому лучше эталона он быть не может. `run_hk`/`noqt_raw` — без
`truth.txt`: позиция относительно эталона 1.2 м P95, скорости 0.004 м/с.

**Побочный эффект общих данных.** Наборы `ITT_Students-Katya/dataset_shum/*`
(9 файлов) и `run_hk/data/raw/StartupNav.ini` — общие для обеих версий; в них
4-я строка переведена с `120.0`/`100.0`/`240.0`/`30.0` на `1.0`. Формат файла
не изменён. Следствие: Qt-консоль при прогоне на этих наборах тоже читает
окно 1 с и делает выставку **старым** алгоритмом; после перехода NoQT на новую
схему побитового паритета на этих наборах нет (это и есть сознательное
расхождение раздела 6).

**Что в NoQT остаётся прежним:** математика ESKF (15 состояний), построчное
хранение матриц, углы в радианах внутри и в градусах на выходе, форматы
`result.txt` / `reference.txt` / `errors.txt` / `gnss_guard.txt`, защита СНС,
пороги сведения наклона, аналитика по флагам (`--bias-log`, `--bias-report`,
`--consistency`).
