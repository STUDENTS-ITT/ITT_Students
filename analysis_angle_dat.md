# Анализ файла angle.dat

## 1. Где используется?

`angle.dat` читается только в одном месте — классе `SnsReader` (`data_reader.cpp`), который открывает его параллельно с `gps.dat`. Вызов из `main.cpp`:

```cpp
sns.open(gps_file, angle_file)
```

## 2. Как используется?

`SnsReader::next()` читает строки из `gps.dat` и `angle.dat` синхронно (по одной строке из каждого файла за вызов). Из `angle.dat` извлекаются три угла:

```
angle.dat: time_s | timestamp_ns | roll | pitch | yaw
```

Они записываются в `SnsSample` (поля `heading`, `pitch`, `roll`) и далее используются в двух целях:

| Цель | Место использования | Описание |
|------|---------------------|----------|
| Коррекция фильтра Калмана | `ins::correct()` в `ins_filter.h` | Вектор измерений `sns = ref.measurement()` содержит `heading/pitch/roll` — это эталон для вычисления инновации `z = bins − sns` |
| Запись эталона | `makeReference()` в `trajectory.h` | Углы из `SnsSample` конвертируются в градусы и записываются в `reference.txt` |

## 3. Проблема: отсутствие на аппарате

На реальном аппарате файла `angle.dat` **не будет**. Он существует только в лабораторных данных. Это означает:

- Текущий алгоритм **не запустится** без `angle.dat` — `SnsReader::next()` вернёт `false`, коррекция по СНС не будет выполняться.
- Файлы `gps.dat` и `angle.dat` синхронизированы построчно (одна строка gps + одна строка angle). Без `angle.dat`рушится механизм чтения эталона.

## 4. Варианты решения

### Вариант А: Полное отвязывание от angle.dat (рекомендуется)

1. Разделить чтение `gps.dat` и `angle.dat` — сделать их независимыми.
2. При отсутствии `angle.dat` — формировать вектор измерений без угловых компонент:
   - Измерение: `{lat, lon, alt, vn, vh, ve}` (6 компонент)
   - Матрица наблюдения `H`: 6x15 вместо 9x15
   - Матрица шумов `R`: 6x6 вместо 9x9
3. Координаты и скорости из `gps.dat` — доступны на аппарате (от СНС/ГНСС).
4. Углы ориентации — вычисляются автономно по ИМУ (уже реализовано: `headingFromEarthRate()` для начального курса, `eulerRates()` + `integrate()` для динамики).

### Вариант Б: Вычисление эталонных углов по другому источнику

Если на аппарате появится другой датчик углов (магнитометр, визуальная навигация и т.д.) — подключить его вместо `angle.dat`.

### Вариант В: Временный — заглушка

Пока идёт разработка: при отсутствии `angle.dat` заполнять `heading/pitch/roll` нулями. Коррекция будет работать только по позиции и скорости. Это **снижает точность**, но позволяет тестировать остальной алгоритм.

## 5. Рекомендация

Реализовать **Вариант А**: сделать чтение `angle.dat` опциональным, при его отсутствии переключаться на 6-компонентную коррекцию (только координаты + скорости). Это позволит:

- Запускать алгоритм на аппарате (без `angle.dat`).
- Сохранять работоспособность на лабораторных данных (с `angle.dat`).
- В будущем подключить альтернативный источник углов без изменения архитектуры.
