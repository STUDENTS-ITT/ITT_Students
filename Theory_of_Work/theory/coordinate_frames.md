# Системы координат и углы ориентации

Теория систем координат, в которых считает ядро. Все формулы — из
`src/core/math_lib/transformations.h`, `src/core/ins/attitude_calc.h`,
`src/core/utils/constants.h`.

---

## 1. Две системы координат

### 1.1. Связанная СК (СК тела, «body»)

Жёстко связана с корпусом, оси совмещены с осями чувствительности датчиков:

| Ось | Направление |
|---|---|
| **X** | продольная (нос) |
| **Y** | вертикальная (вверх) |
| **Z** | поперечная (правый борт) |

Именно в этой СК акселерометр выдаёт `f_б = (Ax, Ay, Az)` (м/с²), а гироскоп —
`ω_б = (Wx, Wy, Wz)` (рад/с). Обратите внимание: ось **Y** смотрит вверх, а не
вбок — это необычный для многих учебников, но сквозной для проекта выбор
(сила тяжести в покое даёт `Ay ≈ +g`).

### 1.2. Навигационная (географическая) СК, «nav»

Начало — в текущей точке, оси ориентированы по местной вертикали и сторонам
света:

| Ось | Направление |
|---|---|
| **X** (индекс 0) | Север |
| **Y** (индекс 1) | вверх (против силы тяжести) |
| **Z** (индекс 2) | Восток |

Набор `(Север, Вверх, Восток)` принято называть **NUE**. Он фиксирован в коде:
скорость `V = {Vn, Vh, Ve}` (`V[0]` — север, `V[1]` — вверх, `V[2]` — восток),
гравитация `g = {0, +normalGravity, 0}`.

> Расхождение с историческим `SINS/docs/2_Algorithm_Description.md`: там
> описана та же навигационная СК (Xg — Север, Yg — вверх, Zg — Восток), но
> матрица поворота и соглашения о знаках курса отличаются. Актуален код.

## 2. Углы Эйлера–Крылова

Ориентация тела относительно навигационной СК задаётся тремя углами в
последовательности поворотов **курс → тангаж → крен** (Z-Y-X):

| Угол | Имя | Что задаёт |
|---|---|---|
| `heading` | ψ (Yaw/курс) | поворот вокруг оси Y nav; от Севера к проекции оси X тела на горизонт |
| `pitch` | θ (тангаж) | поворот вокруг оси Z nav; подъём носа над горизонтом |
| `roll` | φ (крен) | поворот вокруг оси X тела; наклон вбок |

В коде они живут в `ins::Attitude { heading, pitch, roll }`
(`src/core/ins/attitude_calc.h`) — **всегда в радианах**. На вывод (файлы, GUI)
переводятся умножением на `RAD_TO_DEG`.

**Соглашение о знаке курса:** курс отсчитывается от Севера **по часовой
стрелке** (к Востоку). При `ψ = 90°` продольная ось тела смотрит на восток
(см. `bodyToNavMatrix` в `transformations.h`). Это объясняет знак минус в
кинематическом уравнении курса (раздел 4).

## 3. Матрица направляющих косинусов `C_б^н`

Функция `bodyToNavMatrix(heading, pitch, roll)` (`transformations.h`) возвращает
матрицу 3×3, которая переводит вектор из СК тела в навигационную:

```
v_nav = C_б^н · v_body
```

Элементы построчно (`at(C, r, c, 3)`, строка — индекс nav-оси, столбец — body):

```
c_p·c_y                                        -c_r·c_y·s_p - s_r·s_y        s_r·c_y·s_p - c_r·s_y
s_p                                             c_r·c_p                    -s_r·c_p
c_p·s_y                                        -c_r·s_y·s_p + s_r·c_y        s_r·s_y·s_p + c_r·c_y
```

где `c_p = cos(pitch)`, `s_p = sin(pitch)`, `c_y = cos(heading)`, `s_y = sin(heading)`,
`c_r = cos(roll)`, `s_r = sin(roll)`.

Проверка вырожденного случая: при `ψ = θ = φ = 0` матрица единичная —
оси тела совпадают с осями nav.

Обратное преобразование — через транспонирование (`C` ортогональна):

```
v_body = (C_б^н)ᵀ · v_nav
```

Реализовано как `navToBody(C, v_nav)` и `bodyToNav(C, v_body)`.

Матрица используется в каждом такте счисления:
- `f_н = C · f_б` — кажущееся ускорение в навигационной СК;
- `(C)ᵀ · ω_Земля` — проекция вращения Земли на оси тела (раздел 4);
- `C` — в матрице перехода `F` фильтра (`estimation.md`).

## 4. Кинематика углов: скорости Эйлера

Углы меняются не по показаниям гироскопа напрямую. Сначала вычитается
переносная угловая скорость вращения Земли
(`ins::relativeRate`, `attitude_calc.h`):

```
ω_отн = ω_гиро − (C_б^н)ᵀ · ω_Земля
```

где `ω_Земля = {U_EARTH·cos(lat), U_EARTH·sin(lat), 0}` — в навигационной СК
(`navAngularRate` даёт полную версию с учётом движения, см. `ins_equations.md`).

Затем скорость ухода углов вычисляется обратной связывающей матрицей Эйлера
(`ins::eulerRates`):

```
ψ̇ = −(ω_y·cos φ − ω_z·sin φ) / cos θ
θ̇ = ω_y·sin φ + ω_z·cos φ
φ̇ = ω_x − tan θ·(ω_y·cos φ − ω_z·sin φ)
```

где `ω = (ω_x, ω_y, ω_z)` — компоненты `ω_отн`.

- Знак минус в `ψ̇` — следствие отсчёта курса по часовой стрелке (ω_y
  положительна против часовой).
- `cos θ` защищён от нуля: `cos_pitch = fmax(|cos θ|, 1e-10)`. При `θ = ±90°`
  связывающая матрица вырождена (℘-образная особенность Эйлера) — это
  принципиальное ограничение представления углами, а не дефект кода.

Скорости Эйлера хранятся в `ins::AttitudeRates { heading_dot, pitch_dot, roll_dot }`.

## 5. Интегрирование углов

`ins::integrate(prev, now, prev_rates, dt)` интегрирует методом трапеций:

```
угол(t) = normalize_angle( угол(t−dt) + (rate_now + rate_prev)/2 · dt )
```

Для точности промежуточная арифметика ведётся в `long double`
(`v_integral_ld`). Результат всегда прогоняется через `normalize_angle`.

---

## 6. Нормализация угла

`normalize_angle(a)` (`transformations.h`) приводит угол к диапазону `[−π, π]`:

```cpp
a = fmod(a, 2π);
while (a >  π) a -= 2π;
while (a ≤ −π) a += 2π;
```

Применяется ко всем углам после интегрирования, при формировании инноваций
курса/тангажа/крена и при выводе. Нижняя граница строгая (`a > −π`), поэтому
значение ровно `−π` переходит в `+π`.

## 7. Единицы измерения

| Величина | Внутри ядра | На выводе |
|---|---|---|
| координаты | рад (широта, долгота), м (высота) | град, м |
| углы | рад | град |
| угловые скорости | рад/с | — |
| ускорения | м/с² | — |
| время | с | с |

Перевод: `RAD_TO_DEG = 180/π`, `DEG_TO_RAD = π/180` (`constants.h`).

Исключение: диагональ ковариации позиции в `R` фильтра хранится в **рад**
(`sig_pos = 2.64401e-08`, что при умножении на `R_EARTH` даёт ≈ 0.17 м линейной
меры), т. к. состояние `x[0], x[1]` — в радианах.
