# Уравнения БИНС (счисления)

Уравнения бесплатформенной инерциальной системы, которые решает ядро на каждом
такте ИМУ. Реализация — `src/core/navigation/position_calc.h`,
`src/core/navigation/trajectory.h` (`nav::step`), `src/core/math_lib/interpolation.h`,
`src/core/utils/constants.h`.

Постановка: БИНС измеряет кажущееся ускорение `f_б` (удельная сила, «то, что
показывает акселерометр») и абсолютную угловую скорость `ω_б`. Задача —
перейти от них к координатам, скорости и ориентации.

---

## 1. Модель Земли

Ядро использует простую сферическую модель (`constants.h`):

| Константа | Значение | Смысл |
|---|---|---|
| `U_EARTH` | `7.292115e-5` рад/с | угловая скорость вращения Земли |
| `R_EARTH` | `6371e3` м | средний радиус |
| `G_EQ` | `9.780327` м/с² | g на экваторе |
| `GRAVITY_CONSTANT` | `0.0053024` | коэффициент формулы Клеро |

Нормальная сила тяжести — **формула Клеро с поправкой на высоту**
(`utils::normalGravity(lat, h)`):

```
g0    = G_EQ · (1 + GRAVITY_CONSTANT · sin²lat)
scale = R_EARTH / (R_EARTH + h)
g     = g0 · scale²
```

Это отличается от «точечной массы» `GM/r²`: используется общепринятая
геодезическая аппроксимация, где g зависит от широты (на полюсе больше, чем на
экваторе). Исторический дубль той же формулы — `nav::calculate_g` в
`aligner.hpp` (численно идентична, но через `NAV_R`).

В высотной поправке применяется квадрат масштаба (обратный квадрат расстояния
до центра), что согласовано с законом тяготения.

## 2. Угловая скорость навигационной СК

Навигационная СК не инерциальна: она вращается вместе с Землёй и вместе с
движением аппарата. Её абсолютная угловая скорость — `navAngularRate`
(`position_calc.h`):

```
ω_N = U_EARTH·cos(lat) + V_E / R_h
ω_H = U_EARTH·sin(lat) + V_E·tan(lat) / R_h
ω_E = −V_N / R_h
```

где `R_h = R_EARTH + alt`, `V_N = V[0]`, `V_E = V[2]`.

Слагаемые:
- `U_EARTH·cos(lat)`, `U_EARTH·sin(lat)` — проекция вращения Земли на
  горизонтальную (север) и вертикальную оси;
- `V_E / R_h` и `V_E·tan(lat)/R_h` — поворот СК при движении на восток;
- `−V_N / R_h` — поворот СК при движении на север.

Здесь же берётся проекция вращения Земли для вычитания из гироскопа
(см. `coordinate_frames.md`, раздел 4): в `nav::step` используется `w_nav =
navAngularRate(...)`, затем `ω_отн = relativeRate(gyro, w_nav, C)`.

---

## 3. Уравнение скоростей

Основное уравнение движения в навигационной СК (второй закон Ньютона для
кажущегося ускорения):

```
V̇ = C_б^н · f_б − a_вред
```

Реализовано тремя шагами в `position_calc.h` / `trajectory.h`:

```
n_nav = C · f_б                        // bodyToNav
a_harm = harmfulAccel(...)             // вредные ускорения
V_dot = velocityDot(n_nav, a_harm)     // V̇
```

### 3.1. Вредные ускорения `harmfulAccel`

Это то, что нужно вычесть из показаний акселерометра, чтобы получить
кинематическое ускорение относительно Земли:

```
a_вред = 2·ω_Земля × V  +  ω̂_СК × V  +  g
```

Разложение по коду:

- **Кориолис** `2·ω_Земля × V`, где `ω_Земля = {U_EARTH·cos(lat),
  U_EARTH·sin(lat), 0}`; в коде вектор `U2 = 2·ω_Земля`, затем
  `Ac = vector_product(U2, V)`.
- **Центробежное / переносное** `ω̂_СК × V`, где `ω̂_СК — угловая скорость
  вращения самой СК`:
  ```
  ω̂ = {lon_dot·cos(lat), lon_dot·sin(lat), −lat_dot}
  ```
  (широта и долгота меняются — СК «закручивается» под аппаратом).
- **Гравитация** `g = {0, normalGravity(lat, alt), 0}` — вверх.

Сумма: `A_harm = Ac + ω̂×V`, возврат `A_harm + g`.

> Для низкоскоростных аппаратов вклад Кориолиса мал, но в модели он учтён —
> поэтому же он присутствует в матрице `F` фильтра (`estimation.md`).

### 3.2. Интегрирование скорости

Метод трапеций (`interpolation.h`, `v_integral`):

```
V(t) = V(t−dt) + (V̇_now + V̇_prev)/2 · dt
```

Векторная перегрузка `integrateVelocity(V_dot, V_prev, V_dot_prev, dt)` —
поэлементно. Прошлое значение `V̇_prev` хранится в состоянии
(`NavState::V_dot_prev`) для согласованности порядка точности.

## 4. Уравнение координат

Координаты интегрируются из скорости (`integratePosition`, `position_calc.h`):

```
Rh     = R_EARTH + alt
φ̇      = V_N / R_h                           (широта)
φ(t)   = clamp( φ(t−dt) + (φ̇_now + φ̇_prev)/2 · dt ,  −π/2 … π/2 )

λ̇      = V_E / (R_h · cos φ)                 (долгота)
λ(t)   = normalize_angle( λ(t−dt) + (λ̇_now + λ̇_prev)/2 · dt )

h(t)   = h(t−dt) + (V_H_now + V_H_prev)/2 · dt    (высота)
```

Особенности:
- широта ограничивается полюсами `±π/2` (защита от «переполюсовки»);
- `cos φ` защищён: `fmax(|cos φ|, 1e-10)` — у полюса долгота не определена,
  деление не даёт бесконечность;
- долгота нормализуется в `[−π, π]` — переход через меридиан ±180° корректен;
- высота интегрируется **напрямую** из вертикальной скорости (в отличие от
  исторического `SINS/docs`, где вертикальный канал блокировался).

Производные `lat_dot`, `lon_dot`, `alt_dot` кэшируются в состоянии
(`NavState::lat_dot_prev` и т. д.) для следующей трапеции.

## 5. Кажущееся ускорение и показания датчиков

Показания датчиков вычитанием оценок смещений (`ins::accel`, `ins::gyro`,
`imu_processor.h`):

```
f_б = (Ax, Ay, Az) − ba
ω_б = (Wx, Wy, Wz) − bg
```

где `ba`, `bg` — оценки смещений акселерометра и гироскопа (обновляются
фильтром Калмана, `estimation.md`; начальное `ba` — из выставки).

---

## 6. Ориентация

Ориентация интегрируется отдельно (см. подробно `coordinate_frames.md`,
разделы 4–5):

1. `ω_отн = ω_б − (C)ᵀ·ω_н` (вычитание вращения Земли и движения);
2. `(ψ̇, θ̇, φ̇) = eulerRates(ω_отн, θ, φ)`;
3. `(ψ, θ, φ)(t) = integrate(..., dt)` — трапеция + `normalize_angle`.

При этом `C_б^н` пересчитывается по углам на каждом такте.

---

## 7. Полный такт счисления (без фильтра)

Шаги 1–11 `nav::step` (`trajectory.h`) — «чистое» счисление:

1. `dt = time − time_prev` (при `dt ≤ 0` — `IMU_PERIOD`);
2. `C = bodyToNavMatrix(att)`;
3. `f_б = accel(row, ba)`, `n_nav = C·f_б`;
4. `a_harm = harmfulAccel(...)`, `V̇ = n_nav − a_harm`, `V = integrateVelocity(...)`;
5. `pos = integratePosition(...)`;
6. `V̇_б = (C)ᵀ·V̇` (для tilt-контура), `ω_б = gyro(row, bg)`;
7. признаки манёвра (гироскоп/торможение);
8. оценка горизонта по акселю;
9. `ω_н = navAngularRate(...)`, `ω_отн = relativeRate(...)`, `rates =
   eulerRates(...)`, интегрирование углов;
10. запись нового `V`, `lat`, `lon`, `alt`, `att` и производных;
11. tilt-контур (`navigation_tilt.md`).

Далее идут предсказание и коррекция фильтра — это уже `estimation.md`.

---

## 8. Порядок точности и ограничения

- Везде метод трапеций (второй порядок по `dt`); для углов промежуточная
  арифметика в `long double`.
- СК — сферическая: нет учёта сжатия Земли, эллипсоида и изменения широты
  в модели тяжести, кроме формулы Клеро.
- `fullstate` не пересчитывается на «подшагах» — один вызов на такт ИМУ
  (200 Гц, `dt ≈ 5 мс`).
- Особенность Эйлера при `θ = ±90°` (см. `coordinate_frames.md`).
