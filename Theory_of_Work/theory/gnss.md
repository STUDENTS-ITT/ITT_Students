# Комплексирование с СНС и защита от отказов

Теория измерений спутниковой навигации (СНС) и отсева аномальных кадров.
Реализация — `src/core/navigation/gps_processor.h`,
`src/core/navigation/gnss_guard.h`, разбор — `src/core/data_io/data_reader.cpp`,
дизайн — `docs/gnss_guard_design.md`.

---

## 1. Роль СНС в комплексе

БИНС сама по себе «накапливает» ошибку: смещение гироскопа уводит углы, ошибка
ориентации через кажущееся ускорение уводит скорость, а та — координаты. СНС
даёт **абсолютные**, но редкие (`SNS_RATE_HZ = 10` Гц против `IMU_RATE_HZ = 200`
Гц) и шумные измерения. Фильтр Калмана (`estimation.md`) объединяет то и другое:
БИНС даёт точную динамику на коротком интервале, СНС — привязку к абсолютной
системе координат на длинном.

---

## 2. Один отсчёт СНС: `SnsSample`

`SnsSample` (`gps_processor.h`) — все данные кадра СНС:

| Поле | Единица | Смысл |
|---|---|---|
| `time` | с | время |
| `lat`, `lon` | рад | координаты |
| `alt` | м | высота |
| `vn`, `vh`, `ve` | м/с | скорости (Север, Вверх, Восток) |
| `heading` | рад | курс (из `angle.dat`, если есть) |
| `roll`, `pitch` | рад | крен, тангаж |

Методы:
- `measurement()` — упаковка в вектор `z[0..8] = {lat, lon, alt, vn, vh, ve,
  heading, pitch, roll}` (порядок согласован с `H` фильтра);
- `maxSpeed()` — максимум `|vn|, |vh|, |ve|` (порог «есть движение»).

Источник: `SnsReader` (`data_reader.cpp`) читает `gps.dat` (координаты
градусы → радианы) и **опционально** `angle.dat` углы. Углы стыкуются с GPS по
**ближайшему времени**, а не по номеру строки. Если `angle.dat` нет — углы
нулевые, а фильтр не корректирует курс (`has_heading_ref == false`).

---

## 3. Модель измерения

Измерение фильтра — разность «БИНС − СНС» (см. `estimation.md`, раздел 2):

```
z = y_БИНС − y_СНС
```

Не все 9 компонент «равноценны»:
- координаты/скорости — прямо из СНС;
- курс — из СНС (если есть эталон `angle.dat`), иначе из номинала БИНС
  (нулевая инновация);
- тангаж/крен — из **акселерометра** (tilt-контур), а не из СНС.

Матрица `H = [I₉ | 0₉ₓ₆]`, `R = diag(...)` с шумами СНС
(`sig_pos`, `sig_h`, `sig_v`, `sig_hdg`) и шумами углов из акселя.

---

## 4. Защита от отказов СНС

СНС может выдавать мусор: «нулевой фикс» (нет решения), телепорт, заморозку,
недостижимую скорость, немонотонное время, полный отказ (молчание). Если такие
кадры подавать в фильтр, они разрушают оценку. Защита реализована **уровнями**
(полный дизайн — `docs/gnss_guard_design.md`):

- **Уровень 0** — устойчивый разбор строк (`data_reader.cpp`): повреждённые
  строки пропускаются, файл читается в бинарном режиме.
- **Уровень 1** — самодостаточная валидация кадра (`SnsGuard::validate`):
  диапазоны, нулевой фикс, скорость, высота, кинематика, монотонность времени.
- **Уровень 2** — детектор молчания по времени ИМУ.
- **Уровни 3–6** (гейт по инновации, детектор скачка, блокировка с backoff,
  мягкое пересопряжение) **не реализованы**.

### 4.1. Статус кадра: `SnsStatus`

Статус — свойство **кадра**, а не пары «кадр ↔ состояние фильтра». Булева
признака недостаточно: важно отличать «СНС молчит» от «СНС отвечает мусором» —
это разные отказы с разной реакцией.

| Статус | Значение |
|---|---|
| `VALID` | самодостаточные проверки пройдены |
| `INVALID` | данные есть, но кадр непригоден |
| `STALE` | корректных отсчётов нет дольше таймаута |

### 4.2. Уровень 1: `SnsGuard::validate` (порядок проверок)

Причина отклонения — `SnsReject`:

| № | Проверка | Причина |
|---|---|---|
| 1 | конечность 9 компонент и `time` | `NONFINITE` |
| 2 | `\|lat\| ≤ 90°`, `\|lon\| ≤ 180°` | `RANGE` |
| 3 | не «нулевой фикс» (`\|lat\|,\|lon\| < 1e-7` рад) | `ZERO_FIX` |
| 4 | `maxSpeed() ≤ gnss_vel_plaus` (60 м/с) | `SPEED` |
| 5 | высота в полосе `±5000` м вокруг первого фикса | `ALTITUDE` |
| 6 | `dt = t − t_принятого > 0` и `≤ 3600` с | `TIME` |
| 7 | `Δ_horiz ≤ vel_plaus·dt + gnss_acc_bound` (50 м) | `KINEMATICS` |

Ключевые идеи:
- **Опора проверок — последний *принятый* фикс** (`last_accepted`), а не
  последний прочитанный. Иначе мусор становится опорой и «легализует»
  следующий мусор.
- **Проверка 7 (кинематика)** — одно правило закрывает сразу заморозку
  (аппарат «стоит» на месте при движении), телепорт и правдоподобный, но
  неверный фикс: горизонтальное смещение ограничено максимально возможным по
  времени и допуску ускорения.
- Метрики `last_dt`, `last_dpos`, `last_dvel` пишутся в лог (в `gnss_guard.txt`)
  для разбора — в том числе при нарушении (причина `TIME` не остаётся без
  числа).
- При успехе: при первом кадре задаётся `alt0` (центр полосы высоты),
  обновляются `last_accepted`, счётчик `accepted_frames`, статус `VALID`.

### 4.3. Уровень 2: детектор молчания

Считается **по времени ИМУ**, а не по числу кадров, — поэтому пауза в данных и
обрыв связи дают одинаковую реакцию:

```
t_ref = has_accepted ? last_accepted.time : first_seen_time
if (imu_time − t_ref > gnss_silence_timeout_s)   status = STALE
```

(`gnss_silence_timeout_s = 0.5` с по умолчанию). Статус только что пришедшего
кадра не перекрывается: `INVALID` — «данные есть, но плохие», `STALE` — «данных
нет».

### 4.4. Кадр оценивается один раз

`SnsGuard::update` определяет новый кадр по изменению времени
(`is_new_frame = !has_seen || s.time != last_seen_time`). Повторные вызовы с тем
же отсчётом (между кадрами СНС, на каждом такте ИМУ) решение не пересчитывают —
отдаётся сохранённый статус. Это дёшево и детерминировано.

**Известное ограничение:** повтор времени (`dt = 0`) не наблюдается — строка с
прежним временем не считается новым кадром и в лог как отказ не попадает
(разбор — `docs/gnss_guard_design.md`, раздел 14.2).

### 4.5. Разрешение на коррекцию

`update` возвращает `true`, если коррекцию применять разрешено:

```
cfg.gnss_guard_on ≤ 0.5  ||  status == VALID
```

С выключенной защитой (`gnss_guard_on = 0`) разрешение прежнее — поведение не
меняется, но **наблюдение продолжается**: можно сравнить прогоны с защитой и
без. В `nav::step` итог: `apply_correction = do_correction && sns_ok`.

## 5. Пороговые константы (уровень 1)

| Константа | Значение | Смысл |
|---|---|---|
| `SNS_ALT_BAND_M` | `5000.0` м | полоса высоты вокруг первого фикса |
| `SNS_ZERO_FIX_EPS_RAD` | `1e-7` рад | порог «нулевого фикса» |
| `SNS_DT_MAX_S` | `3600.0` с | предельный интервал между кадрами |
| `gnss_vel_plaus` | `60.0` м/с | предел правдоподобной скорости |
| `gnss_acc_bound` | `50.0` м | допуск кинематической проверки |
| `gnss_silence_timeout_s` | `0.5` с | порог молчания |

Полоса высоты и предельный интервал — **предохранители**, а не «настройки
подбора»: выход за них означает отказ датчика. Поэтому они не вынесены в
`KalmanConfig`, в отличие от параметров, которые могут настраиваться
(`gnss_vel_plaus`, `gnss_acc_bound`, таймаут).

---

## 6. Наблюдаемость решений

Каждое решение защиты отдаётся в лог (`NavLogger`, файл `gnss_guard.txt`):
время, статус, причина, `new_frame`/`applied`/`manual`, метрики `dt/dpos/dvel`,
накопленные счётчики принятых/отклонённых. Пишется при
`gnss_guard_log > 0.5`. Итоговая сводка (отрезки STALE, причины отклонений по
новым кадрам) дописывается при `close()`. Это соответствует принципу дизайна
«каждое решение наблюдаемо».

---

## 7. Свободное счисление (окно без СНС)

Помимо защиты, есть штатное окно `outage_start_s`/`outage_end_s` из настроек:
внутри него коррекции по СНС **намеренно** отключаются (`do_correction =
!in_outage && ...`) — для проверки деградации чистой БИНС. Если окно задано
нулями, оно выключено.
