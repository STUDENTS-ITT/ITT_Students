# Набор `square_harsh`

Геометрия как в square_650, но грубый ИМУ (ДУС 8e-3 рад/с, смещение 150 °/ч), СНС 5 м по горизонту и 8 м по высоте, пропуски отсчётов 2 %. Проверка робастности.

## Файлы

| Файл | Содержание |
|------|------------|
| `imu.dat` | ИМУ: `time_s timestamp_ns wx wy wz ax ay az` (рад/с, м/с²) |
| `gps.dat` | СНС: `time_s timestamp_ns latitude longitude altitude vx vy vz` (град, м, м/с; vx=Vn, vy=Vверх, vz=Ve) |
| `angle.dat` | Углы: `time_s timestamp_ns roll pitch yaw` (радианы) |
| `StartupNav.ini` | Долгота, широта, высота и время выставки |
| `truth.txt` | Истина в формате `reference.txt` (10 колонок, углы в градусах) |
| `params.json` | Полный набор параметров профиля и шума |

## Согласованность данных

Счисление по **чистым** (до внесения шума) показаниям ИМУ уравнениями программы без коррекции отклоняется от истины не более чем на:

- 23.1333 м по горизонту;
- 0.0248 м по высоте;
- 0.12415 м/с по скорости;
- 0.00289° по углам.

Это ошибка дискретизации схемы программы (трапеции, матрица ориентации берётся с предыдущего такта), а не рассогласование набора: она падает вдвое при удвоении частоты ИМУ и растёт с интенсивностью манёвра и неравномерностью отсчётов. В штатной работе этот уход снимает коррекция по СНС.

## Запуск

```powershell
Copy-Item square_harsh\*.dat ..\raw\ -Force
Copy-Item square_harsh\StartupNav.ini ..\raw\ -Force
cd ..\..\build; .\imitator.exe
```

Сравнение с истиной: `truth.txt` имеет тот же формат, что `reference.txt`, поэтому подходит для `tools/plot_trajectory.py` и расчёта RMSE.
