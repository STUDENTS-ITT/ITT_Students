## Форматы

Совпадают с исходным датасетом: табуляция, заголовок с `#`, общая сетка метки времени 3 мс, углы `angle.dat` в **радианах**, координаты `gps.dat` в градусах, скорости `vx, vy, vz` = север, вверх, восток.

## Как пользоваться

1. Скопировать `imu.dat`, `gps.dat`, `angle.dat`, `StartupNav.ini` набора в `data/raw/`.
2. Запустить `imitator` из `build/`.
3. Сравнить `result.txt` с `truth.txt` (тот же формат, что `reference.txt`).
4. Ожидаемые оценки фильтра: смещения из `params.json` (`noise_si.gyro_bias_rad_s`, `noise_si.accel_bias_m_s2`).

Столбцы — максимальное отклонение счисления по **чистым** (до внесения шума) показаниям ИМУ от истины, без фильтра Калмана. Это ошибка дискретизации схемы программы (трапеции, матрица ориентации берётся с предыдущего такта), а не рассогласование набора: `--selftest` показывает, что она падает вдвое при удвоении частоты ИМУ. Величина растёт с интенсивностью манёвра и с неравномерностью отсчётов, поэтому у `high_dynamics` и `square_harsh` она заметно больше. По углам невязка везде меньше 0.1°, а в штатной работе эти уходы снимает коррекция по СНС.

## Повторная генерация

```powershell
python tools/generate_datasets.py --list
python tools/generate_datasets.py --only square_650
python tools/generate_datasets.py --selftest
```

Зерно генератора зафиксировано в каждом сценарии, поэтому наборы воспроизводимы.
