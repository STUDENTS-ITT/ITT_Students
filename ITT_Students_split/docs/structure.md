## Сборка

```bash
cmake -S . -B build
cmake --build build --config Release
```

Исполняемый файл ищет `imu.dat`, `gps.dat`, `angle.dat` в текущем рабочем каталоге,
а если их там нет — в каталоге самого exe (`src/utils/paths.h`). Результаты
`kalman15_line2.txt`, `d_1.txt` и `Angles.dat` пишутся в тот же каталог, откуда
взяты данные, поэтому запускать можно из любого места.

## Начальная выставка

Углы начальной ориентации считаются автономно, по неподвижному участку в начале
записи (`src/navigation/bins_alignment.h`); `angle.dat` при этом используется
только как эталон для сравнения и как запасной вариант, если выставка не удалась.

- Границу участка задаёт первый отсчёт `gps.dat` с ненулевой скоростью.
- Показания ИМУ сглаживаются скользящим средним (`movingAverage`): проекция
  угловой скорости Земли на порядок меньше шума гироскопов.
- Крен и тангаж — из проекций силы тяжести, курс — гирокомпасированием
  `ψ = atan2(−ω_z, ω_x)`; курс усредняется как направление (`circularMean`).
- Сила тяжести берётся не константой, а по нормальной формуле для широты и
  высоты первого отсчёта СНС (`normalGravity`).

На имеющихся данных участок составляет 180 с, крен и тангаж получаются с точностью
до 1e-5 рад, курс — с ошибкой около 10° из-за остаточного смещения гироскопов;
фильтр Калмана сводит её примерно за минуту движения.

## Чтение данных

Все три входных файла читаются построчно и синхронно: `data_io::ImuReader` даёт
очередную строку `imu.dat`, `data_io::SnsReader` — парную ей пару строк из
`gps.dat` и `angle.dat`. Целиком в памяти ничего не держится. Отсчёт эталона
забирается только под годную строку ИМУ, иначе потоки разъехались бы.

Служебная строка в каждом файле одна, и пропускается ровно одна.

Заглянуть вперёд основному циклу нельзя, поэтому границу неподвижного участка
и стартовый отсчёт даёт отдельный разведочный проход `nav::scanSns`.

## Схема коррекции

Схема разомкнутая. Счисление идёт свободно, поправки в него не вводятся; вектор
`x` накапливает полную ошибку решения. Обратная связь остаётся только по
смещениям датчиков `x[9..14]` — они вычитаются из показаний ИМУ.

- `ins::predict` — каждый такт ИМУ: `x⁻ = Φx`, `P⁻ = ΦPΦᵀ + Q` с шагом `dt`
  текущего такта и точкой линеаризации на его начало.
- `ins::correct` — раз в `SNS_DECIMATION` тактов, по приходу отсчёта СНС.
- В файл пишется решение за вычетом накопленной оценки: `makeRecord` вычитает
  `x[0..8]`. Колонка `lat_bins` — широта свободного счисления, без вычитания.

Плата за разомкнутую схему: ошибка свободного счисления накапливается по-настоящему.
На имеющихся данных уход по широте доходит до 23 км — почти целиком из-за того,
что ошибка курса после выставки (около 10°) в счисление не вводится. Итоговое
решение при этом эталон отслеживает, но точность углов деградирует до 3–4°,
поскольку линейная модель ошибок на таких величинах уже работает на пределе.

## Основные структуры

- `nav::SnsSample` — один отсчёт эталона: строка `gps.dat` вместе с парной ей
  строкой `angle.dat`.
- `nav::NavState` — состояние счисления: координаты, скорости, углы, производные
  предыдущего шага, вектор ошибок `x` (15) и его ковариация `P`.
- `ins::Attitude` / `ins::AttitudeRates` — углы ориентации и их производные.
- `nav::Position` — координаты и их производные на текущем шаге.
- `data_io::NavRecord` — строка выходного файла, `data_io::NavLogger` — запись файлов.

## Порядок вызовов в `main`

1. `nav::scanSns` — разведочный проход по эталону.
2. `nav::alignBins` — автономная выставка, `nav::initialAlignment` — стартовое состояние.
3. `ImuReader::open` + `SnsReader::open` — открытие потоков основного цикла.
4. Первые 180 с (`180 * 197` отсчётов) пишется стартовая точка без счисления.
5. `nav::step` на каждый отсчёт ИМУ: прогноз ошибок, пересчёт ускорений в
   географическую СК, интегрирование скоростей, координат и углов, раз в 197
   отсчётов — коррекция по эталону и запись строки результатов.
