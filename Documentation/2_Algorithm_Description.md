# Техническое описание алгоритма БИНС

## 1. Описание систем координат

### 1.1. Связанная система координат (OXYZ)

Связана с корпусом объекта. Оси совмещены с осями чувствительности датчиков:
- **X** — продольная ось (нос)
- **Y** — вертикальная ось (вверх)
- **Z** — поперечная ось (правый борт)

Именно в этой системе акселерометры и гироскопы выдают измерения: `Ax, Ay, Az` (м/с²) и `Wx, Wy, Wz` (град/с).

### 1.2. Географическая система координат (OXgYgZg)

Начало — в текущей точке положения объекта:
- **Xg** — на Север
- **Yg** — вверх (против силы тяжести)
- **Zg** — на Восток

Ориентация объекта задаётся тремя углами Эйлера–Крылова:
- **Yaw (ψ)** — рыскание, угол от Севера к проекции оси X на горизонтальную плоскость
- **Pitch (θ)** — тангаж, угол подъёма носа над горизонтом
- **Roll (ϕ)** — крен, угол поворота вокруг продольной оси

### 1.3. Матрица направляющих косинусов (МНК)

Матрица `C` размером 3×3 переводит векторы из связанной системы в географическую:

```
n_geo = C · n_body
```

Матрица вычисляется из углов Эйлера–Крылова (`math_utils.h:buildRotationMatrix`):

```
C = | c_p·c_y    -c_r·c_y·s_p + s_r·s_y    s_r·c_y·s_p + c_r·s_y |
    | s_p         c_r·c_p                     -s_r·c_p              |
    | -c_p·s_y    c_r·s_y·s_p + s_r·c_y     -s_r·s_y·s_p + c_r·c_y|
```

где `c_y = cos(ψ)`, `s_y = sin(ψ)`, `c_p = cos(θ)`, `s_p = sin(θ)`, `c_r = cos(ϕ)`, `s_r = sin(ϕ)`.

## 2. Кинематические уравнения ориентации

### 2.1. Уравнения Эйлера–Крылова

Скорость изменения углов ориентации связана с проекциями относительной угловой скорости на оси географического трёхгранника:

```
dψ/dt = (ω_yg·cos(ϕ) − ω_zg·sin(ϕ)) / cos(θ)
dθ/dt = ω_yg·sin(ϕ) + ω_zg·cos(ϕ)
dϕ/dt = ω_xg − tg(θ)·(ω_yg·cos(ϕ) − ω_zg·sin(ϕ))
```

где `ω_xg, ω_yg, ω_zg` — проекции **относительной** угловой скорости на оси географического трёхгранника.

### 2.2. Относительная угловая скорость

Измерения гироскопов содержат абсолютную угловую скорость тела в инерциальном пространстве. Чтобы получить **относительную** угловую скорость (относительно вращающейся Земли и географического трёхгранника), из показаний гироскопов вычитается переносная угловая скорость:

```
ω_relative = ω_gyro − ω_e
```

где `ω_e` — переносная угловая скорость географического трёхгранника (стр. 120, ф-ла 3.6):

```
ω_xg = Ω·cos(lat) + Ve / R
ω_yg = Ω·sin(lat) + (Ve / R)·tg(lat)
ω_zg = −Vn / R
```

где:
- `Ω = 7.292115×10⁻⁵` рад/с — угловая скорость вращения Земли
- `lat` — текущая широта
- `Vn, Ve` — составляющие скорости (Север, Восток)
- `R` — радиус Земли + высота

Переносная скорость проецируется на связанную систему через `C^T`:

```
ω_e_body = C^T · ω_e
```

### 2.3. Сингулярность

При `cos(θ) ≈ 0` (тангаж ≈ ±90°) знаменатель в формуле для `dψ/dt` обращается в нуль. В коде (`sins_algorithm.h:99`) это проверяется:

```cpp
if (fabs(cos_p) < 1e-6) return;
```

При наступлении сингулярности шаг интегрирования пропускается. Для наземных объектов тангаж остаётся малым, и сингулярность не возникает.

## 3. Навигационные уравнения (счисление пути)

### 3.1. Пересчёт ускорений в географическую систему

Кажущееся ускорение из связанной системы переводится в географическую через МНК:

```
n_geo = C · a_body
```

### 3.2. Компенсация вредных ускорений

#### Ускорение Кориолиса

```
a_cor_x = (Ve / R) · (2Ω·sin(lat) + (Ve / R)·tg(lat))
a_cor_z = −(Vn / R) · (2Ω·sin(lat) + (Ve / R)·tg(lat))
```

#### Сила тяжести

Эффективное ускорение свободного падения (гравитация минус центробежная сила):

```
g_eff = GM / R² − Ω²·R·cos²(lat)
```

где:
- `GM = 3.986004418×10¹⁴` м³/с² — гравитационный параметр Земли
- `R = R_eq + alt` — расстояние от центра Земли
- `R_eq = 6378137.0` м — экваториальный радиус

### 3.3. Интегрирование скоростей

```
dVn/dt = n_g_x − a_cor_x
dVe/dt = n_g_z − a_cor_z
```

### 3.4. Интегрирование координат

```
d(lat)/dt = Vn / R
d(lon)/dt = Ve / (R · cos(lat))
```

### 3.5. Блокировка вертикального канала

Для наземного применения вертикальный канал **заблокирован**:
- `V_up = 0` (вертикальная скорость обнуляется)
- `Alt = 0` (высота фиксируется на уровне моря)

Причина: двойное интегрирование вертикального ускорения неустойчиво и приводит к экспоненциальному дрейфу высоты.

## 4. Процесс инициализации (выставка)

### 4.1. Определение начальных углов

На этапе выставки объект находится в покое. Акселерометры измеряют вектор силы тяжести, проецированный на связанную систему. По этим проекциям вычисляются начальные углы крена и тангажа:

```
θ₀ = arcsin(Ax / g_eff)          — тангаж
ϕ₀ = atan2(−Az, Ay)              — крен
ψ₀ = 0                           — рыскание (не определяется по акселерометрам)
```

### 4.2. Прогрессивное усреднение

На этапе выставки IMU-данные накапливаются в буфер, а затем по каждой оси вычисляется **прогрессивное среднее** — накопленное среднее от начала до текущего момента:

```
mean[i] = (sum[i-1] + value[i]) / (i + 1)
```

Финальное среднее — последний элемент массива (`getFinalMean`). Это позволяет:
- Усреднить шум датчиков (типичный шум IMU ~0.01–0.1 м/с²)
- Определить статическое ускорение с высокой точностью

### 4.3. Граница выставки

Граница определяется из файла `Nav.dat`: файл содержит временной ряд фаз, где столбец `T_nav` переходит из 0 в положительное значение. Это происходит на `T_sys = 333` для набора данных `INS_Data/1`:

| T_sys | T_reg | T_rem | T_nav | Фаза |
|-------|-------|-------|-------|------|
| 20 | 20 | 700 | 0 | Выставка |
| ... | ... | ... | 0 | |
| 332 | 332 | 388 | 0 | Конец выставки |
| **333** | **0.9** | **0** | **0.015** | **Навигация** |

Программа определяет `alignment_end_T = 332` автоматически и собирает все IMU-сэмплы с `Time ≤ 332` для усреднения.
